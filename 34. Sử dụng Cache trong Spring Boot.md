# Lý thuyết về Redis Cache
## 1. Redis
Redis là một hệ thống cơ sở dữ liệu mã nguồn mở, siêu nanh, lưu trữ dữ liệu trong bộ nhớ (NoSQL), sử dụng cấu trúc dữ liệu dạng key-value. Redis hỗ trợ nhiều kiểu dữ liệu như string, list, set, sorted set, hash, stream, hyperloglog, bitmap, geospatial và định tuyến.

Các trường hợp sử dụng Redis phổ biến bao gồm:
- Bộ nhớ đệm (caching)
- Hàng đợi tin nhắn (message queuing)
- Pub/Sub
- Streaming
- Geospatial indexing
- ...

### 1.1. Cài đặt Redis
Cài đặt với Docker Compose, tạo file `docker-compose.yml` với nội dung sau:
```yaml
services:
  redis:
    image: redis:6.2 # Sử dụng image redis phiên bản 6.2
    container_name: redis # Tên container
    ports:
      - "6379:6379" # Map cổng 6379 của host với cổng 6379 của container
    volumes:
      - redis-data:/data # Sử dụng volume để lưu trữ dữ liệu của Redis
volumes:
  redis-data:
```

Sau đó chạy lệnh sau để khởi động Redis:
```bash
docker-compose up -d
```

Để truy cập vào Redis CLI, sử dụng lệnh sau:
```bash
docker exec -it redis bash
```
Sau đó trong container, chạy lệnh sau để truy cập vào Redis CLI:
```bash
redis-cli
```

### 1.2. Các lệnh trong Redis
#### 1.2.1. Quy tắc đặt tên key trong Redis
Khi đặt tên key trong Redis, chúng ta nên tuân theo các quy tắc sau để đảm bảo tính nhất quán và dễ quản lý:
- Sử dụng dấu hai chấm (:) để phân tách các phần của key. Ví dụ: `user:1001:name`
- Sử dụng chữ thường và dấu gạch dưới (_) để tăng tính đọc được. Ví dụ: `user_profile:1001`
- Tránh sử dụng ký tự đặc biệt và khoảng trắng trong tên key.
- Giữ tên key ngắn gọn nhưng vẫn có ý nghĩa. Ví dụ: `sess:abcd1234` thay vì `session_for_user_abcd1234`
- Sử dụng tiền tố (prefix) để nhóm các key liên quan với nhau. Ví dụ: `cache:product:1234`, `cache:product:5678`


#### 1.2.2. Thiết lập key trong Redis
Để thiết lập key trong Redis, chúng ta có thể sử dụng lệnh `SET` trong Redis CLI. Ví dụ:
```bash
SET user:1001:name "John Doe"
SET user:1002:name "Jane Smith"
```

#### 1.2.3. Truy cập key trong Redis
Để lấy ra tất cả các key trong Redis, chúng ta có thể sử dụng lệnh sau trong Redis CLI:
```bash
KEYS *
```
Có thể dùng `regex` để lọc key, ví dụ:
```bash
KEYS user:* # Lấy tất cả các key bắt đầu bằng "user:"
```

> Sử dụng `KEYS` trong môi trường production không được khuyến khích vì nó có thể gây tắc nghẽn Redis server nếu có quá nhiều key. Thay vào đó, nên sử dụng `SCAN` để duyệt qua các key một cách an toàn hơn như sau:

```bash
scan 0 
```
Lệnh này sẽ trả về một con trỏ (cursor) và một danh sách các key. Chúng ta có thể tiếp tục sử dụng con trỏ này để quét các key tiếp theo cho đến khi con trỏ trả về 0. Ví dụ:
```bash
scan 0 # Điểm bắt đầu
### OUTPUT
1) "23"  # con trỏ cần tiếp tục sử dụng
2) 1) "user:1001"
   2) "user:1002"
scan 23 # Tiếp tục quét với con trỏ 23
### OUTPUT
1) "0"  # con trỏ 0 nghĩa là đã quét xong
2) 1) "user:1003"
   2) "user:1004"
  
```

Ngoài ra, để `scan` với `pattern` cụ thể, chúng ta có thể sử dụng lệnh sau:
```bash
scan 0 MATCH user:* # Lấy tất cả các key bắt đầu bằng "user:"
### OUTPUT
1) "23"  # con trỏ cần tiếp tục sử dụng
2) 1) "user:1001"
   2) "user:1002"
scan 23 MATCH user:* # Tiếp tục quét với con trỏ 23
### OUTPUT
1) "0"  # con trỏ 0 nghĩa là đã quét xong
2) 1) "user:1003"
   2) "user:1004"
```
#### 1.2.4. Xóa key trong Redis
Để xóa một key trong Redis, chúng ta có thể sử dụng lệnh `DEL [keyName]` trong Redis CLI. Ví dụ:
```bash
DEL user:1001:name
```
Tương tự để xóa nhiều key cùng lúc, chúng ta có thể sử dụng lệnh `DEL` với nhiều key cách nhau bởi dấu cách. Ví dụ:
```bash
DEL user:1001:name user:1002:name
```

> Lưu ý, không tồn tại lệnh xóa key theo pattern trong Redis.

Để xóa hết các key trong Redis, chúng ta có thể sử dụng lệnh `FLUSHDB` trong Redis CLI. Ví dụ:
```bash
flushdb
```

#### 1.2.5. Thời gian sống (TTL) cho key trong Redis
Chúng ta có thể thiết lập thời gian sống (TTL - Time To Live) cho một key trong Redis bằng lệnh `EXPIRE [keyName] [seconds]`. Ví dụ, để thiết lập thời gian sống cho key `user:1001:name` là 60 giây, chúng ta sử dụng lệnh sau:
```bash
EXPIRE user:1001:name 60
```

Để kiểm tra thời gian sống còn lại của một key trong Redis, chúng ta có thể sử dụng lệnh `TTL [keyName]`. Ví dụ:
```bash 
TTL user:1001:name # Khi key còn sống sẽ trả về số giây còn lại, nếu key không tồn tại sẽ trả về -2, nếu key tồn tại nhưng không có thời gian sống sẽ trả về -1
```

Ngoài ra, chúng ta có thể thiết lập thời gian sống cho key ngay khi tạo key bằng lệnh `SET [keyName] EX [seconds]`. Ví dụ:
```bash
SET user:1001:name "John Doe" EX 60
```

> Khi set lại giá trị cho một key đã tồn tại, thời gian sống của key sẽ bị xóa bỏ. Để giữ nguyên thời gian sống của key khi set lại giá trị, chúng ta có thể sử dụng lệnh `SET [keyName] [value] KEEPTTL`. Ví dụ:
```bash
SET user:1001:name "John Smith" KEEPTTL
```

#### 1.2.6. Option XX và NX khi set key trong Redis
Khi sử dụng lệnh `SET` trong Redis, chúng ta có thể sử dụng các option `XX` và `NX` để kiểm soát việc thiết lập giá trị cho key.
- `NX`: Chỉ thiết lập giá trị cho key nếu key chưa tồn tại. Nếu key đã tồn tại, lệnh sẽ không thực hiện và trả về nil. Ví dụ:
```bash
SET user:1001:name "John Doe" NX
``` 
- `XX`: Chỉ thiết lập giá trị cho key nếu key đã tồn tại. Nếu key chưa tồn tại, lệnh sẽ không thực hiện và trả về nil. Ví dụ:
```bash
SET user:1001:name "John Doe" XX
```
Để kiểm tra key có tồn tại hay không, chúng ta có thể sử dụng lệnh `EXISTS [keyName]`. Ví dụ:
```bash
EXISTS user:1001:name # Trả về 1 nếu key tồn tại, trả về 0 nếu key không tồn tại
```

#### 1.2.7. Increment và Decrement key trong Redis
Chúng ta có thể sử dụng lệnh `INCR` và `DECR` để tăng hoặc giảm giá trị của một key trong Redis. Ví dụ:
```bash
INCR page:view:count # Tăng giá trị của key page:view:count lên 1, nếu key không tồn tại sẽ được khởi tạo với giá trị 0 trước khi tăng
DECR page:view:count # Giảm giá trị của key page:view:count xuống 1, nếu key không tồn tại sẽ được khởi tạo với giá trị 0 trước khi giảm
INCRBY page:view:count 5 # Tăng giá trị của key page:view:count lên 5
DECRBY page:view:count 3 # Giảm giá trị của key page:view:count xuống 3
```

Việc sử dụng `INCR` và `DECR` rất hữu ích trong các trường hợp như đếm số lượt truy cập trang web, số lượt thích bài viết, v.v.

#### 1.2.8. Ứng dụng trong Rate Limiting với Redis
Chúng ta có thể sử dụng Redis để triển khai cơ chế Rate Limiting, giới hạn số lượng yêu cầu từ một người dùng trong một khoảng thời gian nhất định. Ví dụ, chúng ta muốn giới hạn mỗi người dùng chỉ được phép gửi tối đa 100 yêu cầu trong vòng 1 phút. Chúng ta có thể sử dụng lệnh `INCR` để đếm số yêu cầu và lệnh `EXPIRE` để thiết lập thời gian sống cho key. Ví dụ:
```bash
INCR user:12345:request_count
EXPIRE user:12345:request_count 60
```
Nếu giá trị trả về từ lệnh `INCR` vượt quá 100, chúng ta có thể từ chối yêu cầu của người dùng.

Sau 1 phút, key `user:12345:request_count` sẽ hết hạn và bị xóa khỏi Redis, cho phép người dùng gửi lại yêu cầu mới.

#### 1.2.9. Hash trong Redis
Chúng ta có thể sử dụng kiểu dữ liệu Hash trong Redis để lưu trữ các cặp key-value liên quan đến một đối tượng. Ví dụ, chúng ta muốn lưu trữ thông tin của một người dùng với các thuộc tính như tên, tuổi và email. Chúng ta có thể sử dụng lệnh `HSET` để thiết lập các thuộc tính cho người dùng. Ví dụ:
```bash
HSET user:1001 name "John Doe" age "30" email "john.doe@example.com"
HSET user:1002 name "Jane Smith" age "25" email "jane.smith@example.com"
```
Để lấy thông tin của người dùng, chúng ta có thể sử dụng lệnh `HGETALL`. Ví dụ:
```bash
HGETALL user:1001
### OUTPUT
1) "name"
2) "John Doe"
3) "age"
4) "30"
5) "email"
6) "john.doe@example.com"
```
Để lấy một thuộc tính cụ thể của người dùng, chúng ta có thể sử dụng lệnh `HGET`. Ví dụ:
```bash
HGET user:1001 email
```
Để lấy tất cả các key của hash, chúng ta có thể sử dụng lệnh `HKEYS`. Ví dụ:
```bash
HKEYS user:1001
```
Để lấy tất cả các value của hash, chúng ta có thể sử dụng lệnh `HVALS`. Ví dụ:
```bash
HVALS user:1001
```
Để xóa một thuộc tính trong hash, chúng ta có thể sử dụng lệnh `HDEL`. Ví dụ:
```bash
HDEL user:1001 email
```
Để kiểm tra sự tồn tại của một thuộc tính trong hash, chúng ta có thể sử dụng lệnh `HEXISTS`. Ví dụ:
```bash
HEXISTS user:1001 email # Trả về 1 nếu thuộc tính tồn tại, trả về 0 nếu thuộc tính không tồn tại
```

> Lưu ý: Redis Hash không có thời gian sống riêng cho từng trường trong hash. Thời gian sống chỉ được áp dụng cho toàn bộ hash.

Để thiết lập thời gian sống cho một hash, chúng ta có thể sử dụng lệnh `EXPIRE` trên key của hash. Ví dụ:
```bash
EXPIRE user:1001 60 # Thiết lập thời gian sống cho hash user:1001 là 60 giây
```
#### 1.2.10. List & Queue trong Redis
Chúng ta có thể sử dụng kiểu dữ liệu List trong Redis để lưu trữ một danh sách các phần tử. Redis List hỗ trợ các thao tác như thêm phần tử vào đầu hoặc cuối danh sách, lấy phần tử từ đầu hoặc cuối danh sách, v.v.
Ví dụ, chúng ta muốn lưu trữ một danh sách các nhiệm vụ cần thực hiện. Chúng ta có thể sử dụng lệnh `LPUSH` để thêm nhiệm vụ vào đầu danh sách và lệnh `RPUSH` để thêm nhiệm vụ vào cuối danh sách. Ví dụ:
```bash
RPUSH task_queue "Task 1" # Thêm vào cuối list có key (task_queue)
```

Để đếm kích thước của list, ta dùng `LLEN`:
```bash
LLEN task_queue 
```

Để lấy ra tất cả phần tử trong list. Sử dụng lệnh `LRANGE [KEY] [START_IDX] [END_IDX]` với idx bắt đầu là 0, và idx cuối cùng có chỉ số là -1:
```bash
LRANGE task_queue 0 -1 # In ra tất cả phần tử trong list
LRANGE task_queue 0 2 # In ra 3 phần từ 0, 1, 2 đầu tiên trong list
```

Để lấy ra và bỏ đi phần tử của list. Chúng ta thực hiện lệnh `LPOP` hoặc `RPOP`:
```bash
LPOP task_queue # Lấy phần tử đầu tiên của đầu list, đồng thời bỏ phân tử đó đi
LPOP task_queue 2 # Lấy 2 phần tử đầu tiên của đầu list, đồng thời bỏ 2 phần tử đó đi
```

> Ứng dụng List & Queue trong Redis có thể làm hệ thống xử lý công việc nền (background job processing), hàng đợi tin nhắn (message queuing), v.v. Ví dụ, chúng ta có thể sử dụng Redis List để triển khai một hệ thống hàng đợi công việc, nơi các nhiệm vụ được thêm vào danh sách, mỗi lần thêm sẽ sử dụng lệnh `RPUSH`, và các worker sẽ lấy nhiệm vụ từ danh sách sử dụng lệnh `LPOP` để xử lý.

Cơ chế `RPUSH` - `LPOP` hoặc `LPUSH` - `RPOP` giúp đảm bảo rằng các nhiệm vụ được xử lý theo thứ tự chúng được thêm vào danh sách (FIFO - First In First Out).

Cơ chế `LPUSH` - `LPOP` hoặc `RPUSH` - `RPOP` cũng có thể được sử dụng để triển khai một hệ thống ngăn xếp (stack), nơi các nhiệm vụ được thêm và lấy theo nguyên tắc LIFO (Last In First Out).

#### 1.2.11. Set trong Redis
Chúng ta có thể sử dụng kiểu dữ liệu Set trong Redis để lưu trữ một tập hợp các phần tử duy nhất, không có thứ tự. Redis Set hỗ trợ các thao tác như thêm phần tử, xóa phần tử, kiểm tra sự tồn tại của phần tử, v.v. Ứng dụng của Set trong Redis bao gồm quản lý danh sách bạn bè, theo dõi người dùng đã thích một bài viết, v.v.

Các lệnh cơ bản để làm việc với Set trong Redis bao gồm:
- `SADD [key] [member1] [member2] ...`: Thêm một hoặc nhiều phần tử vào Set. Ví dụ:
```bash
SADD user:1001:friends 2001 2002 2003 # Thêm các user 2001, 2002, 2003 vào danh sách bạn bè của user 1001 (key: user:1001:friends)
```
- `SCARD [key]`: Đếm số phần tử trong Set. Ví dụ:
```bash
SCARD user:1001:friends # Đếm số bạn bè của user 1001
### OUTPUT
# (integer) 3
```
- `SMEMBERS [key]`: Lấy tất cả các phần tử trong Set. Ví dụ:
```bash
SMEMBERS user:1001:friends # Lấy tất cả bạn bè của user 1001
### OUTPUT
# 1) "2001"
# 2) "2002"
# 3) "2003"
```
- `SISMEMBER [key] [member]`: Kiểm tra sự tồn tại của một phần tử trong Set. Ví dụ:
```bash
SISMEMBER user:1001:friends 2002 # Kiểm tra xem user 2002 có phải là bạn bè của user 1001 không
### OUTPUT
# (integer) 1 # (1: tồn tại, 0: không tồn tại)
```
- `SREM [key] [member1] [member2] ...`: Xóa một hoặc nhiều phần tử khỏi Set. Ví dụ:
```bash
SREM user:1001:friends 2002 # Xóa user 2002 khỏi danh sách bạn bè của user 1001
```
- `SPOP [key] [count]`: Lấy và xóa ngẫu nhiên một hoặc nhiều phần tử khỏi Set. Ví dụ:
```bash
SPOP user:1001:friends 1 # Lấy và xóa ngẫu nhiên 1 bạn bè khỏi danh sách bạn bè của user 1001
### OUTPUT
# "2003" # (phần tử được lấy và xóa)
```

> Lưu ý, ứng dụng của Set trong Redis rất hữu ích khi có thể tìm tập hợp giao (intersection), hợp (union), và hiệu (difference) của các Set để thực hiện các phép toán tập hợp. Ứng dụng này rất phổ biến trong các hệ thống mạng xã hội để tìm bạn chung, đề xuất bạn bè, v.v. Dưới đây là một số lệnh để thực hiện các phép toán tập hợp trên Set trong Redis:

- `SINTER [key1] [key2] ..`.: Tìm tập hợp giao (intersection) của các Set. Ví dụ:
```bash
SINTER user:1001:friends user:1002:friends # Tìm bạn chung giữa user 1001 và user 1002
### OUTPUT
# 1) "2003" # (giả sử cả hai user đều có bạn chung là user 2003)
```
- `SUNION [key1] [key2] ...`: Tìm tập hợp hợp (union) của các Set. Ví dụ:
```bash
SUNION user:1001:friends user:1002:friends # Tìm tất cả bạn bè của user 1001 và user 1002
### OUTPUT
# 1) "2001"
# 2) "2002"
# 3) "2003"
# (giả sử user 1001 có bạn là 2001, 2002 và user 1002 có bạn là 2002, 2003)
```
- `SDIFF [key1] [key2] ...`: Tìm tập hợp hiệu (difference) của các Set. Ví dụ:
```bash
SDIFF user:1001:friends user:1002:friends # Tìm bạn bè của user 1001 mà không phải là bạn bè của user 1002
### OUTPUT
# 1) "2001" # (giả sử user 1001 có bạn là 2001, 2002 và user 1002 có bạn là 2002, 2003)
```
- `SINTERSTORE [destination] [key1] [key2] ...`: Tạo một Set mới là tập hợp giao của các Set và lưu vào key đích. Ví dụ:
```bash
SINTERSTORE user:1001_and_1002_friends user:1001:friends user:1002:friends # Tạo Set mới chứa bạn chung giữa user 1001 và user 1002
```

#### 1.2.12. Sorted Set
Chúng ta có thể sử dụng kiểu dữ liệu Sorted Set trong Redis để lưu trữ một tập hợp các phần tử duy nhất, mỗi phần tử có một điểm số (score) đi kèm. Redis Sorted Set hỗ trợ các thao tác như thêm phần tử với điểm số, lấy phần tử theo thứ tự điểm số, v.v. Ứng dụng của Sorted Set trong Redis bao gồm xếp hạng người dùng, danh sách bài hát yêu thích, v.v.

Các lệnh cơ bản để làm việc với Sorted Set trong Redis bao gồm:
- `ZADD [key] [score1] [member1] [score2] [member2] ...`: Thêm một hoặc nhiều phần tử vào Sorted Set với điểm số tương ứng. Ví dụ:
```bash
ZADD leaderboard 100 "user:1001" 200 "user:1002" 150 "user:1003" # Thêm các user với điểm số vào bảng xếp hạng
```
- `ZCARD [key]`: Đếm số phần tử trong Sorted Set. Ví dụ:
```bash
ZCARD leaderboard # Đếm số người chơi trong bảng xếp hạng
### OUTPUT
# (integer) 3
```
- `ZINCRBY [key] [increment] [member]`: Tăng điểm số của một phần tử trong Sorted Set. Ví dụ:
```bash
ZINCRBY leaderboard 50 "user:1001" # Tăng điểm số của user 1001 lên thêm 50 điểm
```
- `ZRANGE [key] [start] [stop] [WITHSCORES]`: Lấy các phần tử trong Sorted Set theo thứ tự điểm số từ thấp đến cao. Ví dụ:
```bash
ZRANGE leaderboard 0 -1 WITHSCORES # Lấy tất cả người chơi trong bảng xếp hạng cùng với điểm số, nếu không có WITHSCORES thì chỉ lấy member
### OUTPUT
# 1) "user:1003"
# 2) "150"
# 3) "user:1001"
# 4) "150"
# 5) "user:1002"
# 6) "200"

ZRANGE leaderboard 0 0 WITHSCORES # Lấy người chơi có điểm số thấp nhất cùng với điểm số
ZRANGE leaderboard -1 -1 WITHSCORES # Lấy người chơi có điểm số cao nhất cùng với điểm số
ZRANGE leaderboard 0 0 REV WITHSCORES # Lấy người chơi có điểm số cao nhất cùng với điểm số (cách khác)
ZRANGE leaderboard 0 1 WITHSCORES # Lấy 2 người chơi có điểm số thấp nhất cùng với điểm số
```

- `ZRANK [key] [member]`: Lấy vị trí (rank) của một phần tử trong Sorted Set theo thứ tự điểm số từ thấp đến cao. Ví dụ:
```bash
ZRANK leaderboard "user:1001" # Lấy vị trí của user 1001 trong bảng xếp hạng
### OUTPUT
# (integer) 1 # (vị trí bắt đầu từ 0)
ZREVRANK leaderboard "user:1001" # Lấy vị trí của user 1001 trong bảng xếp hạng theo thứ tự điểm số từ cao đến thấp
### OUTPUT
# (integer) 1 # (vị trí bắt đầu từ 0)
```
- `ZSCORE [key] [member]`: Lấy điểm số của một phần tử trong Sorted Set. Ví dụ:
```bash
ZSCORE leaderboard "user:1001" # Lấy điểm số của user 1001 trong bảng xếp hạng
### OUTPUT
# "150"
```
- `ZPOPN [key] [count]`: Lấy và xóa phần tử có điểm số thấp nhất trong Sorted Set. Ví dụ:
```bash
ZPOPN leaderboard 1 # Lấy và xóa 1 người chơi có điểm số thấp nhất trong bảng xếp hạng
### OUTPUT
# 1) "user:1003"
# 2) "150"
```

- `ZPOPMAX [key] [count]`: Lấy và xóa phần tử có điểm số cao nhất trong Sorted Set. Ví dụ:
```bash
ZPOPMAX leaderboard 1 # Lấy và xóa 1 người chơi có điểm số cao nhất trong bảng xếp hạng
### OUTPUT
# 1) "user:1002"
# 2) "200"
```
Ứng dụng của Sorted Set đóng vai trò như là 1 Priority Queue, nơi các phần tử được xử lý theo thứ tự điểm số của chúng. Ví dụ, trong một hệ thống xếp hạng thứ hạng thành viên, các thành viên có điểm số cao hơn sẽ được ưu tiên xử lý trước.


### 1.3. Redis Transaction
Redis hỗ trợ giao dịch (transaction) thông qua các lệnh `MULTI`, `EXEC`, `DISCARD`, và `WATCH`. Giao dịch trong Redis cho phép chúng ta thực hiện một loạt các lệnh một cách nguyên tử, đảm bảo rằng tất cả các lệnh trong giao dịch sẽ được thực hiện hoặc không có lệnh nào được thực hiện.

Ví dụ, chúng ta có 2 key `account:1001:balance` và `account:1002:balance`, chúng ta muốn chuyển 100 đơn vị tiền từ tài khoản 1001 sang tài khoản 1002. Chúng ta có thể sử dụng giao dịch trong Redis để đảm bảo rằng cả hai thao tác trừ và cộng tiền đều được thực hiện một cách nguyên tử.

```bash
WATCH account:1001:balance account:1002:balance # Giám sát các key để phát hiện thay đổi
MULTI # Bắt đầu giao dịch (Thực hiện nhiều lệnh một cách nguyên tử)
DECRBY account:1001:balance 100 # Trừ 100 đơn vị tiền từ tài khoản 1001
INCRBY account:1002:balance 100 # Cộng 100 đơn vị tiền vào tài khoản 1002
EXEC # Thực hiện giao dịch
```
Nếu trong quá trình giao dịch, giá trị của bất kỳ key nào được giám sát bởi `WATCH` bị thay đổi bởi một client khác, giao dịch sẽ bị hủy bỏ và không có lệnh nào được thực hiện. Điều này giúp đảm bảo tính nhất quán của dữ liệu trong các tình huống có nhiều client cùng truy cập và sửa đổi dữ liệu.

> Lưu ý: Giao dịch trong Redis không hỗ trợ rollback (hoàn tác) như các hệ quản trị cơ sở dữ liệu quan hệ truyền thống. Nếu một lệnh trong giao dịch gặp lỗi, các lệnh trước đó vẫn sẽ được thực hiện. Do đó, chúng ta cần thiết kế logic ứng dụng sao cho phù hợp với tính chất này của Redis.

### 2.3. Cấu hình Redisson Client trong Spring Boot
Dưới đây là ví dụ cấu hình Redisson Client trong ứng dụng Spring Boot sử dụng kết nối đơn (single connection) đơn giản, chi tiết xem tại các mục áp dụng bài toán thực tế ở dưới.
> RedissonConfig
```java
import jakarta.annotation.PreDestroy;
import org.redisson.Redisson;
import org.redisson.api.RedissonClient;
import org.redisson.api.RedissonReactiveClient;
import org.redisson.config.Config;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class RedissonConfig {

  @Bean(destroyMethod = "shutdown") // Đảm bảo RedissonClient được tắt đúng cách khi ứng dụng dừng, gọi phương thức shutdown của RedissonClient
  public RedissonClient getClient() {
    Config config = new Config(); // Tạo mới cấu hình Redisson
    config.useSingleServer() // Sử dụng chế độ máy chủ đơn
        .setAddress("redis://127.0.0.1:6379"); // Đặt địa chỉ máy chủ Redis (Lưu ý: Thêm tiền tố "redis://")
    return Redisson.create(config); // Tạo và trả về RedissonClient
  }

  // Bean để cung cấp RedissonReactiveClient
  @Bean(destroyMethod = "shutdown") // Đảm bảo RedissonClient được tắt đúng cách khi ứng dụng dừng, gọi phương thức shutdown của RedissonClient
  public RedissonReactiveClient getReactiveClient() {
    return getClient().reactive(); // Tạo RedissonReactiveClient từ RedissonClient
  }
}
```

### 2.4. Sử dụng RedissonReactiveClient
#### 2.4.1. Tạo Bucket (key-Value)
Dưới đây là ví dụ về cách tạo bucket (key-value) trong RedissonReactiveClient.
```java
@Component
@Slf4j
@RequiredArgsConstructor
public class Lec01KeyValue {

  private final RedissonClient redissonClient;
  private final RedissonReactiveClient redissonReactiveClient;

  @PostConstruct
  public void keyValueAccess() throws InterruptedException {
    log.info("Starting Key Value Access");
    RBucketReactive<String> bucket = redissonReactiveClient.getBucket("user:1:name", StringCodec.INSTANCE); // Lấy bucket phản ứng cho khóa "user:1:name"
    Mono<Void> set = bucket.set("sam"); // Thiết lập giá trị "sam" cho bucket
    // Để set thêm thời gian sống cho key (TTL - Time To Live)
    // Mono<Void> set = bucket.set("sam", Duration.ofSeconds(10)); // Thiết lập giá trị "sam" với thời gian sống 10 giây
    Mono<Void> get = bucket.get() // Lấy giá trị từ bucket
        .doOnNext(res -> log.info("res: {}", res)) // In ra giá trị nhận được
        .then(); // Chuyển đổi sang Mono<Void>
    Mono<Boolean> expire = bucket.expire(Duration.ofSeconds(30)); // Thiết lập thời gian sống cho bucket là 30 giây
    Mono<Long> ttl = bucket.remainTimeToLive()
        .doOnNext(t -> log.info("TTL: {}", t)); // In ra thời gian sống còn lại

    Student student = new Student("John Doe", 20, "123 Main St", Arrays.asList(1, 2, 3, 4, 5)); // Tạo đối tượng Student
    RBucketReactive<Student> studentBucket = redissonReactiveClient.getBucket("student:1", new TypedJsonJacksonCodec(Student.class)); // Lấy bucket phản ứng cho đối tượng Student với codec JSON
    Mono<Void> setStudent = studentBucket.set(student); // Thiết lập đối tượng Student vào bucket
    Mono<Student> getStudent = studentBucket.get()
        .doOnNext(s -> log.info("Student: {}", s));

    set
        .then(get) // Chuỗi các thao tác: thiết lập giá trị, lấy giá trị
        .then(expire) // Thiết lập thời gian sống
        .then(ttl) // Lấy thời gian sống còn lại
        .subscribe(); // Thực thi chuỗi các thao tác thiết lập và lấy giá trị (Trong Reactive (phản ứng) cần có sự kiện subscribe để bắt đầu thực thi)

    setStudent
        .then(getStudent) // Chuỗi các thao tác: thiết lập đối tượng Student, lấy đối tượng Student
        .subscribe(); // Thực thi chuỗi các thao tác thiết lập và lấy đối tượng Student
  }

  @AllArgsConstructor
  @NoArgsConstructor
  @Data
  public static class Student {

    private String name;
    private int age;
    private String address;
    private List<Integer> marks;
  }

}
```
> Lưu ý: 
> - Trong Reactive (phản ứng) cần có sự kiện subscribe để bắt đầu thực thi. Trong trường hợp này, chúng ta sử dụng phương thức `subscribe()` để bắt đầu thực thi chuỗi các thao tác.
> - Để set thêm thời gian sống cho key (TTL - Time To Live), chúng ta sử dụng phương thức `set("sam", Duration.ofSeconds(10))`.
> - Trong trường hợp này, chúng ta sử dụng `StringCodec.INSTANCE` để chỉ định codec để mã hóa/ giải mã giá trị trong bucket. Redisson cung cấp nhiều codec khác nhau để mã hóa/ giải mã giá trị trong bucket như: `StringCodec (Dành cho String)`, `IntegerCodec (Dành cho Integer)`, `LongCodec (Dành cho Long)`, `JsonJacksonCodec (Dành cho JSON sử dụng thư viện Jackson)`, `MsgPackJacksonCodec (Dành cho MsgPack sử dụng thư viện Jackson)`, `CborJacksonCodec (Dành cho CBOR sử dụng thư viện Jackson)`, `SmileJacksonCodec (Dành cho Smile sử dụng thư viện Jackson)`, `FstCodec (Sử dụng thư viện FST)`, `KryoCodec (Sử dụng thư viện Kryo)`, v.v.
> - Đối với các đối tượng phức tạp, chúng ta có thể sử dụng `TypedJsonJacksonCodec` để mã hóa/ giải mã giá trị trong bucket dưới dạng JSON sử dụng thư viện Jackson, các đối tượng này định nghĩa class Java cụ thể (không được dùng record).

#### 2.4.2. Sử dụng Atomic để tăng/giảm giá trị
Dưới đây là ví dụ về cách sử dụng Atomic trong RedissonReactiveClient để tăng/giảm giá trị.
```java
@Component
@Slf4j
@RequiredArgsConstructor
public class Lec02IncrDecrNumber {

  private final RedissonClient redissonClient;
  private final RedissonReactiveClient redissonReactiveClient;

  @PostConstruct
  public void incrdecrNumber() throws InterruptedException {
    log.info("Starting Number Store");
    RAtomicLongReactive atmoic = redissonReactiveClient.getAtomicLong("user:1:visits"); // Lấy AtomicLong phản ứng cho khóa "user:1:visits"
    Mono<Void> mono = Flux.range(1, 30) // Tạo Flux từ 1 đến 30
        .delayElements(Duration.ofSeconds(1)) // Giãn cách mỗi phần tử 1 giây
        .flatMap(i -> atmoic.incrementAndGet()) // Tăng giá trị AtomicLong lên 1 và lấy giá trị mới và trả về Mono<Long>
        .doOnNext(i -> log.info("Incr: {}", i))  // In ra giá trị sau khi tăng
        .then();
    mono.subscribe(); // Thực thi chuỗi các thao tác tăng giá trị (Trong Reactive (phản ứng) cần có sự kiện subscribe để bắt đầu thực thi)
  }
}
```

#### 2.4.3. Tạo Map (Hash)
Dưới đây là ví dụ về cách tạo Map (Hash) trong RedissonReactiveClient.
```java
@Component
@Slf4j
@RequiredArgsConstructor
public class Lec03MapHash {

  private final RedissonClient redissonClient;
  private final RedissonReactiveClient redissonReactiveClient;

  @PostConstruct
  public void mapHashAccess() throws InterruptedException {
    log.info("Starting Map Hash Access");
    RMapReactive<String, String> map = redissonReactiveClient.getMap("user:1:profile", StringCodec.INSTANCE); // Lấy Map phản ứng cho khóa "user:1:profile"
    // Nếu muốn sử dụng đối tượng phức tạp làm value trong Map, ta có thể sử dụng TypedJsonJacksonCodec
    // RMapReactive<String, Student> map = redissonReactiveClient.getMap("user:1:profile", new TypedJsonJacksonCodec(String.class, Student.class));
    Mono<Void> putAll = map.putAll(Map.of(
            "name", "sam",
            "age", "30",
            "email", "sam@example.com"
    ));
    putAll.subscribe(); // Thực thi việc thêm tất cả các phần tử vào Map

    // Ngoài ra, còn có RMapCacheReactive để làm việc với Map có hỗ trợ Cache với thời gian sống cho từng entry trong Map
    RMapCacheReactive<String, String> mapCache = redissonReactiveClient.getMapCache("user:2:profile", StringCodec.INSTANCE); // Lấy MapCache phản ứng cho khóa "user:2:profile"
    Mono<Void> mapCache.put("name", "bob", 10, TimeUnit.SECONDS) // Thêm phần tử vào MapCache với thời gian sống 10 giây
        .subscribe(); // Thực thi việc thêm phần tử vào MapCache

  }
}
```
Với `Redisson` chúng ta có thể dễ dàng làm việc với các cấu trúc dữ liệu phức tạp trong Redis như Map (Hash) và có thể thiết lập thời gian sống cho từng entry trong Map khi sử dụng `RMapCacheReactive`.

#### 2.4.4. Event Listener
Event Listener trong RedissonReactiveClient cho phép chúng ta lắng nghe các sự kiện xảy ra trên Redis, chẳng hạn như khi một key được thêm, sửa đổi hoặc xóa. 

Để thiết lập Event Listener trong Redis, chúng ta cần thêm cấu hình `notify-keyspace-events` trong Redis. Chúng ta có thể thiết lập cấu hình này trong file `redis.conf` hoặc sử dụng lệnh Redis sau:
```bash
CONFIG SET notify-keyspace-events AKE
```
hoặc tạo file `redis.conf` với nội dung:
```conf
notify-keyspace-events AKE
```
và sửa lại file docker-compose.yml để sử dụng file cấu hình này khi khởi động Redis:
```yaml
services:
  redis:
    image: redis:7.0.5
    container_name: redis-server
    ports:
      - "6379:6379"
    volumes:
      - ./redis.conf:/usr/local/etc/redis/redis.conf # Mount file cấu hình redis.conf vào container
    command: ["redis-server", "/usr/local/etc/redis/redis.conf"] # Sử dụng file cấu hình khi khởi động Redis
```

Tiếp theo, chúng ta có thể tạo Event Listener trong RedissonReactiveClient như sau:
```java
@Component
@Slf4j
@RequiredArgsConstructor
public class Lec03EventListener {

  private final RedissonClient redissonClient;
  private final RedissonReactiveClient redissonReactiveClient;

  @PostConstruct
  public void expireEventListener() throws InterruptedException {
    log.info("Starting Event Listener");
    RBucketReactive<String> bucket = redissonReactiveClient.getBucket("worker:1:name", StringCodec.INSTANCE); // Lấy bucket phản ứng cho khóa "worker:1:name"
    Mono<Void> set = bucket.set("alan", Duration.ofSeconds(10)); // Thiết lập giá trị "alan" cho bucket với thời gian sống 10 giây
    Mono<Void> get = bucket.get() // Lấy giá trị từ bucket
        .doOnNext(res -> log.info("res: {}", res)) // In ra giá trị nhận được
        .then(); // Chuyển đổi sang Mono<Void>
    Mono<Void> event = bucket.addListener(new ExpiredObjectListener() { // Thêm listener để lắng nghe sự kiện hết hạn của bucket
      @Override
      public void onExpired(String s) { // Xử lý khi đối tượng hết hạn
        log.info("expired object {}", s); // In ra thông báo key đã hết hạn
      }
    }).then();

    set.concatWith(get).concatWith(event) // Chuỗi các thao tác: thiết lập giá trị, lấy giá trị, thêm listener
        .subscribe(); // Thực thi chuỗi các thao tác (Trong Reactive (phản ứng) cần có sự kiện subscribe để bắt đầu thực thi)
  }

  @PostConstruct
  public void removeEventListener() throws InterruptedException {
    log.info("Starting Remove Event Listener");
    RBucketReactive<String> bucket = redissonReactiveClient.getBucket("worker:2:name", StringCodec.INSTANCE); // Lấy bucket phản ứng cho khóa "worker:2:name"
    Mono<Void> set = bucket.set("bob"); // Thiết lập giá trị "bob" cho bucket
    Mono<Void> get = bucket.get() // Lấy giá trị từ bucket
        .doOnNext(res -> log.info("res: {}", res)) // In ra giá trị nhận được
        .then(); // Chuyển đổi sang Mono<Void>
    Mono<Void> event = bucket.addListener(new DeletedObjectListener() { // Thêm listener để lắng nghe sự kiện hết hạn của bucket
      @Override
      public void onDeleted(String s) { // Xử lý khi đối tượng hết hạn
        log.info("deleted object {}", s); // In ra thông báo key đã hết hạn
      }
    }).then();

    set.concatWith(get).concatWith(event) // Chuỗi các thao tác: thiết lập giá trị, lấy giá trị, thêm listener
        .subscribe(); // Thực thi chuỗi các thao tác (Trong Reactive (phản ứng) cần có sự kiện subscribe để bắt đầu thực thi)
  }

  /**
   * Lưu ý: Để nhận được sự kiện hết hạn, bạn cần đảm bảo rằng Redis server của bạn được cấu hình đúng cách để hỗ trợ các sự kiện này.
   * Bạn có thể kiểm tra và thiết lập cấu hình này trong tệp cấu hình Redis (redis.conf) bằng cách đảm bảo rằng tùy chọn "notify-keyspace-events" được thiết lập đúng cách.
   * Ví dụ: Để nhận sự kiện hết hạn, bạn có thể thiết lập nó như sau:
   * notify-keyspace-events AKE
   */
}
```

#### 2.4.5. LocalCachedMap
`LocalCachedMap` là một cấu trúc dữ liệu trong Redisson cung cấp khả năng lưu trữ dữ liệu trong bộ nhớ đệm cục bộ (local cache) để tăng hiệu suất truy cập dữ liệu.

Khác với `RMap` thông thường, `LocalCachedMap` giữ một bản sao của dữ liệu trong bộ nhớ cục bộ của ứng dụng, giúp giảm thiểu số lần truy cập đến Redis server và cải thiện tốc độ truy xuất dữ liệu.

# Sử dụng Cache trong Spring Boot
Trong bài viết này, chúng ta sẽ tìm hiểu cách sử dụng Cache trong ứng dụng Spring Boot.

## 1. Giới thiệu.
### 1.1. LoadingCache
LoadingCache là một interface trong thư viện `caffeine` hỗ trợ cache dữ liệu trong bộ nhớ. Nó có cơ chế tự động load dữ liệu vào cache khi dữ liệu không tồn tại trong cache.

### 1.2. CacheLoader
CacheLoader là một công cụ có trong thư viện `caffeine` hỗ trợ nạp dữ liệu cho LoadingCache mỗi khi LoadingCache không chứa dữ liệu cần tìm.

### 1.3. Redis
Redis là một hệ thống cơ sở dữ liệu mã nguồn mở, lưu trữ dữ liệu dạng `key-value`, dữ liệu sẽ lưu ở 1 server nào đó, khác với `LoadingCache`.

Hỗ trợ nhiều kiểu dữ liệu như string, list, set, sorted set, hash, stream, hyperloglog, bitmap, geospatial và định tuyến. 

Redis cung cấp các tính năng như in-memory, lưu trữ dữ liệu trên ổ đĩa, replica, partition, cluster, pub/sub, lua scripting, transation, key expiration, LRU eviction, geospatial indexing, và các tính năng khác.

### 1.4. Redisson
Redisson là một thư viện Java hỗ trợ tương tác với Redis. 

Redisson cung cấp các tính năng như Redis client, Redisson client, Redisson Spring Cache, Redisson Spring Data, Redisson Spring Session, Redisson Spring Boot Starter, Redisson Spring Data Connection, Redisson Spring Data Repository, Redisson Spring Data Transaction, Redisson Spring Data Web, Redisson Spring Data Web Reactive, Redisson Spring Data Web Socket, Redisson Spring Data Web Socket

### 1.5. Jackson
Jackson là một thư viện Java hỗ trợ chuyển đổi dữ liệu giữa Java Object và JSON.

Để làm việc với Redis, chúng ta cần chuyển đổi dữ liệu giữa Java Object sang JSON khi lưu vào Redis và ngược lại khi lấy dữ liệu từ Redis.

```java
//============ CẤU HÌNH ĐỂ SỬ DỤNG ANNOTATION @Cacheable, @CacheConfig, @CachePut, @CacheEvict ====================
  public SerializationPair<Object> getJdkSerialization() { // Hàm trả về SerializationPair<Object> với JdkSerializationRedisSerializer
    ClassLoader loader = Thread.currentThread()
        .getContextClassLoader(); // Lấy class loader của thread hiện tại
    JdkSerializationRedisSerializer jdkSerializer = new JdkSerializationRedisSerializer(
        loader); // Tạo JdkSerializationRedisSerializer với class loader vừa lấy
    return SerializationPair.fromSerializer(
        jdkSerializer); // Trả về SerializationPair<Object> với JdkSerializationRedisSerializer vừa tạo
  } // Hàm này sẽ được sử dụng để serialize value khi lưu vào Redis với JdkSerializationRedisSerializer (mặc định)

  public RedisCacheConfiguration createDefaultCacheConfiguration(
      long ttl) { // Hàm tạo RedisCacheConfiguration mặc định với thời gian sống là ttl
    return RedisCacheConfiguration.defaultCacheConfig()
        .serializeValuesWith(
            getJdkSerialization()) // thuộc tính serializeValuesWith với giá trị trả về từ hàm getJdkSerialization()
        .computePrefixWith(cacheName -> {
          String prefix = appName + "::"; // Tạo prefix là appName + "::"
          if (StringUtils.hasText(cacheName)) {
            prefix += cacheName + "::"; // Nếu cacheName không rỗng thì thêm cacheName vào prefix
          }
          return prefix; // Trả về prefix vừa tạo
        })
        .entryTtl(Duration.ofMillis(ttl)); // Thiết lập thời gian sống của entry là ttl
  }

  @Bean
  public CacheManager redisCacheManager(RedissonConnectionFactory redissonConnectionFactory,
      RedissonConfigurationProperties properties) {
    Map<String, RedisCacheConfiguration> config = new HashMap<>();
    RedisCacheWriter redisCacheWriter = RedisCacheWriter.nonLockingRedisCacheWriter(redissonConnectionFactory);
    for (Map.Entry<String, Long> cachesWithTtl : properties.getCacheExpirations().entrySet()) {
      config.put(cachesWithTtl.getKey(), createDefaultCacheConfiguration(cachesWithTtl.getValue()));
    }
    return RedisCacheManager.builder(redisCacheWriter)
        .cacheDefaults(createDefaultCacheConfiguration(properties.getTtl()))
        .withInitialCacheConfigurations(config)
        .build();
  }

  /**
   * Sử dụng bằng cách đặt annotation @CacheConfig(cacheNames = {"cacheName"}, cacheManager= "redisCacheManager") trên class
   * Trong đó:
   * * cacheNames: Tên cache
   * * cacheManager: Tên bean CacheManager, có thể tạo nhiều CacheManager với tên khác nhau
   * Ngoài ra, có thể sử dụng @Cacheable(value="namefunc", key="#name", sync=true) trên method để cache kết quả trả về của method ví dụ như method này
   * Trong đó:
   * * value: Tên cache
   * * key: key để lưu cache (cùng key sẽ lấy cache, ko thì sẽ thực thi method), sử dụng SpLE expression
   * * sync: Đồng bộ cache giúp tránh việc nhiều thread cùng truy cập cache cùng một lúc
   * Ví dụ:
   * @Cacheable(value="namefunc", key="#name", sync=true)
   * public String getName(String name) {
   *    return name; // name sẽ được key của Cache get đươợc trong name "namefunc" truyên xuống
   *    }
   *
   */

}
```

#### 2.2.5. Sử dụng `RLock` (Redisson) để đồng bộ hóa các thao tác với Redis.
Chúng ta có thể sử dụng `RLock` để đồng bộ hóa các thao tác với Redis. Điều này giúp tránh tình trạng nhiều thread cùng truy cập cache cùng một lúc.
> RedisLockService.java
```java
package com.example.demo.service;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.redisson.api.RLock;
import org.redisson.api.RedissonClient;
import org.springframework.stereotype.Service;
import java.util.concurrent.Callable;
@Service
@Slf4j
@RequiredArgsConstructor
public class RedisLockService {
  private final RedissonClient redissonClient;

  // Đặt lock với key tương ứng, nếu lock đã được đặt thì sẽ chờ cho đến khi lock được giải phóng.
  public void lock(String key) {
    RLock lock = redissonClient.getLock(key); // Lấy lock với key tương ứng
    try {
      lock.lock(); // Đặt lock
      log.info("Lock acquired for key: {}", key);
    } catch (Exception e) {
      log.error("Error acquiring lock for key: {}", key, e);
    }
  }

  // Giải phóng lock với key tương ứng nếu lock đang được giữ bởi thread hiện tại.
  public void unlock(String key) {
    RLock lock = redissonClient.getLock(key); // Lấy lock với key tương ứng
    try {
      if (lock.isHeldByCurrentThread()) { // Kiểm tra xem lock có đang được giữ bởi thread hiện tại không
        lock.unlock(); // Giải phóng lock
        log.info("Lock released for key: {}", key);
      }
    } catch (Exception e) {
      log.error("Error releasing lock for key: {}", key, e);
    }
  }

  // Thực hiện hành động sau khi đã đặt lock, và giải phóng lock sau khi thực hiện xong.
  public <T> T executeWithLock(String key, Callable<T> action) {
    RLock lock = redissonClient.getLock(key); // Lấy lock với key tương ứng
    try {
      lock.lock(); // Đặt lock
      log.info("Lock acquired for key: {}", key);
      return action.call(); // Thực hiện hành động với lock đã đặt
    } catch (Exception e) {
      log.error("Error executing action with lock for key: {}", key, e);
      throw new RuntimeException(e);
    } finally {
      if (lock.isHeldByCurrentThread()) { // Kiểm tra xem lock có đang được giữ bởi thread hiện tại không
        lock.unlock(); // Giải phóng lock
        log.info("Lock released for key: {}", key);
      }
    }
  }
}
```

```java
  public static String convertToUnsigned(String input){ // chuyển chuỗi có dấu thành không dấu
```

### 2.4. Sử dụng `RedisTemplate` và `ObjectMapper` trong ứng dụng.
Chúng ta có thể sử dụng `RedisTemplate` và `ObjectMapper` để thực hiện các thao tác với Redis.

> CacheService.java
```java
package com.example.demo.service;

import com.example.demo.utils.ObjectMapperUtils;
import java.util.concurrent.TimeUnit;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.data.redis.core.RedisTemplate;
import org.springframework.stereotype.Service;
import org.springframework.util.StringUtils;

@Service
@Slf4j
@RequiredArgsConstructor
public class CacheService {
  private final RedisTemplate<String, Object> redisTemplate;

  @Value("${spring.application.name}")
  private String appName;

  public <T> void setCache(String cacheName, String key, T value) {
    setCache(cacheName, key, value, -1); // Gọi hàm setCache với thời gian hết hạn mặc định là -1 (không hết hạn)
  }

  public <T> void setCache(String cacheName, String key, T value, long timeout) {
    String keyGen = this.keyGen(cacheName, key);
    log.info("RedisCacheTemplate put: cacheName = {}, key = {}, value = {}", cacheName, keyGen,
        ObjectMapperUtils.toJson(value));
    try {
      String valueStr = ObjectMapperUtils.toJson(value); // Chuyển object thành chuỗi JSON
      redisTemplate.opsForValue().set(keyGen, valueStr); // Lưu chuỗi JSON vào Redis
      if (timeout != -1) { // Nếu thời gian hết hạn khác -1 thì set thời gian hết hạn cho keyGen
        redisTemplate.expire(keyGen, timeout, TimeUnit.SECONDS); // Set thời gian hết hạn cho keyGen là timeout giây
      }
    } catch (Exception ex) {
      log.error("SetCache: Redis cache exception", ex);
    }
  }

  public <T> T getCache(String cacheName, String key, Class<T> objectClass) { // Lấy cache từ Redis
    String keyGen = this.keyGen(cacheName, key); // Tạo key cho cache
    log.info("RedisCacheTemplate get: cacheName = {}, key = {}", cacheName, keyGen); // Log thông tin cacheName và key
    String valueStr = (String) redisTemplate.opsForValue().get(keyGen); // Lấy giá trị từ Redis với keyGen và ép kiểu về String (JSON)
    if (valueStr == null) { // Nếu valueStr rỗng thì trả về null
      log.info("Key {} does not exist", keyGen);
      return null;
    } else {
      try {
        return ObjectMapperUtils.fromJson(valueStr, objectClass); // Chuyển chuỗi JSON thành object với class objectClass
      } catch (Exception ex) {
        log.error("GetCache: Redis cache exception", ex);
        return null;
      }
    }
  }

  public void deleteCache(String cacheName, String key) { // Xóa cache từ Redis
    String keyGen = this.keyGen(cacheName, key); // Tạo key cho cache
    log.info("RedisCacheTemplate delete: cacheName = {}, key = {}", cacheName, keyGen);
    Boolean isDeleted = redisTemplate.delete(keyGen); // Xóa keyGen từ Redis
    if (!Boolean.TRUE.equals(isDeleted)) {
      log.info("Key {} does not exist or delete fail", keyGen);
    }
  }

  private String keyGen(String cacheName, Object key) { // Tạo key cho cache
    return StringUtils.hasLength(cacheName) ? this.appName + ":" + cacheName + ":" + key : key.toString();
  } 

}
```

TỪ `CacheService` chúng ta có thể Inject vào các `Service` khác để thực hiện các thao tác với Redis.

### 2.5. Sử dụng `@Cacheable`, `@CachePut`, `@CacheEvict` trong ứng dụng.

Sau đó, chúng ta có thể sử dụng các annotation `@Cacheable`, `@CachePut`, `@CacheEvict` trong các `Service` khác để thực hiện các thao tác với cache. Trong đó:
- `@Cacheable`: Đánh dấu phương thức sẽ cache kết quả trả về của phương thức. Spring sẽ kiểm tra cache trước khi thực hiện phương thức, nếu chưa có cache thì sẽ thực hiện khối logic trong code
- `@CachePut`: Đánh dấu phương thức sẽ cache kết quả trả về của phương thức và cập nhật cache.
- `@CacheEvict`: Đánh dấu phương thức sẽ xóa cache.
- `@Caching`: Đánh dấu phương thức sẽ thực hiện nhiều thao tác với cache.
- `@CacheConfig`: Đánh dấu class sẽ sử dụng cache với tên cache và cacheManager cụ thể, ví dụ trong `RedissonCacheConfig` thì chúng ta có thể khai báo `@CacheConfig(cacheNames = {"cacheName"}, cacheManager= "redisCacheManager")` trên class. Ngoài ra, nếu có nhiều `CacheManager` ở trong file khác thì chúng ta có thể khai báo nhiều `CacheManager` khác nhau.

> Service.java

```java
  @PostConstruct // Được gọi sau khi bean được khởi tạo (Được gọi sau khi constructor và trước khi các phương thức khác được gọi)
  public void init() {
    CacheLoader<String, UserDto> loader = this::load; // Tạo một loader để load dữ liệu khi không tìm thấy trong cache (Nhận key là String và trả về UserDto giống với LoadingCache)
    loadingCache = Caffeine.newBuilder() // Tạo một LoadingCache với các cấu hình
        .maximumSize(Integer.MAX_VALUE) // Số lượng phần tử tối đa trong cache
        .expireAfterWrite(Duration.ofMinutes(EXPIRETIME)) // Thời gian hết hạn cache
        .evictionListener((key, value, cause) -> log.info("removing key - {}, value - {}, cause: {}", key, value, cause)) // Listener khi xóa phần tử khỏi cache
        .build(loader); // Sử dụng loader để load dữ liệu khi không tìm thấy trong cache
  }

  private UserDto load(String key) { // Phương thức load dữ liệu vào CacheLoader (Nhận key là String và trả về UserDto giống với CacheLoader)
    try {
      log.info("GET USER FROM KEY [{}]", key);
      ResponseEntity<UserDto> responseEntity = restTemplateService.process(
          HttpMethod.GET,
          "https://jsonplaceholder.typicode.com/users",
          null,
          "null",
          new ParameterizedTypeReference<UserDto>() {
          }
      );
      return responseEntity.getBody();
    } catch (Exception ex) {
      log.error("CacheLocal.load error: " + ex.getMessage(), ex);
      return null;
    }
  }

  public UserDto getUser(String key) { // Phương thức lấy dữ liệu từ cache gọi đến LoadingCache, nếu không tìm thấy sẽ gọi đến phương thức load
    if (!StringUtils.hasText(key)) {
      log.error("Key is empty");
      return null;
    }
    UserDto userDto = loadingCache.get(key);
    log.info("Get user from cache: {}", userDto);
    return userDto;
  }
}

```

### 3.3. Sử dụng `CacheLoading` ở nơi khác
Sau khi cấu hình `LoadingCache` và tạo hàm để lấy dữ liệu từ `LoadingCache`, chúng ta có thể sử dụng `LoadingCache` ở nơi khác trong ứng dụng.

>UserService.java
```java
package com.didan.loading_cache.service;

import com.didan.loading_cache.dto.UserDto;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Service;

@Service
@Slf4j
@RequiredArgsConstructor
public class UserService {
  private final CacheUserService cacheUserService;

  public UserDto getUser(String key) {
    return cacheUserService.getUser(key); // Gọi đến phương thức getUser trong CacheLocal để lấy dữ liệu từ cache
  }
}
```
