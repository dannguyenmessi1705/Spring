# Reactive Spring Boot
## 1. Giới thiệu về Reactive Programming
Reactive Programming là một mô hình lập trình tập trung vào việc xử lý dữ liệu và sự kiện bất đồng bộ, cho phép xây dựng các ứng dụng có khả năng mở rộng cao và phản hồi nhanh. Trong bối cảnh của Spring Boot, Reactive Programming được hỗ trợ thông qua Spring WebFlux, một module cung cấp các công cụ để xây dựng các ứng dụng web phản ứng.

## 2. Lợi ích của Reactive Spring Boot
- **Hiệu suất cao**: Reactive Spring Boot sử dụng mô hình lập trình không chặn (non-blocking), giúp tối ưu hóa việc sử dụng tài nguyên hệ thống và cải thiện hiệu suất của ứng dụng.
- **Khả năng mở rộng**: Ứng dụng Reactive có thể dễ dàng mở rộng để xử lý nhiều kết nối đồng thời mà không cần tăng tài nguyên phần cứng.
- **Phản hồi nhanh**: Reactive Spring Boot giúp ứng dụng phản hồi nhanh hơn với người dùng, đặc biệt trong các tình huống tải cao.
- **Dễ dàng tích hợp**: Spring WebFlux có thể dễ dàng tích hợp với các công nghệ khác trong hệ sinh thái Spring, như Spring Data, Spring Security, v.v.
## 3. Các thành phần chính của Reactive Spring Boot
- **Spring WebFlux**: Module chính để xây dựng các ứng dụng web phản ứng, hỗ trợ cả lập trình dựa trên annotation và lập trình chức năng.
- **Project Reactor**: Thư viện lập trình phản ứng được sử dụng trong Spring WebFlux, cung cấp các loại dữ liệu như Mono và Flux để xử lý luồng dữ liệu bất đồng bộ.
- **Reactive Repositories**: Spring Data cung cấp các repository phản ứng để làm việc với cơ sở dữ liệu một cách hiệu quả trong môi trường phản ứng.
## 4. So sánh giữa Spring MVC và Spring WebFlux
| Đặc điểm               | Spring MVC                     | Spring WebFlux                |
|-----------------------|--------------------------------|-------------------------------|
| Mô hình lập trình     | Blocking (chặn)                | Non-blocking (không chặn)     |
| Xử lý kết nối đồng thời | Hạn chế                        | Cao                           |
| Hiệu suất              | Thấp hơn trong tải cao          | Cao hơn trong tải cao          |
| Thư viện sử dụng      | Servlet API                    | Project Reactor                |
| Phù hợp cho            | Ứng dụng truyền thống          | Ứng dụng hiện đại, tải cao      |

### 4.1. Ví dụ so sánh đơn giản giữa Spring MVC và Spring WebFlux
#### Spring MVC
```java
@RestController
public class HelloController {
    @GetMapping("/hello")
    public String hello() {
        return "Hello, World!";
    }
}
```
#### Spring WebFlux
```java
@RestController
public class HelloController {
    @GetMapping("/hello")
    public Mono<String> hello() {
        return Mono.just("Hello, World!");
    }
}
```
> Khi call API `/hello`, Spring MVC sẽ chặn luồng cho đến khi trả về kết quả, trong khi Spring WebFlux sẽ trả về một `Mono` ngay lập tức và xử lý kết quả bất đồng bộ.

Ví dụ khác, khi sử dụng `ChatGPT` yêu cầu trả lời, nếu sử dụng mô hình blocking, hệ thống sẽ phải chờ đợi cho đến khi nhận được phản hồi từ ChatGPT trước khi tiếp tục xử lý các yêu cầu khác. Trong khi đó, với mô hình non-blocking, hệ thống có thể trả về một phản hồi tạm thời (như "Đang xử lý yêu cầu của bạn...") hoặc trả lời từng phần khi nhận được dữ liệu từ ChatGPT, cho phép hệ thống tiếp tục xử lý các yêu cầu khác trong khi chờ đợi phản hồi hoàn chỉnh. Để làm như vậy, ta sử dụng kỹ thuật như sau:
```java
@RestController
public class HelloController {
      private final WebClient webClient = WebClient.create(); // Sử dụng WebClient (non-blocking)
    @GetMapping(path = "/reply/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<ResponseDto> hello() {
        return webClient.get()
            .uri("https://api.openai.com/v1/chat/completions")
            .retrieve()
            .bodyToFlux(ResponseDto.class)
            .onErrorComplete() // Nếu có lỗi, hoàn thành luồng mà không phát sinh lỗi
            .doOnNext(response -> log.info("Received chunk from ChatGPT API: {}", response));
            // .subscribe(); // Không cần subscribe ở đây, để Spring WebFlux quản lý luồng dữ liệu (Chỉ dùng khi không trả về Flux hoặc Mono từ controller )
    }
}
```
> Khi call API `/reply/stream`, hệ thống sẽ trả về một luồng dữ liệu (stream) và có thể gửi các phần dữ liệu từng phần khi chúng sẵn sàng, thay vì chờ đợi toàn bộ phản hồi từ ChatGPT, nhờ sử dụng `Flux` và `MediaType.TEXT_EVENT_STREAM_VALUE`.
> Khi có lỗi trong quá trình gọi API, `onErrorComplete()` sẽ giúp hoàn thành luồng mà không phát sinh lỗi, đảm bảo rằng hệ thống vẫn hoạt động bình thường và có thể tiếp tục xử lý các yêu cầu khác.
> Trong các trường hợp, cần thêm `subscribe()` để kích hoạt luồng dữ liệu, tuy nhiên trong controller của Spring WebFlux, không cần gọi `subscribe()` vì Spring sẽ tự động quản lý việc này khi trả về `Flux` hoặc `Mono`.
> Ngoài sử dụng `.retrieve().bodyToFlux(...)`, `.retrieve().bodyToMono(...)`, bạn cũng có thể sử dụng `.exchangeToFlux(...)`, `.exchangeToMono(...)` để có thêm quyền kiểm soát phản hồi HTTP, bao gồm việc xử lý mã trạng thái và tiêu đề.

```java
@RestController
public class HelloController {
      private final WebClient webClient = WebClient.create(); // Sử dụng WebClient (non-blocking)
    @GetMapping("/reply/mono")
    public Mono<ResponseDto> hello() {
        return webClient.get()
            .uri("https://api.openai.com/v1/chat/completions")
            .exchangeToMono(response -> {
                if (response.statusCode().is2xxSuccessful()) {
                    return response.bodyToMono(ResponseDto.class);
                } else {
                    return Mono.error(new RuntimeException("Failed to fetch data from ChatGPT API"));
                }
            })
            .doOnNext(response -> log.info("Received response from ChatGPT API: {}", response));
            // .subscribe(); // Không cần subscribe ở đây, để Spring WebFlux quản lý luồng dữ liệu (Chỉ dùng khi không trả về Flux hoặc Mono từ controller )
    }
}
```
Lưu ý rằng, không được nhầm lẫn, hiểu lầm giữa mô hình non-blocking với việc trả về phản hồi ngay lập tức. Mô hình non-blocking cho phép hệ thống tiếp tục xử lý các yêu cầu khác trong khi chờ đợi phản hồi, nhưng không có nghĩa là phản hồi sẽ được trả về ngay lập tức. Phản hồi vẫn sẽ được gửi khi dữ liệu sẵn sàng, nhưng hệ thống không bị chặn trong quá trình chờ đợi đó.
```java
@RestController
public class HelloController {
    private final RestClient restClient = RestClient.builder()
      .requestFactory(new JdkClientHttpRequestFactory())
      .build(); // Sử dụng RestClient truyền thống (blocking)

    @GetMapping("/chatgpt/reply")
    public Flux<ResponseDto> getReply() {
        var list = restClient.get()
            .uri("https://api.openai.com/v1/chat/completions")
            .retrieve()
            .body(new ParameterizedTypeReference<List<ResponseDto>>() {});
        log.info("Request sent to ChatGPT API");
        return Flux.fromIterable(list); 
    }
}
```
> Đây không phải là `Reactive Pipeline`, mặc dù sử dụng `Flux` để trả về dữ liệu, nhưng toàn bộ quá trình gọi API vẫn là blocking do sử dụng `RestClient` trong cách thông thường. Hệ thống sẽ chờ đợi cho đến khi nhận được toàn bộ phản hồi từ ChatGPT trước khi tiếp tục xử lý các yêu cầu khác.

# Các Functional Interface trong Java
## 1. Giới thiệu về Functional Interface
Functional Interface là một interface trong Java chỉ chứa một phương thức trừu tượng duy nhất. Chúng được sử dụng rộng rãi trong lập trình hàm (functional programming) và là cơ sở cho các biểu thức lambda trong Java 8 trở lên. Functional Interface cho phép bạn truyền các hành vi (behavior) dưới dạng đối tượng, giúp mã nguồn trở nên ngắn gọn và dễ đọc hơn.

## 2. Các Functional Interface phổ biến trong Java
### 2.1. `Function<T, R>`
- Công dụng: Nhận một đối tượng kiểu T và trả về một đối tượng kiểu R.
- Method: `R apply(T t)`
```java
// Ví dụ: Chuyển String thành độ dài của nó
Function<String, Integer> stringLength = s -> s.length();
System.out.println(stringLength.apply("Hello")); // Output: 5
```

### 2.2. `BiFunction<T, U, R>`
- Công dụng: Nhận hai đối tượng kiểu T và U, và trả về một đối tượng kiểu R.
- Method: `R apply(T t, U u)`
```java
// Ví dụ: Cộng hai số nguyên
BiFunction<Integer, Integer, Integer> add = (a, b) -> a + b;
System.out.println(add.apply(5, 10)); // Output: 15
```

### 2.3. `Consumer<T>`
- Công dụng: Nhận một đối tượng kiểu T và không trả về giá trị.
- Method: `void accept(T t)`
```java
// Ví dụ: In ra một chuỗi
Consumer<String> print = s -> System.out.println(s);
print.accept("Hello, World!"); // Output: Hello, World!
```
### 2.4. `BiConsumer<T, U>`
- Công dụng: Nhận hai đối tượng kiểu T và U, và không trả về giá trị.
- Method: `void accept(T t, U u)`
```java
// Ví dụ: In ra hai chuỗi
BiConsumer<String, String> printNames = (firstName, lastName) -> System.out.println(firstName + " " + lastName);
printNames.accept("John", "Doe"); // Output: John Doe
```
### 2.5. `Supplier<T>`
- Công dụng: Không nhận đối số và trả về một đối tượng kiểu T.
- Method: `T get()`
```java
// Ví dụ: Cung cấp một chuỗi
Supplier<String> stringSupplier = () -> "Hello, World!";
System.out.println(stringSupplier.get()); // Output: Hello, World!
```

### 2.6. `Predicate<T>`
- Công dụng: Nhận một đối tượng kiểu T và trả về một giá trị boolean.
- Method: `boolean test(T t)`
```java
// Ví dụ: Kiểm tra xem một chuỗi có độ dài lớn hơn 5 hay không
Predicate<String> isLongerThan5 = s -> s.length() > 5;
System.out.println(isLongerThan5.test("Hello")); // Output: false
System.out.println(isLongerThan5.test("Hello, World!")); // Output: true
```
### 2.7. `BiPredicate<T, U>`
- Công dụng: Nhận hai đối tượng kiểu T và U, và trả về một giá trị boolean.
- Method: `boolean test(T t, U u)`
```java
// Ví dụ: Kiểm tra xem hai số có bằng nhau hay không
BiPredicate<Integer, Integer> areEqual = (a, b) -> a.equals(b);
System.out.println(areEqual.test(5, 5)); // Output: true
System.out.println(areEqual.test(5, 10)); // Output: false
``` 
### 2.8. `UnaryOperator<T>`
- Công dụng: Nhận một đối tượng kiểu T và trả về một đối tượng kiểu T.
- Method: `T apply(T t)`
```java
// Ví dụ: Tăng gấp đôi một số nguyên
UnaryOperator<Integer> doubleValue = n -> n * 2;
System.out.println(doubleValue.apply(5)); // Output: 10
```
### 2.9. `BinaryOperator<T>`
- Công dụng: Nhận hai đối tượng kiểu T và trả về một đối tượng kiểu T.
- Method: `T apply(T t1, T t2)`
```java
// Ví dụ: Cộng hai số nguyên
BinaryOperator<Integer> add = (a, b) -> a + b;
System.out.println(add.apply(5, 10)); // Output: 15
```
### 2.10. `Runnable`
- Công dụng: Không nhận đối số và không trả về giá trị.
- Method: `void run()`
```java
// Ví dụ: In ra một thông điệp
Runnable printMessage = () -> System.out.println("Hello, World!");
printMessage.run(); // Output: Hello, World!
```
### 2.11. `Callable<V>`
- Công dụng: Không nhận đối số và trả về một đối tượng kiểu V, có thể ném ra ngoại lệ.
- Method: `V call() throws Exception`
```java
// Ví dụ: Cung cấp một chuỗi, có thể ném ra ngoại lệ
Callable<String> stringCallable = () -> {
    if (Math.random() > 0.5) {
        throw new Exception("Random failure");
    }
    return "Hello, World!";
};

try {
    System.out.println(stringCallable.call()); // Output: Hello, World!
} catch (Exception e) {
    System.err.println(e.getMessage());
}
```
### 2.12. `Comparator<T>`
- Công dụng: So sánh hai đối tượng kiểu T và trả về một giá trị nguyên.
- Method: `int compare(T o1, T o2)`
```java
// Ví dụ: So sánh hai chuỗi
Comparator<String> stringComparator = (s1, s2) -> s1.length() - s2.length();
System.out.println(stringComparator.compare("Hello", "World")); // Output: 0
System.out.println(stringComparator.compare("Hello", "Java")); // Output: 1
System.out.println(stringComparator.compare("Java", "Hello")); // Output: -1
```

# R2DBC vs Spring Data
## 1. Giới thiệu về R2DBC và Spring Data
R2DBC (Reactive Relational Database Connectivity) là một tiêu chuẩn kết nối cơ sở dữ liệu quan hệ theo mô hình lập trình phản ứng (reactive programming). Nó cho phép các ứng dụng tương tác với cơ sở dữ liệu một cách không chặn (non-blocking) và bất đồng bộ, giúp tối ưu hóa hiệu suất và khả năng mở rộng của ứng dụng.

Spring Data là một dự án trong hệ sinh thái Spring cung cấp các công cụ và thư viện để làm việc với cơ sở dữ liệu một cách dễ dàng và hiệu quả. Spring Data hỗ trợ nhiều loại cơ sở dữ liệu khác nhau, bao gồm cả cơ sở dữ liệu quan hệ và NoSQL.

## 2. So sánh R2DBC và Spring Data
### 2.1. R2DBC
- **Ưu điểm**:
  - Hỗ trợ mô hình lập trình phản ứng, giúp tối ưu hóa hiệu suất và khả năng mở rộng.
  - Cho phép xử lý nhiều kết nối đồng thời mà không cần tăng tài nguyên phần cứng.
  - Thích hợp cho các ứng dụng hiện đại, tải cao và yêu cầu phản hồi nhanh với áp lực ngược (Backpressure).

- **Nhược điểm**:
    - Cần phải sử dụng các thư viện và công cụ hỗ trợ R2DBC, có thể làm tăng độ phức tạp của dự án.
    - Không phải tất cả các cơ sở dữ liệu quan hệ đều hỗ trợ R2DBC.
    - Không có các tính năng phong phú như Spring Data trong việc quản lý dữ liệu và truy vấn như không có các annotation như `@OneToMany`, `@ManyToOne`, v.v.

`R2DBC` có các driver riêng biệt cho từng cơ sở dữ liệu, ví dụ như:
- `r2dbc-postgresql` cho PostgreSQL
- `r2dbc-mysql` cho MySQL
- `r2dbc-mssql` cho Microsoft SQL Server
- `r2dbc-h2` cho H2 Database
- `r2dbc-mariadb` cho MariaDB
- `oracle-r2dbc` cho Oracle Database
- `jasync-r2dbc`
- `cloud-spanner-r2dbc` cho Google Cloud Spanner
- `clickhouse-r2dbc` cho ClickHouse

Ví dụ `connection string` kết nối đến cơ sở dữ liệu H2 sử dụng R2DBC:
```application.properties
# Cấu hình r2dbc đên thư mục chứa file sql khởi tạo (nêu cần chạy khi khởi động ứng dụng)
spring.sql.init.data-locations=classpath:sql/data.sql

# Cấu hình kết nối R2DBC đến cơ sở dữ liệu H2 trong bộ nhớ
spring.r2dbc.url=r2dbc:h2:mem:///./testdb;DB_CLOSE_DELAY=-1;DB_CLOSE_ON_EXIT=FALSE
spring.r2dbc.username=sa
spring.r2dbc.password=

# Cấu hình log để hiển thị các câu lệnh SQL được thực thi
logging.level.org.springframework.r2dbc="DEBUG"
```

> Lưu ý, vì không phải Spring WebMVC nên sẽ không thể truy cập vào `/h2-console` được, thay vào đó bạn có thể sử dụng các công cụ bên ngoài như DBeaver, DataGrip, hoặc các công cụ dòng lệnh để kết nối và quản lý cơ sở dữ liệu H2.

*Spring Data R2DBC* là một phần mở rộng của Spring Data, cung cấp các repository phản ứng để làm việc với cơ sở dữ liệu R2DBC một cách dễ dàng và hiệu quả.
```java
public interface UserRepository extends ReactiveCrudRepository<User, Long> {
    Flux<User> findByLastName(String lastName);

    Mono<User> findByEmail(String email);

    @Query("SELECT * FROM users WHERE age > :age")
    Flux<User> findUsersOlderThan(int age);
    
    @Query("UPDATE users SET status = :status WHERE id = $1")
    Mono<Integer> updateUserStatusById(String status, Long id);

    @Modifying // Chỉ định đây là một truy vấn thay đổi dữ liệu
    @Query("DELETE FROM users WHERE last_login < :date")
    Mono<Integer> deleteUsersInactiveSince(LocalDate date);
}
```

Với clas tạo Entity, khác với JPA, Spring Data R2DBC sử dụng các annotation như `@Table`, `@Column`, `@Id`, v.v. để định nghĩa các thực thể và ánh xạ chúng với bảng trong cơ sở dữ liệu, và không hỗ trợ các annotation như `@OneToMany`, `@ManyToOne`, cũng như các tùy chọn cascade và fetch type.
```java
@Table("users")
public class User {
    @Id
    private Long id;

    @Column("first_name")
    private String firstName;

    @Column("last_name")
    private String lastName;

    @Column("email")
    private String email;

    // Getters and Setters
}
```

### 2.2. Database Client
Database Client là một thành phần trong Spring Data R2DBC, cung cấp một API cấp cao để tương tác với cơ sở dữ liệu R2DBC một cách linh hoạt và dễ dàng. Nó cho phép bạn thực hiện các truy vấn SQL, cập nhật dữ liệu và quản lý giao dịch một cách phản ứng.
Ví dụ sử dụng Database Client để thực hiện một truy vấn đơn giản:
```java
import org.springframework.r2dbc.core.DatabaseClient;
import reactor.core.publisher.Flux;
import reactor.core.publisher.Mono;
import org.springframework.stereotype.Repository;
@Repository
public class UserRepositoryCustom {

    private final DatabaseClient databaseClient;

    public UserRepositoryCustom(DatabaseClient databaseClient) {
        this.databaseClient = databaseClient;
    }

    public Flux<User> findUsersByLastName(String lastName) {
        return databaseClient.sql("SELECT * FROM users WHERE last_name = :lastName")
                .bind("lastName", lastName) // Đặt giá trị cho tham số :lastName 
                .map((row, metadata) -> { // Ánh xạ kết quả truy vấn thành đối tượng User
                    User user = new User(); // Tạo một đối tượng User mới
                    user.setId(row.get("id", Long.class)); // Lấy giá trị cột "id" và gán cho thuộc tính id của User
                    user.setFirstName(row.get("first_name", String.class)); // Lấy giá trị cột "first_name" và gán cho thuộc tính firstName của User
                    user.setLastName(row.get("last_name", String.class)); // Lấy giá trị cột "last_name" và gán cho thuộc tính lastName của User
                    user.setEmail(row.get("email", String.class)); // Lấy giá trị cột "email" và gán cho thuộc tính email của User
                    return user; // Trả về đối tượng User đã được ánh xạ
                })
                .all(); // Trả về tất cả các kết quả dưới dạng Flux<User>
    }

    public Mono<Integer> updateUserEmail(Long id, String newEmail) {
        return databaseClient.sql("UPDATE users SET email = :email WHERE id = :id")
                .bind("email", newEmail)
                .bind("id", id)
                .fetch() // Lấy đối tượng FetchSpec để thực hiện truy vấn
                .rowsUpdated(); // Trả về số lượng hàng bị ảnh hưởng dưới dạng Mono<Integer>
    }
}
```

## 3. Sử dụng Pageable với R2DBC
Spring Data R2DBC hỗ trợ phân trang (pagination) thông qua việc sử dụng `Pageable` trong các phương thức repository. Điều này cho phép bạn dễ dàng truy xuất dữ liệu theo từng trang, giúp tối ưu hóa hiệu suất khi làm việc với tập dữ liệu lớn.
Ví dụ về cách sử dụng `Pageable` trong một repository R2DBC:
```java
import org.springframework.data.domain.Page;
import org.springframework.data.domain.Pageable;
import org.springframework.data.r2dbc.repository.Query;
import org.springframework.data.repository.reactive.ReactiveCrudRepository;
import reactor.core.publisher.Mono;
public interface UserRepository extends ReactiveCrudRepository<User, Long> {

    @Query("SELECT * FROM users")
    Flux<User> findAllBy(Pageable pageable); // Nên sử dụng Flux thay vì Mono<Page> vì Flux sẽ phù hợp trả về các luồng dữ liệu hơn
}
```
Nên sử dụng `Flux<User>` thay vì `Mono<Page<User>>` vì `Flux` sẽ phù hợp trả về các luồng dữ liệu hơn trong môi trường phản ứng (reactive). Khi sử dụng `Flux`, bạn có thể dễ dàng xử lý từng phần tử trong luồng dữ liệu một cách linh hoạt và hiệu quả hơn khi làm việc với R2DBC. Sau đó, ở tầng `Service` hoặc `Controller`, bạn có convert về `Mono<Page<User>>` nếu cần thiết.
```java
import org.springframework.data.domain.Page;
import org.springframework.data.domain.PageImpl;
import org.springframework.data.domain.Pageable;
import reactor.core.publisher.Flux;
import reactor.core.publisher.Mono;
public Mono<Page<User>> getUsers(Pageable pageable) {
    return userRepository.findAllBy(pageable)
            .collectList() // Thu thập tất cả người dùng vào một danh sách (Mono<List<User>>)
            .zipWith(userRepository.count()) // Kết hợp với Mono<Long> đếm tổng số người dùng
            .map(tuple -> new PageImpl<>(tuple.getT1(), pageable, tuple.getT2())); // Tạo Page<User> từ danh sách người dùng
}
```

## 4. Sử dụng `StepVerifier` để kiểm thử R2DBC
Khi làm việc với R2DBC và các luồng dữ liệu phản ứng, việc kiểm thử các luồng này là rất quan trọng để đảm bảo rằng chúng hoạt động đúng như mong đợi. `StepVerifier` là một công cụ mạnh mẽ trong thư viện Reactor Test, giúp bạn kiểm thử các luồng dữ liệu phản ứng một cách dễ dàng và hiệu quả.
Dưới đây là một ví dụ về cách sử dụng `StepVerifier` để kiểm thử một phương thức trong repository sử dụng R2DBC:
```java
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;  
import org.springframework.boot.test.autoconfigure.data.r2dbc.DataR2dbcTest;
import reactor.core.publisher.Flux;
import reactor.test.StepVerifier;

@DataR2dbcTest
public class UserRepositoryTest {

    @Autowired
    private UserRepository userRepository;

    @Test
    public void testFindByLastName() {
        Flux<User> users = userRepository.findByLastName("Doe");

        StepVerifier.create(users)
                .expectNextMatches(user -> user.getLastName().equals("Doe"))
                .verifyComplete();
    }
}
```
Trong ví dụ trên, chúng ta đã tạo một lớp kiểm thử `UserRepositoryTest` sử dụng annotation `@DataR2dbcTest` để cấu hình môi trường kiểm thử cho R2DBC. Chúng ta đã kiểm thử phương thức `findByLastName` trong `UserRepository` bằng cách sử dụng `StepVerifier`. Chúng ta tạo một `Flux<User>` từ phương thức và sử dụng `StepVerifier` để xác nhận rằng luồng dữ liệu trả về đúng như mong đợi, với ít nhất một người dùng có họ là "Doe" và kết thúc luồng một cách hoàn chỉnh.

Ngoài ra `SepVerifier` còn cung cấp nhiều phương thức khác để kiểm thử các luồng dữ liệu phản ứng, như:
- `create()`: Tạo một `StepVerifier` từ một `Publisher`.
- `expectNext()`: Kiểm tra các phần tử tiếp theo trong luồng.
- `expectNextMatches()`: Kiểm tra phần tử tiếp theo dựa trên một điều kiện.
- `expectNextCount()`: Kiểm tra số lượng phần tử tiếp theo.
- `thenConsumeWhile()`: Tiêu thụ các phần tử trong luồng cho đến khi điều kiện không còn đúng.
- `assertNext()`: Kiểm tra phần tử tiếp theo với một hàm kiểm tra tùy chỉnh.
- `expectComplete()`: Kiểm tra rằng luồng đã hoàn thành.
- `expectError()`: Kiểm tra rằng luồng đã kết thúc với một lỗi cụ thể.
- `verify()`: Kích hoạt quá trình kiểm thử và xác nhận các kỳ vọng đã được thiết lập.

```java
var flux = Flux.just(1, 2, 3, 4, 5); // Tạo một Flux với các số từ 1 đến 5 
StepVerifier.create(flux) // Tạo StepVerifier từ Flux
    .expectNext(1) // Kiểm tra phần tử tiếp theo là 1
    .expectNextCount(4) // Kiểm tra có thêm 4 phần tử tiếp theo (2, 3, 4, 5)
    .expectComplete() // Kiểm tra rằng luồng đã hoàn thành
    .verify(); // Kích hoạt quá trình kiểm thử
```

> Khi sử dụng `Flux` hoặc `Mono` trong Spring, thường có hàm `doOnNext()` để thực hiện một hành động phụ khi một phần tử được phát ra. Chúng ta có thể tận dụng nó để có thể xử lý dữ liệu được phát ra ngay mà không cần phải chờ đến khi hoàn thành toàn bộ luồng dữ liệu. Ví dụ:
```java
// Spring MVC
User user = userRepository.findById(id);
user.setName("New Name");
userRepository.save(user);

// Spring WebFlux
userRepository.findById(id)
    .doOnNext(user -> {
        user.setName("New Name");
        userRepository.save(user).subscribe(); // Lưu thay đổi ngay lập tức, subscribe để kích hoạt luồng dữ liệu
    })
    .subscribe();
```

> sử dụng `flatMap()` để thực hiện các thao tác bất đồng bộ trên từng phần tử trong luồng dữ liệu thay cho `map()`, vì `map()` chỉ biến đổi dữ liệu mà không hỗ trợ các thao tác bất đồng bộ.
> Sử dụng `concatMap()` khi bạn muốn duy trì thứ tự của các phần tử trong luồng dữ liệu, trong khi `flatMap()` có thể không đảm bảo thứ tự.
```java
userRepository.findByName("Dan")
    .doOnNext(user -> {
        user.setName("New Name");
    })
    .flatMap(user -> userRepository.save(user)) // Sử dụng flatMap để lưu thay đổi bất đồng bộ
    .subscribe();
```

> Có thể sử dụng `Spring Data JPA` trong các ứng dụng `Spring WebFlux`, tuy nhiên cần lưu ý rằng `Spring Data JPA` hoạt động theo mô hình lập trình đồng bộ (blocking), khi sử dụng trong môi trường phản ứng (reactive) như `Spring WebFlux`, cần phải đảm bảo rằng các thao tác truy cập cơ sở dữ liệu không chặn luồng chính của ứng dụng. Điều này có thể được thực hiện bằng cách sử dụng các kỹ thuật như `Schedulers` để chuyển đổi các thao tác đồng bộ sang các luồng riêng biệt, tránh làm tắc nghẽn luồng chính.
```java
import reactor.core.scheduler.Schedulers;

Mono.fromSupplier(() -> userJpaRepository.findById(id))
    .subscribeOn(Schedulers.boundedElastic()) // Chuyển đổi thao tác đồng bộ sang luồng riêng biệt (rất quan trọng)
    .map(user -> {
        user.setName("New Name");
        return userJpaRepository.save(user);
    })
    .doOnNext(savedUser -> {
        // Xử lý sau khi lưu thành công
    });
```

## 1. Giới thiệu
Trong phần này, chúng ta sẽ xây dựng một ứng dụng CRUD (Create, Read, Update, Delete) đơn giản sử dụng Spring WebFlux và R2DBC để tương tác với cơ sở dữ liệu phản ứng. Chúng ta sẽ tạo một API RESTful để quản lý các thực thể "User".

## 2. Cấu hình dự án
Trước tiên, hãy tạo một dự án Spring Boot mới với các phụ thuộc sau trong `build.gradle` hoặc `pom.xml`:

- Spring Data R2DBC
- R2DBC Driver cho cơ sở dữ liệu bạn đang sử dụng (ví dụ: H2, PostgreSQL, MySQL, v.v.)
- Lombok (tùy chọn, để giảm boilerplate code)

Trong `application.properties` hoặc `application.yml`, cấu hình kết nối R2DBC đến cơ sở dữ liệu của bạn. Ví dụ, với H2:

```properties   
spring.r2dbc.username=sa
spring.r2dbc.password=
spring.sql.init.platform=h2
spring.sql.init.mode=always
```
## 4. Tạo thực thể Customer
Tạo một lớp thực thể `Customer` để đại diện cho bảng khách hàng trong cơ sở dữ liệu:
```java
import org.springframework.data.annotation.Id;
import org.springframework.data.relational.core.mapping.Table;
import lombok.Data;
import lombok.NoArgsConstructor;
import lombok.AllArgsConstructor;
import lombok.Builder;
@Data
@NoArgsConstructor
@AllArgsConstructor
@Builder

```

## 5. Tạo Repository
Tạo một interface `CustomerRepository` mở rộng từ `ReactiveCrudRepository` để cung cấp các phương thức CRUD:
```java
import org.springframework.data.repository.reactive.ReactiveCrudRepository;
import reactor.core.publisher.Mono;
public interface CustomerRepository extends ReactiveCrudRepository<Customer, Long> {
    Mono<Customer> findByName(String name);
}
```
## 6. Tạo Service
Tạo một lớp dịch vụ `CustomerService` để xử lý logic nghiệp vụ:
```java
package com.didan.reactive.learn.crud.service;

import com.didan.reactive.learn.crud.dto.CustomerDto;
import com.didan.reactive.learn.crud.mapper.EntityDtoMapper;
import com.didan.reactive.learn.crud.repository.CustomerRepository;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;
import reactor.core.publisher.Flux;
import reactor.core.publisher.Mono;

@Service
@RequiredArgsConstructor
public class CustomerService {

  private final CustomerRepository customerRepository;

  public Flux<CustomerDto> getAllCustomers() {
    return this.customerRepository.findAll() // Lấy tất cả khách hàng từ repository
        .map(EntityDtoMapper::toDto); // Chuyển đổi từng Customer entity thành CustomerDto
  }

  public Mono<CustomerDto> getCustomerById(Integer id) {
    return this.customerRepository.findById(id) // Tìm khách hàng theo ID
        .map(EntityDtoMapper::toDto); // Chuyển đổi Customer entity thành CustomerDto
  }

  public Mono<CustomerDto> saveCustomer(Mono<CustomerDto> customerDtoMono) { // Truyền vào Mono<CustomerDto>
    return customerDtoMono.map(EntityDtoMapper::toEntity) // Chuyển đổi CustomerDto thành Customer entity
        .flatMap(this.customerRepository::save) // Sau khi lưu có kiểu Mono<Customer> nên phải dùng flatMap để tránh lồng Mono
        .map(EntityDtoMapper::toDto);
  }

  public Mono<CustomerDto> updateCustomer(Integer id, Mono<CustomerDto> customerDtoMono) {
    return this.customerRepository.findById(id) // Tìm khách hàng theo ID
        .flatMap(entity -> customerDtoMono) // Lấy dữ liệu mới từ client (Mono<CustomerDto>) dùng flatMap để tránh lồng Mono (biến đổi Mono sang Entity)
        .map(EntityDtoMapper::toEntity) // Chuyển đổi CustomerDto thành Customer entity
        .doOnNext(c -> c.setId(id)) // Đảm bảo ID không bị thay đổi
        .flatMap(customerRepository::save) // Lưu khách hàng đã được cập nhật (Mono<Customer>) dùng flatMap để tránh lồng Mono, vì save trả về Mono<Customer> biến đổi sang DTO
        .map(EntityDtoMapper::toDto); // Chuyển đổi Customer entity thành CustomerDto
  }

  public Mono<Void> deleteCustomer(Integer id) {
    return this.customerRepository.deleteById(id); // Xoá khách hàng theo ID
  }
}
```
> Lưu ý: Sử dụng `flatMap()` để thực hiện các thao tác bất đồng bộ trên từng phần tử trong luồng dữ liệu thay cho `map()`, vì `map()` chỉ biến đổi dữ liệu mà không hỗ trợ các thao tác bất đồng bộ. Ngoài ra, khi thực hiện các thao tác với r2dbc, các phương thức như `save()`, `findById()`, và `deleteById()` đều trả về các kiểu `Mono` hoặc `Flux`, do đó việc sử dụng `flatMap()` hoặc `concatMap()` là cần thiết để xử lý các luồng dữ liệu phản ứng này convert về đúng kiểu.

## 7. Tạo Controller
Tạo một lớp controller `CustomerController` để xử lý các yêu cầu HTTP:
```java
package com.didan.reactive.learn.crud.controller;

import com.didan.reactive.learn.crud.dto.CustomerDto;
import com.didan.reactive.learn.crud.service.CustomerService;
import lombok.RequiredArgsConstructor;
import org.springframework.web.bind.annotation.DeleteMapping;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.PutMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;
import reactor.core.publisher.Flux;
import reactor.core.publisher.Mono;

@RestController
@RequestMapping("customers")
@RequiredArgsConstructor
public class CustomerController {

  private final CustomerService customerService;

  @GetMapping
  public Flux<CustomerDto> allCustomers() {
    return customerService.getAllCustomers();
  }

  @GetMapping("{id}")
  public Mono<CustomerDto> getCustomerById(@PathVariable Integer id) {
    return customerService.getCustomerById(id);
  }

  @PostMapping
  public Mono<CustomerDto> createCustomer(@RequestBody Mono<CustomerDto> customerDto) {
    return customerService.saveCustomer(customerDto);
  }

  @PutMapping("{id}")
  public Mono<CustomerDto> updateCustomer(@PathVariable Integer id,
      @RequestBody Mono<CustomerDto> customerDto) {
    return customerService.updateCustomer(id, customerDto);
  }

  @DeleteMapping("{id}")
  public Mono<Void> deleteCustomer(@PathVariable Integer id) {
    return customerService.deleteCustomer(id);
  }

}
```
> Sử dụng `@RequestBody Mono<T>` khác với `@RequestBody T` ở chỗ `Mono<T>` cho phép xử lý bất đồng bộ và có thể chứa giá trị null, trong khi `T` yêu cầu giá trị không null và đồng bộ. Điều này rất quan trọng trong các ứng dụng phản ứng như Spring WebFlux, nơi mà việc xử lý dữ liệu bất đồng bộ là cần thiết để tận dụng tối đa hiệu suất và khả năng mở rộng của ứng dụng.

## 8. Sử dụng ResponseEntity để trả về phản hồi HTTP
Trong `WebFlux`, nên lưu ý rằng, với `Flux` sẽ trả về một luồng dữ liệu có thể chứa nhiều phần tử, do đó không thể sử dụng `ResponseEntity` để bao bọc `Flux`. Thay vào đó, bạn có thể trả về `Flux` trực tiếp từ controller. Ví dụ:
```java
@GetMapping
public Flux<CustomerDto> allCustomers() {
  return customerService.getAllCustomers();
}
```
Tuy nhiên, với `Mono`, bạn có thể sử dụng `ResponseEntity` để bao bọc phản hồi HTTP. Ví dụ:
```java
@GetMapping("{id}")
public Mono<ResponseEntity<CustomerDto>> getCustomerById(@PathVariable Integer id) {
  return customerService.getCustomerById(id) // Tìm khách hàng theo ID
      .map(ResponseEntity::ok) // Nếu tìm thấy, trả về ResponseEntity với mã 200 OK
      .defaultIfEmpty(ResponseEntity.notFound().build()); // Nếu không tìm thấy, trả về mã 404 Not Found
}
```

## 9. Testing với WebTestClient
Bạn có thể sử dụng `WebTestClient` để kiểm thử các endpoint của bạn trong môi trường WebFlux. Dưới đây là một ví dụ về cách viết các bài kiểm thử cho `CustomerController`:
```java
package com.didan.reactive.learn.crud;

import com.didan.reactive.learn.crud.dto.CustomerDto;
import java.util.Objects;
import lombok.extern.slf4j.Slf4j;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.reactive.AutoConfigureWebTestClient;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.http.MediaType;
import org.springframework.test.web.reactive.server.WebTestClient;

@AutoConfigureWebTestClient
@Slf4j
public class CustomerServiceTest {

  @Autowired
  private WebTestClient client; // Khách hàng WebTestClient để thực hiện các yêu cầu HTTP trong bài kiểm tra

  @Test
  public void allCustomers() {
    client.get() // Tạo yêu cầu GET
        .uri("/customers") // Đặt URI cho yêu cầu
        .exchange() // Thực hiện yêu cầu
        .expectStatus().is2xxSuccessful() // Kiểm tra mã trạng thái HTTP trả về là 2xx
        .expectHeader().contentType(MediaType.APPLICATION_JSON) // Kiểm tra header Content-Type là application/json
        .expectBodyList(CustomerDto.class) // Kỳ vọng phản hồi là một danh sách các đối tượng CustomerDto
        .value(list -> log.info("Customers: {}", list)) // Ghi log danh sách khách hàng nhận được
        .hasSize(10) // Kiểm tra kích thước của danh sách là 10
        .consumeWith(response -> log.info("Response: {}", response.getResponseBody())); // Ghi log phản hồi nhận được
  }

  @Test
  public void paginatedCustomers() {
    this.client.get()
        .uri("/customers/paginated?page=3&size=2") // Gọi API với tham số phân trang page=3 và size=2
        .exchange() // Thực hiện yêu cầu
        .expectStatus().is2xxSuccessful() // Kiểm tra mã trạng thái HTTP trả về là 2xx
        .expectBody() // Kỳ vọng phản hồi
        .consumeWith(r -> log.info("{}", new String(Objects.requireNonNull(r.getResponseBody())))) // Ghi log phản hồi nhận được
        .jsonPath("$.length()").isEqualTo(2) // Kiểm tra độ dài mảng phản hồi là 2 vơi `$` đại diện cho json root
        .jsonPath("$[0].id").isEqualTo(7) // Kiểm tra phần tử đầu tiên có id là 5 với `$` đại diện cho json root
        .jsonPath("$[1].id").isEqualTo(8); // Kiểm tra phần tử thứ hai có id là 6 với `$` đại diện cho json root
  }

  @Test
  public void customerById() {
    this.client.get()
        .uri("/customers/1") // Gọi API để lấy khách hàng có ID là 1
        .exchange() // Thực hiện yêu cầu
        .expectStatus().is2xxSuccessful() // Kiểm tra mã trạng thái HTTP trả về là 2xx
        .expectBody() // Kỳ vọng phản hồi
        .consumeWith(r -> log.info("{}", new String(Objects.requireNonNull(r.getResponseBody())))) // Ghi log phản hồi nhận được
```

# Validation trong Spring WebFlux
## 1. Giới thiệu
Trong Spring WebFlux, việc thực hiện validation (xác thực) dữ liệu đầu vào là rất quan trọng để đảm bảo rằng dữ liệu nhận được từ client là hợp lệ trước khi xử lý. Spring WebFlux hỗ trợ validation thông qua việc sử dụng các annotation từ thư viện `spring-boot-starter-validation`. Cách sử dụng validation trong WebFlux tương tự như trong Spring MVV.

## 3. Custom Validator
Tạo một lớp validator tùy chỉnh để kiểm tra các quy tắc phức tạp hơn:
```java
package com.didan.reactive.learn.validation.validator;

import com.didan.reactive.learn.validation.dto.CustomerDto;
import com.didan.reactive.learn.validation.exception.ApplicationException;
import java.util.Objects;
import java.util.function.Predicate;
import java.util.function.UnaryOperator;
import reactor.core.publisher.Mono;

public class RequestValidator {

  private static Predicate<CustomerDto> hasName() {
    return dto -> Objects.nonNull(dto.name());
  } // Kiểm tra tên không null hoặc rỗng, Predicate<CustomerDto> là một hàm nhận vào CustomerDto và trả về boolean

  private static Predicate<CustomerDto> hasValidEmail() {
    return dto -> Objects.nonNull(dto.email()) && dto.email().contains("@");
  } // Kiểm tra email không null và có chứa ký tự '@', Predicate<CustomerDto> là một hàm nhận vào CustomerDto và trả về boolean

  public static UnaryOperator<Mono<CustomerDto>> validate() {
    return mono -> mono
        .filter(hasName()) // Lọc các CustomerDto có tên hợp lệ
        .switchIfEmpty(ApplicationException.misssingName()) // Nếu không có CustomerDto nào hợp lệ, trả về lỗi tên bị thiếu
        .filter(hasValidEmail()) // Lọc các CustomerDto có email hợp lệ
        .switchIfEmpty(ApplicationException.missingValidEmail()); // Nếu không có CustomerDto nào hợp lệ, trả về lỗi email không hợp lệ
  } // UnaryOperator<Mono<CustomerDto>> là một hàm nhận vào Mono<CustomerDto> và trả về Mono<CustomerDto> sau khi đã kiểm tra các điều kiện
}
```
> Lưu ý: Sử dụng `Predicate<T>` để định nghĩa các điều kiện kiểm tra đầu vào là T đầu ra boolean, và `UnaryOperator<T>` để định nghĩa các phép biến đổi trên T, trong trường hợp này là `Mono<CustomerDto>` trước và sau khi validation.

## 4. Sử dụng Validator trong Service
Áp dụng validator tùy chỉnh trong lớp dịch vụ để kiểm tra dữ liệu đầu vào:
```java
@RestController
@RequestMapping("customers")
@RequiredArgsConstructor
public class CustomerController {
  
  @GetMapping("{id}")
  public Mono<CustomerDto> getCustomerById(@PathVariable Integer id) {
    return customerService.getCustomerById(id)
        .switchIfEmpty(ApplicationException.customerNotFound(id)); // Nếu không tìm thấy khách hàng, trả về lỗi CustomerNotFoundException
  }

  @PostMapping
  public Mono<CustomerDto> createCustomer(@RequestBody Mono<CustomerDto> customerDto) {
    return customerDto.transform(RequestValidator.validate()) // Áp dụng bộ validator để kiểm tra dữ liệu đầu vào
        .as(customerService::saveCustomer); // Lưu khách hàng nếu dữ liệu hợp lệ
  }

  @PutMapping("{id}")
  public Mono<CustomerDto> updateCustomer(@PathVariable Integer id,
      @RequestBody Mono<CustomerDto> customerDto) {
    return customerDto.transform(RequestValidator.validate()) // transform để áp dụng bộ validator kiểm tra dữ liệu đầu vào
        .as(validRequest -> customerService.updateCustomer(id, validRequest)) // Cập nhật khách hàng nếu dữ liệu hợp lệ, dua vào id và dữ liệu đã được kiểm tra
        .switchIfEmpty(ApplicationException.customerNotFound(id)); // Nếu không tìm thấy khách hàng để cập nhật, trả về lỗi CustomerNotFoundException
  }
}

```
> Lưu ý: Sử dụng `transform()` để áp dụng validator tùy chỉnh trên `Mono<CustomerDto>`, giúp kiểm tra dữ liệu đầu vào trước khi chuyển tiếp đến dịch vụ để xử lý.
> Sử dụng `switchIfEmpty()` để xử lý trường hợp không tìm thấy khách hàng, trả về lỗi tùy chỉnh nếu cần thiết.
> Sử dụng `as()` để chuyển đổi `Mono<CustomerDto>` đã được kiểm tra thành `Mono
> Thay thế `ResponseEntity` bằng việc trả về trực tiếp `Mono<T>` hoặc `Flux<T>` từ controller kết hợp với việc sử dụng exception handling để quản lý lỗi và trạng thái HTTP.

## 5. Sử dụng `@ControllerAdvice` để tùy chỉnh xử lý lỗi toàn cục
Tạo lớp `ApplicationExceptionHandler` với annotation `@ControllerAdvice` để xử lý lỗi toàn cục trong ứng dụng WebFlux:
```java
package com.didan.reactive.learn.validation.advice;

import com.didan.reactive.learn.validation.exception.CustomerNotFoundException;
import com.didan.reactive.learn.validation.exception.InvalidInputException;
import java.net.URI;
import org.springframework.http.HttpStatus;
import org.springframework.http.ProblemDetail;
import org.springframework.web.bind.annotation.ControllerAdvice;
import org.springframework.web.bind.annotation.ExceptionHandler;

@ControllerAdvice
public class ApplicationExceptionHandler {

  @ExceptionHandler(CustomerNotFoundException.class)
  public ProblemDetail handleException(CustomerNotFoundException ex) {
    var problem = ProblemDetail.forStatusAndDetail(HttpStatus.NOT_FOUND, ex.getMessage());
    problem.setType(URI.create("htpp://example.com/problem/customer-not-found"));
    problem.setTitle("Customer Not Found");
    return problem;
  }

  @ExceptionHandler(InvalidInputException.class)
  public ProblemDetail handleException(InvalidInputException ex) {
    var problem = ProblemDetail.forStatusAndDetail(HttpStatus.BAD_REQUEST, ex.getMessage());
    problem.setType(URI.create("htpp://example.com/problem/invalid-input"));
    problem.setTitle("Invalid Input");
    return problem;
  }
}
```
> Lưu ý: Sử dụng `@ControllerAdvice` để tạo một lớp xử lý lỗi toàn cục, giúp quản lý các ngoại lệ phát sinh trong toàn bộ ứng dụng WebFlux.
> Sử dụng `@ExceptionHandler` để định nghĩa các phương thức xử lý lỗi cho từng loại ngoại lệ cụ thể, trả về đối tượng `ProblemDetail` để cung cấp thông tin chi tiết về lỗi cho client.
> Sử dụng `ProblemDetail` để chuẩn hóa phản hồi lỗi theo định dạng RFC 7807, giúp client dễ dàng hiểu và xử lý lỗi. `ProblemDetail` cung cấp các thông tin như mã trạng thái HTTP, chi tiết lỗi, loại lỗi và tiêu đề lỗi.

# Web Filter trong Spring WebFlux
## 1. Giới thiệu
Web Filter trong Spring WebFlux là một thành phần quan trọng giúp bạn can thiệp vào quá trình xử lý yêu cầu và phản hồi trong ứng dụng WebFlux. Chúng cho phép bạn thực hiện các tác vụ như xác thực, ghi log, xử lý lỗi, và nhiều hơn nữa trước khi yêu cầu được chuyển đến controller hoặc sau khi phản hồi được tạo ra. `Web Filter` trong Spring WebFlux tương tự như `Servlet Filter` trong Spring MVC, nhưng được thiết kế để hoạt động trong môi trường phản ứng (reactive).

## 2. Cách hoạt động của Web Filter
Trong luồng xử lý yêu cầu trong Spring WebFlux, các Web Filter được áp dụng trước khi yêu cầu đến `controller` và sau khi phản hồi được tạo ra. Điều này cho phép bạn can thiệp vào cả hai giai đoạn của quá trình xử lý yêu cầu.

`Web Filter` hoạt động theo chuỗi (chain), nghĩa là bạn có thể xếp chồng nhiều filter lại với nhau. Mỗi filter có thể quyết định có tiếp tục chuyển yêu cầu đến filter tiếp theo trong chuỗi hay không thông qua việc gọi phương thức `chain.filter(exchange)`. Bạn cũng có thể thực hiện các thao tác trước hoặc sau khi yêu cầu được xử lý bởi filter tiếp theo trong chuỗi. Điều này cho phép bạn thực hiện các tác vụ như ghi log, xác thực, hoặc xử lý lỗi một cách linh hoạt, hoặc có thể dừng quá trình xử lý và trả về phản hồi ngay lập tức.

Các chuỗi filter này được quản lý bởi `WebFilterChain`, cho phép bạn kiểm soát luồng xử lý yêu cầu và phản hồi trong ứng dụng WebFlux của mình một cách hiệu quả. Để sắp xếp các filter trong chuỗi, bạn có thể sử dụng annotation `@Order` để xác định thứ tự ưu tiên của từng filter. Filter có giá trị `order` thấp hơn sẽ được áp dụng trước các filter có giá trị `order` cao hơn.

> Lưu ý: Trong Spring WebFlux, `WebFilter` không thể đọc được body của request hoặc response nhiều lần do tính chất bất đồng bộ và luồng dữ liệu phản ứng. Khi body được đọc một lần, nó sẽ không còn sẵn sàng để đọc lại trong các filter hoặc handler tiếp theo trong chuỗi xử lý. Để giải quyết vấn đề này, bạn có thể sử dụng các kỹ thuật như caching hoặc buffering body nếu cần thiết, nhưng điều này có thể làm tăng độ phức tạp và ảnh hưởng đến hiệu suất của ứng dụng.
## 3. Tạo Web Filter
```java

public enum Category {
  STANDARD,
  PRIME;
}

package com.didan.reactive.learn.webfilter.filter;

import java.util.Map;
import java.util.Objects;
import org.springframework.core.annotation.Order;
import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Component;
import org.springframework.web.server.ServerWebExchange;
import org.springframework.web.server.WebFilter;
import org.springframework.web.server.WebFilterChain;
import reactor.core.publisher.Mono;

@Order(1) // Filter sẽ qua bộ lọc này đầu tiên
@Component
public class AuthenticationWebFilter implements WebFilter {

  private static final Map<String, Category> TOKEN_CATEGGORY_MAP = Map.of(
      "secret123", Category.STANDARD,
      "secret456", Category.PRIME
  ); // Vi dụ về ánh xạ token để phân loại người dùng

  @Override
  public Mono<Void> filter(ServerWebExchange exchange, WebFilterChain chain) {
    var token = exchange.getRequest().getHeaders().getFirst("auth-token"); // Lấy token từ header của yêu cầu

    if (Objects.nonNull(token) && TOKEN_CATEGGORY_MAP.containsKey(token)) {
      exchange.getAttributes().put("category", TOKEN_CATEGGORY_MAP.get(token)); // Lưu category vào attributes của exchange để sử dụng trong các chuỗi lọc tiếp theo
      return chain.filter(exchange); // Nếu token hợp lệ, tiếp tục chuỗi lọc
    }
    return Mono.fromRunnable(() -> exchange.getResponse().setStatusCode(HttpStatus.UNAUTHORIZED)); // Nếu token không hợp lệ, trả về lỗi 401 Unauthorized. Sử dụng Mono.fromRunnable để đảm bảo rằng việc thiết lập mã trạng thái được thực hiện khi Mono được đăng ký
  }
}

package com.didan.reactive.learn.webfilter.filter;

import org.springframework.core.annotation.Order;
import org.springframework.http.HttpMethod;
import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Component;
import org.springframework.web.server.ServerWebExchange;
import org.springframework.web.server.WebFilter;
import org.springframework.web.server.WebFilterChain;
import reactor.core.publisher.Mono;

@Order(2) // Filter sẽ qua bộ lọc này đầu tiên
@Component
public class AuthorizationWebFilter implements WebFilter {

  @Override
  public Mono<Void> filter(ServerWebExchange exchange, WebFilterChain chain) {
    var category = exchange.getAttributeOrDefault("category", Category.STANDARD); // Lấy category từ attributes của exchange, nếu không có thì mặc định là STANDARD
    return switch (category) {
      case PRIME -> prime(exchange, chain); // Nếu là người dùng PRIME, gọi phương thức prime
      case STANDARD -> standard(exchange, chain); // Nếu là người dùng STANDARD, gọi phương thức standard
    };
  }

  private Mono<Void> prime(ServerWebExchange exchange, WebFilterChain chain) {
    return chain.filter(exchange); // Cho phép truy cập nếu là người dùng PRIME
  }

  private Mono<Void> standard(ServerWebExchange exchange, WebFilterChain chain) {
    var isGet = HttpMethod.GET.equals(exchange.getRequest().getMethod()); // Kiểm tra xem phương thức yêu cầu có phải là GET không
    if (isGet) {
      return chain.filter(exchange); // Cho phép truy cập nếu là phương thức GET
    }
    return Mono.fromRunnable(() -> exchange.getResponse().setStatusCode(HttpStatus.FORBIDDEN)); // Nếu không phải GET, trả về lỗi 403 Forbidden
  }
}
```

> Như vậy, chúng ta đã tạo hai `Web Filter` trong Spring WebFlux: `AuthenticationWebFilter` để xác thực người dùng dựa trên token và `AuthorizationWebFilter` để phân quyền truy cập dựa trên loại người dùng (STANDARD hoặc PRIME). Các filter này được sắp xếp theo thứ tự ưu tiên sử dụng annotation `@Order`, giúp kiểm soát luồng xử lý yêu cầu một cách hiệu quả.

## 4. Đọc attributes trong Controller
Để đọc các attributes đã được thiết lập trong `Web Filter` ví dụ về cách đọc attribute "category" đã được thiết lập trong `AuthenticationWebFilter` và `AuthorizationWebFilter` bằng 2 cách trong controller:
- Sử dụng `ServerWebExchange`:
```java
@GetMapping("category")
public Mono<String> getCategory(ServerWebExchange exchange) {
  var category = exchange.getAttribute("category"); // Lấy category từ attributes của exchange
  return Mono.justOrEmpty(category) // Trả về Mono chứa category nếu không null
      .map(Object::toString) // Chuyển đổi category thành chuỗi
      .defaultIfEmpty("Unknown"); // Nếu category là null, trả về "Unknown"
}
```
- Sử dụng `@RequestAttribute`:
```java
@GetMapping("category")
public Mono<String> getCategory(@RequestAttribute("category") Category category) {
  return Mono.justOrEmpty(category) // Trả về Mono chứa category nếu không null
      .map(Object::toString) // Chuyển đổi category thành chuỗi
      .defaultIfEmpty("Unknown"); // Nếu category là null, trả về "Unknown"
}
```

## 5. Tùy chỉnh response trả về từ Web Filter
Trong `Web Filter`, bạn có thể tùy chỉnh phản hồi trả về cho client khi yêu cầu không hợp lệ hoặc không được phép truy cập. Dưới đây là ví dụ về cách tùy chỉnh phản hồi trong `AuthenticationWebFilter` và `AuthorizationWebFilter`, sử dụng `ProblemDetail` hoặc class tự tạo để cung cấp thông tin chi tiết về lỗi:
```java
package com.didan.reactive.learn.webfilter.filter;

import jakarta.annotation.PostConstruct;
import java.util.List;
import lombok.RequiredArgsConstructor;
import org.springframework.http.HttpStatus;
import org.springframework.http.ProblemDetail;
import org.springframework.http.codec.HttpMessageWriter;
import org.springframework.http.codec.ServerCodecConfigurer;
import org.springframework.stereotype.Component;
import org.springframework.web.reactive.function.server.ServerResponse;
import org.springframework.web.reactive.result.view.ViewResolver;
import org.springframework.web.server.ServerWebExchange;
import reactor.core.publisher.Mono;

@Component
@RequiredArgsConstructor
public class FilterErrorHandler {

  private final ServerCodecConfigurer codecConfigurer; // Cấu hình codec để xử lý mã hóa và giải mã dữ liệu
  private ServerResponse.Context context; // Ngữ cảnh để xử lý phản hồi máy chủ

  @PostConstruct
  private void init() {
    this.context = new ContextImpl(codecConfigurer); // Khởi tạo ngữ cảnh với cấu hình codec ngay sau khi bean được tạo
  }

  // Class nội bộ để triển khai ServerResponse.Context
  private record ContextImpl(ServerCodecConfigurer codecConfigurer) implements ServerResponse.Context {

    // Ghi đè phương thức để trả về danh sách các bộ ghi thông điệp HTTP
    @Override
    public List<HttpMessageWriter<?>> messageWriters() {
      return this.codecConfigurer.getWriters(); // Trả về danh sách các bộ ghi thông điệp HTTP từ cấu hình codec
    }

    // Ghi đè phương thức để trả về danh sách các bộ phân giải view
    @Override
    public List<ViewResolver> viewResolvers() {
      return List.of();
    }
  }

  /**
   * Gửi phản hồi chi tiết về vấn đề qua class Problem Detail với mã trạng thái HTTP và thông điệp cụ thể
   *
   * @param exchange
   * @param httpStatus
   * @param message
   * @return
   */
  public Mono<Void> sendProblemDetail(ServerWebExchange exchange, HttpStatus httpStatus, String message) {
    var problem = ProblemDetail.forStatusAndDetail(httpStatus, message); // Tạo đối tượng ProblemDetail với mã trạng thái và thông điệp chi tiết
    return ServerResponse
        .status(httpStatus) // Thiết lập mã trạng thái cho phản hồi
        .bodyValue(problem) // Đặt đối tượng ProblemDetail làm nội dung phản hồi
        .flatMap(sr -> sr.writeTo(exchange, this.context)); // Ghi phản hồi vào exchange sử dụng ngữ cảnh đã tạo
  }
}
```

> Lưu ý: Sử dụng `ProblemDetail` để chuẩn hóa phản hồi lỗi theo định dạng RFC 7807, giúp client dễ dàng hiểu và xử lý lỗi. `ProblemDetail` cung cấp các thông tin như mã trạng thái HTTP, chi tiết lỗi, loại lỗi và tiêu đề lỗi.
> Sử dụng `ServerResponse` để xây dựng phản hồi HTTP một cách linh hoạt trong môi trường phản ứng của Spring WebFlux.
```java
package com.didan.reactive.learn.webfilter.filter;

import java.util.Map;
import java.util.Objects;
import lombok.RequiredArgsConstructor;
import org.springframework.core.annotation.Order;
import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Component;
import org.springframework.web.server.ServerWebExchange;
import org.springframework.web.server.WebFilter;
import org.springframework.web.server.WebFilterChain;
import reactor.core.publisher.Mono;

@Order(1) // Filter sẽ qua bộ lọc này đầu tiên
@Component
@RequiredArgsConstructor
public class AuthenticationWebFilter implements WebFilter {

  private final FilterErrorHandler errorHandler; // Sử dụng FilterErrorHandler để xử lý lỗi trong filter
  private static final Map<String, Category> TOKEN_CATEGGORY_MAP = Map.of(
      "secret123", Category.STANDARD,
      "secret456", Category.PRIME
  ); // Vi dụ về ánh xạ token để phân loại người dùng

  @Override
  public Mono<Void> filter(ServerWebExchange exchange, WebFilterChain chain) {
    var token = exchange.getRequest().getHeaders().getFirst("auth-token"); // Lấy token từ header của yêu cầu

    if (Objects.nonNull(token) && TOKEN_CATEGGORY_MAP.containsKey(token)) {
      exchange.getAttributes().put("category", TOKEN_CATEGGORY_MAP.get(token)); // Lưu category vào attributes của exchange để sử dụng trong các chuỗi lọc tiếp theo
      return chain.filter(exchange); // Nếu token hợp lệ, tiếp tục chuỗi lọc
    }
//    return Mono.fromRunnable(() -> exchange.getResponse().setStatusCode(HttpStatus.UNAUTHORIZED)); // Nếu token không hợp lệ, trả về lỗi 401 Unauthorized. Sử dụng Mono.fromRunnable để đảm bảo rằng việc thiết lập mã trạng thái được thực hiện khi Mono được đăng ký
    return errorHandler.sendProblemDetail(exchange, HttpStatus.UNAUTHORIZED, "Invalid or missing auth-token"); // Sử dụng FilterErrorHandler để trả về lỗi chi tiết
  }
}
```
> Lưu ý: Sử dụng `FilterErrorHandler` trong `Web Filter` để tùy chỉnh phản hồi lỗi, giúp cung cấp thông tin chi tiết về lỗi cho client một cách nhất quán và dễ hiểu.

# Router Function trong Spring WebFlux
## 1. Giới thiệu
Router Function trong Spring WebFlux là một cách tiếp cận khác để định nghĩa các endpoint và xử lý yêu cầu HTTP trong ứng dụng WebFlux. Thay vì sử dụng annotation như trong controller truyền thống, Router Function cho phép bạn định nghĩa các tuyến đường (routes) và ánh xạ chúng với các hàm xử lý (handler functions) một cách linh hoạt và rõ ràng hơn. Điều này giúp tách biệt logic định tuyến khỏi logic xử lý, làm cho mã nguồn dễ đọc và bảo trì hơn.

Luồng hoạt động của Router Function bao gồm hai thành phần chính:
- Router: Định nghĩa các tuyến đường (routes) và ánh xạ chúng với các hàm xử lý tương ứng.
- Handler: Chứa các hàm xử lý (handler functions) để xử lý các yêu cầu HTTP và trả về phản hồi.

> Giống với cách hoạt động của `Node.js` với `Express.js`, nơi bạn định nghĩa các route và xử lý chúng thông qua các hàm callback.

## 2. Cách hoạt động của Router Function
Router Function hoạt động dựa trên việc định nghĩa các tuyến đường (routes) sử dụng các phương thức như `GET`, `POST`, `PUT`, `DELETE`, v.v., và ánh xạ chúng với các hàm xử lý (handler functions) tương ứng. Mỗi hàm xử lý nhận vào một đối tượng `ServerRequest` và trả về một đối tượng `Mono<ServerResponse>`, cho phép bạn xây dựng phản hồi HTTP một cách linh hoạt.

## 3. Tạo Router Function
```java
package com.didan.reactive.learn.router.config;

import com.didan.reactive.learn.validation.exception.CustomerNotFoundException;
import com.didan.reactive.learn.validation.exception.InvalidInputException;
import lombok.RequiredArgsConstructor;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.web.reactive.function.server.RouterFunction;
import org.springframework.web.reactive.function.server.RouterFunctions;
import org.springframework.web.reactive.function.server.ServerResponse;

@Configuration
@RequiredArgsConstructor
public class RouterConfiguration {

  private final RouterRequestHandler routerRequestHandler;
  private final ApplicationExceptionHandler globalExceptionHandler;

  /**
   * Bean tạo các route cho ứng dụng (thay cho lớp controller truyền thống)
   *
   * @return
   */
  @Bean
  RouterFunction<ServerResponse> createRouters() {
    return RouterFunctions.route()
        .GET("/customers", routerRequestHandler::getAllCustomers) // Định nghĩa route GET /customers và busniess xử lý yêu cầu
        .GET("/customers/paginated", routerRequestHandler::pagniatedCustomers) // Định nghĩa route GET /customers/paginated và busniess xử lý yêu cầu
        .GET("/customers/{id}", routerRequestHandler::getCustomerById) // Định nghĩa route GET /customers/{id} và busniess xử lý yêu cầu
        .POST("/customers", routerRequestHandler::createCustomer) // Định nghĩa route POST /customers và busniess xử lý yêu cầu
        .PUT("/customers/{id}", routerRequestHandler::updateCustomer) // Định nghĩa route PUT /customers/{id} và busniess xử lý yêu cầu
        .DELETE("/customers/{id}", routerRequestHandler::deleteCustomer) // Định nghĩa route DELETE /customers/{id} và busniess xử lý yêu cầu
        .onError(CustomerNotFoundException.class, globalExceptionHandler::handleException) // Xử lý khi bắt được lỗi CustomerNotFoundException, (exception.class, serverRequest, serverResponse) -> {}
        .onError(InvalidInputException.class, globalExceptionHandler::handleException) // Xử lý khi bắt được lỗi InvalidInputException, (exception.class, serverRequest, serverResponse) -> {}
        .build();
  }

  /**
   * Lưu ý: Nên lưu ý việc sắp xếp thứ tự các route, nên để các route cụ thể (có tham số (parameter) ở dưới cùng để tránh ghi đè các route có path kế thừa).
   * Ví dụ: /customers/{id} nên để dưới cùng sau /customers và /customers/paginated
   * * Nếu không, khi truy cập /customers/paginated sẽ bị hiểu nhầm là truy cập /customers/{id} với id = "paginated"
   */
}
```
> Lưu ý: Sử dụng `RouterFunctions.route()` để định nghĩa các tuyến đường và ánh xạ chúng với các hàm xử lý một cách rõ ràng và linh hoạt.
> - Sử dụng `onError()` để xử lý các ngoại lệ cụ thể và cung cấp phản hồi lỗi một cách nhất quán trong toàn bộ ứng dụng.
>  - Sắp xếp các tuyến đường một cách hợp lý để tránh ghi đè và đảm bảo rằng các yêu cầu được xử lý đúng cách. Nên lưu ý việc sắp xếp thứ tự các route, nên để các router cụ thể (có tham số)(parameter) ở dưới trên cùng để tránh bị ghi đè các route chung prefix path. Ví dụ: /customers nên để dưới cùng sau /customers/paginated và /customers/{id}. Nếu không, khi truy cập /customers/paginated sẽ bị hiểu nhầm là truy cập /customers/{id} với id = "paginated"

> Handler functions trong Router Function luôn trả về `Mono<ServerResponse>`, cho phép bạn xây dựng phản hồi HTTP một cách linh hoạt trong môi trường phản ứng của Spring WebFlux.
```java
package com.didan.reactive.learn.router.config;

import com.didan.reactive.learn.router.dto.CustomerDto;
import com.didan.reactive.learn.router.service.CustomerService;
import com.didan.reactive.learn.router.validator.RequestValidator;
import com.didan.reactive.learn.validation.exception.ApplicationException;
import java.util.List;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Component;
import org.springframework.web.reactive.function.server.ServerRequest;
import org.springframework.web.reactive.function.server.ServerResponse;
import reactor.core.publisher.Flux;
import reactor.core.publisher.Mono;

@Component
@RequiredArgsConstructor
public class RouterRequestHandler {

  private final CustomerService customerService;

  /**
   * Các handler xử lý request này luôn trả về Mono<ServerResponse> ServerRequest có thể lấy thông tin từ request như path variable, query param, body, header, ...
   *
   * @param request
   * @return
   */
  public Mono<ServerResponse> getAllCustomers(ServerRequest request) {
    Flux<CustomerDto> customerDtoFlux = customerService.getAllCustomers(); // Lấy tất cả khách hàng từ service
    return customerDtoFlux.as(flux -> ServerResponse.ok().body(flux, CustomerDto.class)); // Trả về phản hồi với danh sách khách hàng
  }

  public Mono<ServerResponse> pagniatedCustomers(ServerRequest request) {
    var page = request
        .queryParam("page") // Lấy tham số truy vấn "page"
        .map(Integer::parseInt) // Chuyển đổi giá trị chuỗi sang Integer do queryParam luôn trả về Optional<String>
        .orElse(1); // Mặc định là trang 1 nếu không có tham số
    var size = request
        .queryParam("size") // Lấy tham số truy vấn "size"
        .map(Integer::parseInt) // Chuyển đổi giá trị chuỗi sang Integer do queryParam luôn trả về Optional<String>
        .orElse(3); // Mặc định là kích thước 3 nếu không có tham số
    Mono<List<CustomerDto>> listMono = customerService.getAllCustomers(page, size); // Lấy danh sách khách hàng phân trang từ service
    return listMono.flatMap(mono -> ServerResponse.ok().bodyValue(mono)); // Trả về phản hồi với danh sách khách hàng, dùng flatMap để tránh lồng Mono (dữ liệu đã là Mono<List<CustomerDto>> -> flatMap sẽ lấy ra List<CustomerDto>)
  }

  public Mono<ServerResponse> getCustomerById(ServerRequest request) {
    var id = Integer.parseInt(request.pathVariable("id")); // Lấy path variable "id" và chuyển đổi sang Integer, do pathVariable luôn trả về String
    Mono<CustomerDto> customerDtoMono = customerService.getCustomerById(id) // Lấy khách hàng theo ID từ service
        .switchIfEmpty(ApplicationException.customerNotFound(id)); // Nếu không tìm thấy khách hàng, trả về lỗi CustomerNotFoundException
    return customerDtoMono.flatMap(customerDto -> ServerResponse.ok().bodyValue(customerDto)); // Trả về phản hồi với khách hàng, dùng flatMap để tránh lồng Mono (dữ liệu đã là Mono<CustomerDto> -> flatMap sẽ lấy ra CustomerDto)
  }

  public Mono<ServerResponse> createCustomer(ServerRequest request) {
    Mono<CustomerDto> customerDtoMono = request.bodyToMono(CustomerDto.class); // Lấy body từ request và chuyển đổi sang Mono<CustomerDto>
    Mono<CustomerDto> validCustomerDtoMono = customerDtoMono.transform(RequestValidator.validate()); // Áp dụng bộ validator để kiểm tra dữ liệu đầu vào
    Mono<CustomerDto> savedCustomerDtoMono = validCustomerDtoMono.as(customerService::saveCustomer); // Lưu khách hàng nếu dữ liệu hợp lệ
    return savedCustomerDtoMono.flatMap(savedCustomerDto -> ServerResponse.ok().bodyValue(savedCustomerDto)); // Trả về phản hồi với khách hàng đã lưu, dùng flatMap để tránh lồng Mono
  }

  public Mono<ServerResponse> updateCustomer(ServerRequest request) {
    var id = Integer.parseInt(request.pathVariable("id"));
    Mono<CustomerDto> customerDtoMono = request.bodyToMono(CustomerDto.class); // Lấy body từ request và chuyển đổi sang Mono<CustomerDto>
    Mono<CustomerDto> validCustomerDtoMono = customerDtoMono.transform(RequestValidator.validate()); // Áp dụng bộ validator để kiểm tra dữ liệu đầu vào
    Mono<CustomerDto> updatedCustomer = validCustomerDtoMono
        .as(validRequest -> customerService.updateCustomer(id, validRequest)) // Cập nhật khách hàng nếu dữ liệu hợp lệ, dua vào id và dữ liệu đã được kiểm tra
        .switchIfEmpty(ApplicationException.customerNotFound(id)); // Nếu không tìm thấy khách hàng để cập nhật, trả về lỗi CustomerNotFoundException
    return updatedCustomer.flatMap(updatedDto -> ServerResponse.ok().bodyValue(updatedDto)); // Trả về phản hồi với khách hàng đã cập nhật, dùng flatMap để tránh lồng Mono
  }

  public Mono<ServerResponse> deleteCustomer(ServerRequest request) {
    var id = Integer.parseInt(request.pathVariable("id"));
    Mono<Boolean> deleteResult = customerService.deleteCustomer(id) // Xóa khách hàng theo id
        .filter(b -> b) // Lọc kết quả trả về, chỉ tiếp tục nếu khách hàng đã được xóa (b == true)
        .switchIfEmpty(ApplicationException.customerNotFound(id)); // Nếu không tìm thấy khách hàng để xóa, trả về lỗi CustomerNotFoundException
    return deleteResult.then(ServerResponse.ok().build()); // Trả về phản hồi rỗng với mã trạng thái OK
  }
}
```
> Lưu ý: Sử dụng `ServerRequest` để truy cập thông tin từ yêu cầu HTTP, bao gồm path variables, query parameters, headers và body.
> - Sử dụng `ServerResponse` để xây dựng phản hồi HTTP một cách linh hoạt trong môi trường phản ứng của Spring WebFlux.

> Handle Exception toàn cục khi sử dụng Router Function

```java
package com.didan.reactive.learn.router.config;

import com.didan.reactive.learn.validation.exception.CustomerNotFoundException;
import com.didan.reactive.learn.validation.exception.InvalidInputException;
import java.net.URI;

/**
 * Class xử lý ngoại lệ toàn cục cho ứng dụng (không sử dụng @ControllerAdvice vì không dùng controller truyền thống)
 */
@Component
public class ApplicationExceptionHandler {

  /**
   * Xử lý ngoại lệ CustomerNotFoundException và trả về ServerResponse với ProblemDetail khi sử dụng RouterFunction thay cho controller truyền thống
   * @param ex
   * @param request
   * @return
   */
  public Mono<ServerResponse> handleException(CustomerNotFoundException ex, ServerRequest request) {

    var problem = ProblemDetail.forStatusAndDetail(status, ex.getMessage());
    problem.setType(URI.create("htpp://example.com/problem/customer-not-found"));
    problem.setTitle("Customer Not Found");
    problem.setInstance(URI.create(request.path()));
    return ServerResponse.status(status).bodyValue(problem);
  }

  /**
   * Xử lý ngoại lệ InvalidInputException và trả về ServerResponse với ProblemDetail khi sử dụng RouterFunction thay cho controller truyền thống
   * @param ex
   * @param serverRequest
   * @return
   */
  public Mono<ServerResponse> handleException(InvalidInputException ex, ServerRequest serverRequest) {
    var status = HttpStatus.BAD_REQUEST;
    var problem = ProblemDetail.forStatusAndDetail(status, ex.getMessage());
    problem.setType(URI.create("htpp://example.com/problem/invalid-input"));
    problem.setTitle("Invalid Input");
    problem.setType(URI.create(serverRequest.path()));
    return ServerResponse.status(status).bodyValue(problem);
  }
```

```java
package com.didan.reactive.learn.validation.validator;

import com.didan.reactive.learn.validation.exception.InvalidInputException;
import org.springframework.stereotype.Component;

@Component
public class CustomerValidator {

  public Mono<Void> validateCustomerDto(CustomerDto customerDto) {

      return Mono.error(new InvalidInputException("Name must not be empty"));
    }
    if (customerDto.getEmail() == null || customerDto.getEmail().isEmpty()) {

}
```

Khác với `controller` truyền thống sử dụng annotation `@ControllerAdvice` để xử lý lỗi toàn cục, khi sử dụng `Router Function`, bạn cần tạo một class Bean như `ApplicationExceptionHandler` để xử lý các ngoại lệ và trả về phản hồi lỗi một cách nhất quán trong toàn bộ ứng dụng.

## 4. Thông tin thêm về Router
### 4.1. Multiple Router Functions
Bạn có thể tạo nhiều `Router Function` trong ứng dụng của mình để tổ chức các tuyến đường theo các module hoặc tính năng khác nhau. Mỗi `Router Function` có thể được định nghĩa trong các lớp cấu hình riêng biệt và sau đó được kết hợp lại trong một `RouterFunction` tổng thể.

```java
@Configuration
public class UserRouterConfig {
    @Bean
    public RouterFunction<ServerResponse> userRoutes(UserHandler userHandler) {
        return RouterFunctions.route()
            .GET("/users", userHandler::getAllUsers)
            .POST("/users", userHandler::createUser)
            .build();
    }
}

@Configuration
public class ProductRouterConfig {
    @Bean
    public RouterFunction<ServerResponse> productRoutes(ProductHandler productHandler) {
        return RouterFunctions.route()
            .GET("/products", productHandler::getAllProducts)
            .POST("/products", productHandler::createProduct)
            .build();
    }
}
```

### 4.2. Nesting Routes
Bạn có thể tổ chức các tuyến đường của mình theo cách lồng nhau (nesting) để tạo cấu trúc rõ ràng hơn cho các endpoint liên quan. Điều này giúp giảm sự trùng lặp trong định nghĩa đường dẫn và làm cho mã nguồn dễ đọc hơn.
```java
  @Bean
  RouterFunction<ServerResponse> createRouters() {
    return RouterFunctions.route()
        .path("customers", this::createRouters2) // Nhóm các route liên quan đến /customers
        .PUT("/customers/{id}", routerRequestHandler::updateCustomer) // Định nghĩa route PUT /customers/{id} và busniess xử lý yêu cầu
        .DELETE("/customers/{id}", routerRequestHandler::deleteCustomer) // Định nghĩa route DELETE /customers/{id} và busniess xử lý yêu cầu
        .onError(CustomerNotFoundException.class, globalExceptionHandler::handleException) // Xử lý khi bắt được lỗi CustomerNotFoundException, (exception.class, serverRequest, serverResponse) -> {}
        .onError(InvalidInputException.class, globalExceptionHandler::handleException) // Xử lý khi bắt được lỗi InvalidInputException, (exception.class, serverRequest, serverResponse) -> {}
        .build();
  }
  
  RouterFunction<ServerResponse> createRouters2() {
    return RouterFunctions.route()
        .GET("/paginated", routerRequestHandler::pagniatedCustomers) // Định nghĩa route GET /customers/paginated và busniess xử lý yêu cầu
        .GET("/{id}", routerRequestHandler::getCustomerById) // Định nghĩa route GET /customers/{id} và busniess xử lý yêu cầu
        .GET(routerRequestHandler::getAllCustomers) // Định nghĩa route GET /customers và busniess xử lý yêu cầu
        .onError(CustomerNotFoundException.class, globalExceptionHandler::handleException) // Xử lý khi bắt được lỗi CustomerNotFoundException, (exception.class, serverRequest, serverResponse) -> {}
        .build();
  }
```
> Lưu ý: 
> - Sử dụng `path()` để nhóm các tuyến đường liên quan lại với nhau, giúp tổ chức mã nguồn một cách rõ ràng và dễ quản lý hơn.
> - Annotation `@Bean` chỉ cần khai báo một lần cho `Router Function` chính, không cần khai báo lại trong các hàm lồng nhau.

### 4.3. WebFilter với Router Function
Bạn có thể sử dụng `WebFilter` cùng với `Router Function` để thực hiện các tác vụ như xác thực, phân quyền, ghi log, và xử lý lỗi trước khi yêu cầu gi đến các hàm xử lý trong `Router Function`. Điều này giúp bạn tách biệt các logic liên quan đến xử lý yêu cầu khỏi logic định tuyến và xử lý trong các hàm handler.

`WebFilter` có thể nhiều chuỗi nối tiếp nhau theo thứ tự.

```java
  @Bean
  RouterFunction<ServerResponse> createRouters() {
    return RouterFunctions.route()
        .path("/customers", this::createRouters2) // Nhóm các route liên quan đến /customers
        .PUT("/customers/{id}", routerRequestHandler::updateCustomer) // Định nghĩa route PUT /customers/{id} và busniess xử lý yêu cầu
        .DELETE("/customers/{id}", routerRequestHandler::deleteCustomer) // Định nghĩa route DELETE /customers/{id} và busniess xử lý yêu cầu
        .onError(CustomerNotFoundException.class, globalExceptionHandler::handleException) // Xử lý khi bắt được lỗi CustomerNotFoundException, (exception.class, serverRequest, serverResponse) -> {}
        .onError(InvalidInputException.class, globalExceptionHandler::handleException) // Xử lý khi bắt được lỗi InvalidInputException, (exception.class, serverRequest, serverResponse) -> {}
        .filter((req, next) -> {
          log.info("Request: {} {}", req.method(), req.uri()); // Log thông tin method và path của request
          log.info("Headers: {}", req.headers().asHttpHeaders()); // Log thông tin header của request
          log.info("Query Params: {}", req.queryParams()); // Log thông tin query param của request
          log.info("Path Variables: {}", req.pathVariables()); // Log thông tin path variable của request

          if (true) { // Ví dụ về việc chặn request (có thể thêm điều kiện tùy ý)
            return next.handle(req); // Tiếp tục xử lý request
          }
          return ServerResponse.status(403).build(); // Chặn request và trả về 403 Forbidden
        })
        .filter((req, next) -> {
          log.info("Filter 2 - Before processing request");
          return next.handle(req);
        })
        .build();
  }
```

### 4.4. RequestPredicate
Khi định nghĩa các tuyến đường trong `Router Function`, bạn có thể sử dụng `RequestPredicate` để tạo các điều kiện phức tạp hơn cho việc ánh xạ yêu cầu đến các hàm xử lý. `RequestPredicate` cho phép bạn kết hợp nhiều điều kiện như phương thức HTTP, đường dẫn, header, query parameters, và nhiều hơn nữa.

> VD:
```java
@Bean
  RouterFunction<ServerResponse> createRouters() {
  return RouterFunctions.route()
      .GET("/predicate/{number}", RequestPredicates.path("*/1?"), req -> ServerResponse.ok()
          .bodyValue(true)) // Ví dụ về việc sử dụng RequestPredicates để định nghĩa route với điều kiện pathVariable của path có prefix là `1x` (x là 1 ký tự bất kỳ) (VD: 10, 11, 12, ..., 19)
      .build();
  }
```

Ngoài ra, bạn có thể sử dụng các phương thức tĩnh trong `RequestPredicates` để tạo các điều kiện phổ biến như:
- `RequestPredicates.method(HttpMethod method)`: Kiểm tra phương thức HTTP của yêu cầu.
- `RequestPredicates.path(String patternPath)`: Kiểm tra đường dẫn của yêu cầu (Pattern có thể bao gồm ký tự đại diện như `*` và `?`). VD: `*/1?` kiểm tra các đường dẫn kết thúc bằng `/10`, `/11`, ..., `/19`.
- `RequestPredicates.headers(Predicate<Headers>)`: Kiểm tra giá trị của một header cụ thể trong yêu cầu. VD: `RequestPredicates.headers(headers -> headers.getFirst("auth-token") != null)` kiểm tra sự tồn tại của header `auth-token`.
- `RequestPredicates.queryParam(String paramName, Predicate<String> predicate)`: Kiểm tra giá trị của một tham số truy vấn cụ thể trong yêu cầu. VD: `RequestPredicates.queryParam("page", value -> Integer.parseInt(value) > 0)` kiểm tra tham số truy vấn `page` có giá trị lớn hơn 0.
- `RequestPredicates.contentType(MediaType mediaType)`: Kiểm tra loại nội dung (Content-Type) của yêu cầu.
- `RequestPredicates.accept(MediaType... mediaTypes)`: Kiểm tra các loại nội dung mà client chấp nhận (Accept header).
- `RequestPredicates.and(RequestPredicate other)`: Kết hợp hai điều kiện với toán tử AND.
- `RequestPredicates.or(RequestPredicate other)`: Kết hợp hai điều kiện với toán tử OR.
- `RequestPredicates.negate()`: Phủ định điều kiện hiện tại.
- `RequestPredicates.pathExtension(String extension)`: Kiểm tra phần mở rộng của đường dẫn yêu cầu.
