# Reactive Spring Boot
## 1. Giới thiệu về Reactive Programming
Reactive Programming là một mô hình lập trình tập trung vào việc xử lý dữ liệu và sự kiện bất đồng bộ, cho phép xây dựng các ứng dụng có khả năng mở rộng cao và phản hồi nhanh. Trong bối cảnh của Spring Boot, Reactive Programming được hỗ trợ thông qua Spring WebFlux, một module cung cấp các công cụ để xây dựng các ứng dụng web phản ứng.

## 2. Lợi ích của Reactive Spring Boot
- **Hiệu suất cao**: Reactive Spring Boot sử dụng mô hình lập trình không chặn (non-blocking), giúp tối ưu hóa việc sử dụng tài nguyên hệ thống và cải thiện hiệu suất của ứng dụng.
- **Khả năng mở rộng**: Ứng dụng Reactive có thể dễ dàng mở rộng để xử lý nhiều kết nối đồng thời mà không cần tăng tài nguyên phần cứng.
- **Phản hồi nhanh**: Reactive Spring Boot giúp ứng dụng phản hồi nhanh hơn với người dùng, đặc biệt trong các tình huống tải cao.
- **Dễ dàng tích hợp**: Spring WebFlux có thể dễ dàng tích hợp với các công nghệ khác trong hệ sinh thái Spring, như Spring Data, Spring Security, v.v.
## 3. Các thành phần chính của Reactive Spring Boot
- **Spring WebFlux**: Module chính để xây dựng các ứng dụng web phản ứng, hỗ trợ cả lập trình dựa trên annotation và lập trình chức năng.
- **Project Reactor**: Thư viện lập trình phản ứng được sử dụng trong Spring WebFlux, cung cấp các loại dữ liệu như Mono và Flux để xử lý luồng dữ liệu bất đồng bộ.
- **Reactive Repositories**: Spring Data cung cấp các repository phản ứng để làm việc với cơ sở dữ liệu một cách hiệu quả trong môi trường phản ứng.
## 4. So sánh giữa Spring MVC và Spring WebFlux
| Đặc điểm               | Spring MVC                     | Spring WebFlux                |
|-----------------------|--------------------------------|-------------------------------|
| Mô hình lập trình     | Blocking (chặn)                | Non-blocking (không chặn)     |
| Xử lý kết nối đồng thời | Hạn chế                        | Cao                           |
| Hiệu suất              | Thấp hơn trong tải cao          | Cao hơn trong tải cao          |
| Thư viện sử dụng      | Servlet API                    | Project Reactor                |
| Phù hợp cho            | Ứng dụng truyền thống          | Ứng dụng hiện đại, tải cao      |

### 4.1. Ví dụ so sánh đơn giản giữa Spring MVC và Spring WebFlux
#### Spring MVC
```java
@RestController
public class HelloController {
    @GetMapping("/hello")
    public String hello() {
        return "Hello, World!";
    }
}
```
#### Spring WebFlux
```java
@RestController
public class HelloController {
    @GetMapping("/hello")
    public Mono<String> hello() {
        return Mono.just("Hello, World!");
    }
}
```
> Khi call API `/hello`, Spring MVC sẽ chặn luồng cho đến khi trả về kết quả, trong khi Spring WebFlux sẽ trả về một `Mono` ngay lập tức và xử lý kết quả bất đồng bộ.

Ví dụ khác, khi sử dụng `ChatGPT` yêu cầu trả lời, nếu sử dụng mô hình blocking, hệ thống sẽ phải chờ đợi cho đến khi nhận được phản hồi từ ChatGPT trước khi tiếp tục xử lý các yêu cầu khác. Trong khi đó, với mô hình non-blocking, hệ thống có thể trả về một phản hồi tạm thời (như "Đang xử lý yêu cầu của bạn...") hoặc trả lời từng phần khi nhận được dữ liệu từ ChatGPT, cho phép hệ thống tiếp tục xử lý các yêu cầu khác trong khi chờ đợi phản hồi hoàn chỉnh. Để làm như vậy, ta sử dụng kỹ thuật như sau:
```java
@RestController
public class HelloController {
      private final WebClient webClient = WebClient.create(); // Sử dụng WebClient (non-blocking)
    @GetMapping(path = "/reply/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<ResponseDto> hello() {
        return webClient.get()
            .uri("https://api.openai.com/v1/chat/completions")
            .retrieve()
            .bodyToFlux(ResponseDto.class)
            .onErrorComplete() // Nếu có lỗi, hoàn thành luồng mà không phát sinh lỗi
            .doOnNext(response -> log.info("Received chunk from ChatGPT API: {}", response));
    }
}
```
> Khi call API `/reply/stream`, hệ thống sẽ trả về một luồng dữ liệu (stream) và có thể gửi các phần dữ liệu từng phần khi chúng sẵn sàng, thay vì chờ đợi toàn bộ phản hồi từ ChatGPT, nhờ sử dụng `Flux` và `MediaType.TEXT_EVENT_STREAM_VALUE`.
> Khi có lỗi trong quá trình gọi API, `onErrorComplete()` sẽ giúp hoàn thành luồng mà không phát sinh lỗi, đảm bảo rằng hệ thống vẫn hoạt động bình thường và có thể tiếp tục xử lý các yêu cầu khác.

Lưu ý rằng, không được nhầm lẫn, hiểu lầm giữa mô hình non-blocking với việc trả về phản hồi ngay lập tức. Mô hình non-blocking cho phép hệ thống tiếp tục xử lý các yêu cầu khác trong khi chờ đợi phản hồi, nhưng không có nghĩa là phản hồi sẽ được trả về ngay lập tức. Phản hồi vẫn sẽ được gửi khi dữ liệu sẵn sàng, nhưng hệ thống không bị chặn trong quá trình chờ đợi đó.
```java
@RestController
public class HelloController {
    private final RestClient restClient = RestClient.builder()
      .requestFactory(new JdkClientHttpRequestFactory())
      .build(); // Sử dụng RestClient truyền thống (blocking)

    @GetMapping("/chatgpt/reply")
    public Flux<ResponseDto> getReply() {
        var list = restClient.get()
            .uri("https://api.openai.com/v1/chat/completions")
            .retrieve()
            .body(new ParameterizedTypeReference<List<ResponseDto>>() {});
        log.info("Request sent to ChatGPT API");
        return Flux.fromIterable(list); 
    }
}
```
> Đây không phải là `Reactive Pipeline`, mặc dù sử dụng `Flux` để trả về dữ liệu, nhưng toàn bộ quá trình gọi API vẫn là blocking do sử dụng `RestClient` trong cách thông thường. Hệ thống sẽ chờ đợi cho đến khi nhận được toàn bộ phản hồi từ ChatGPT trước khi tiếp tục xử lý các yêu cầu khác.

# R2DBC vs Spring Data
## 1. Giới thiệu về R2DBC và Spring Data
R2DBC (Reactive Relational Database Connectivity) là một tiêu chuẩn kết nối cơ sở dữ liệu quan hệ theo mô hình lập trình phản ứng (reactive programming). Nó cho phép các ứng dụng tương tác với cơ sở dữ liệu một cách không chặn (non-blocking) và bất đồng bộ, giúp tối ưu hóa hiệu suất và khả năng mở rộng của ứng dụng.

Spring Data là một dự án trong hệ sinh thái Spring cung cấp các công cụ và thư viện để làm việc với cơ sở dữ liệu một cách dễ dàng và hiệu quả. Spring Data hỗ trợ nhiều loại cơ sở dữ liệu khác nhau, bao gồm cả cơ sở dữ liệu quan hệ và NoSQL.

## 2. So sánh R2DBC và Spring Data
### 2.1. R2DBC
- **Ưu điểm**:
  - Hỗ trợ mô hình lập trình phản ứng, giúp tối ưu hóa hiệu suất và khả năng mở rộng.
  - Cho phép xử lý nhiều kết nối đồng thời mà không cần tăng tài nguyên phần cứng.
  - Thích hợp cho các ứng dụng hiện đại, tải cao và yêu cầu phản hồi nhanh với áp lực ngược (Backpressure).

- **Nhược điểm**:
    - Cần phải sử dụng các thư viện và công cụ hỗ trợ R2DBC, có thể làm tăng độ phức tạp của dự án.
    - Không phải tất cả các cơ sở dữ liệu quan hệ đều hỗ trợ R2DBC.
    - Không có các tính năng phong phú như Spring Data trong việc quản lý dữ liệu và truy vấn như không có các annotation như `@OneToMany`, `@ManyToOne`, v.v.

`R2DBC` có các driver riêng biệt cho từng cơ sở dữ liệu, ví dụ như:
- `r2dbc-postgresql` cho PostgreSQL
- `r2dbc-mysql` cho MySQL
- `r2dbc-mssql` cho Microsoft SQL Server
- `r2dbc-h2` cho H2 Database
- `r2dbc-mariadb` cho MariaDB
- `oracle-r2dbc` cho Oracle Database
- `jasync-r2dbc`
- `cloud-spanner-r2dbc` cho Google Cloud Spanner
- `clickhouse-r2dbc` cho ClickHouse

Ví dụ `connection string` kết nối đến cơ sở dữ liệu H2 sử dụng R2DBC:
```application.properties
# Cấu hình r2dbc đên thư mục chứa file sql khởi tạo (nêu cần chạy khi khởi động ứng dụng)
spring.sql.init.data-locations=classpath:sql/data.sql

# Cấu hình kết nối R2DBC đến cơ sở dữ liệu H2 trong bộ nhớ
spring.r2dbc.url=r2dbc:h2:mem:///./testdb;DB_CLOSE_DELAY=-1;DB_CLOSE_ON_EXIT=FALSE
spring.r2dbc.username=sa
spring.r2dbc.password=

# Cấu hình log để hiển thị các câu lệnh SQL được thực thi
logging.level.org.springframework.r2dbc="DEBUG"
```

> Lưu ý, vì không phải Spring WebMVC nên sẽ không thể truy cập vào `/h2-console` được, thay vào đó bạn có thể sử dụng các công cụ bên ngoài như DBeaver, DataGrip, hoặc các công cụ dòng lệnh để kết nối và quản lý cơ sở dữ liệu H2.

*Spring Data R2DBC* là một phần mở rộng của Spring Data, cung cấp các repository phản ứng để làm việc với cơ sở dữ liệu R2DBC một cách dễ dàng và hiệu quả.
```java
public interface UserRepository extends ReactiveCrudRepository<User, Long> {
    Flux<User> findByLastName(String lastName);

    Mono<User> findByEmail(String email);

    @Query("SELECT * FROM users WHERE age > :age")
    Flux<User> findUsersOlderThan(int age);
    
    @Query("UPDATE users SET status = :status WHERE id = $1")
    Mono<Integer> updateUserStatusById(String status, Long id);

    @Modifying // Chỉ định đây là một truy vấn thay đổi dữ liệu
    @Query("DELETE FROM users WHERE last_login < :date")
    Mono<Integer> deleteUsersInactiveSince(LocalDate date);
}
```

Với clas tạo Entity, khác với JPA, Spring Data R2DBC sử dụng các annotation như `@Table`, `@Column`, `@Id`, v.v. để định nghĩa các thực thể và ánh xạ chúng với bảng trong cơ sở dữ liệu, và không hỗ trợ các annotation như `@OneToMany`, `@ManyToOne`, cũng như các tùy chọn cascade và fetch type.
```java
@Table("users")
public class User {
    @Id
    private Long id;

    @Column("first_name")
    private String firstName;

    @Column("last_name")
    private String lastName;

    @Column("email")
    private String email;

    // Getters and Setters
}
```

### 2.2. Database Client
Database Client là một thành phần trong Spring Data R2DBC, cung cấp một API cấp cao để tương tác với cơ sở dữ liệu R2DBC một cách linh hoạt và dễ dàng. Nó cho phép bạn thực hiện các truy vấn SQL, cập nhật dữ liệu và quản lý giao dịch một cách phản ứng.
Ví dụ sử dụng Database Client để thực hiện một truy vấn đơn giản:
```java
import org.springframework.r2dbc.core.DatabaseClient;
import reactor.core.publisher.Flux;
import reactor.core.publisher.Mono;
import org.springframework.stereotype.Repository;
@Repository
public class UserRepositoryCustom {

    private final DatabaseClient databaseClient;

    public UserRepositoryCustom(DatabaseClient databaseClient) {
        this.databaseClient = databaseClient;
    }

    public Flux<User> findUsersByLastName(String lastName) {
        return databaseClient.sql("SELECT * FROM users WHERE last_name = :lastName")
                .bind("lastName", lastName) // Đặt giá trị cho tham số :lastName 
                .map((row, metadata) -> { // Ánh xạ kết quả truy vấn thành đối tượng User
                    User user = new User(); // Tạo một đối tượng User mới
                    user.setId(row.get("id", Long.class)); // Lấy giá trị cột "id" và gán cho thuộc tính id của User
                    user.setFirstName(row.get("first_name", String.class)); // Lấy giá trị cột "first_name" và gán cho thuộc tính firstName của User
                    user.setLastName(row.get("last_name", String.class)); // Lấy giá trị cột "last_name" và gán cho thuộc tính lastName của User
                    user.setEmail(row.get("email", String.class)); // Lấy giá trị cột "email" và gán cho thuộc tính email của User
                    return user; // Trả về đối tượng User đã được ánh xạ
                })
                .all(); // Trả về tất cả các kết quả dưới dạng Flux<User>
    }

    public Mono<Integer> updateUserEmail(Long id, String newEmail) {
        return databaseClient.sql("UPDATE users SET email = :email WHERE id = :id")
                .bind("email", newEmail)
                .bind("id", id)
                .fetch() // Lấy đối tượng FetchSpec để thực hiện truy vấn
                .rowsUpdated(); // Trả về số lượng hàng bị ảnh hưởng dưới dạng Mono<Integer>
    }
}
```

## 3. Sử dụng Pageable với R2DBC
Spring Data R2DBC hỗ trợ phân trang (pagination) thông qua việc sử dụng `Pageable` trong các phương thức repository. Điều này cho phép bạn dễ dàng truy xuất dữ liệu theo từng trang, giúp tối ưu hóa hiệu suất khi làm việc với tập dữ liệu lớn.
Ví dụ về cách sử dụng `Pageable` trong một repository R2DBC:
```java
import org.springframework.data.domain.Page;
import org.springframework.data.domain.Pageable;
import org.springframework.data.r2dbc.repository.Query;
import org.springframework.data.repository.reactive.ReactiveCrudRepository;
import reactor.core.publisher.Mono;
public interface UserRepository extends ReactiveCrudRepository<User, Long> {

    @Query("SELECT * FROM users")
    Flux<User> findAllBy(Pageable pageable); // Nên sử dụng Flux thay vì Mono<Page> vì Flux sẽ phù hợp trả về các luồng dữ liệu hơn
}
```
Nên sử dụng `Flux<User>` thay vì `Mono<Page<User>>` vì `Flux` sẽ phù hợp trả về các luồng dữ liệu hơn trong môi trường phản ứng (reactive). Khi sử dụng `Flux`, bạn có thể dễ dàng xử lý từng phần tử trong luồng dữ liệu một cách linh hoạt và hiệu quả hơn khi làm việc với R2DBC. Sau đó, ở tầng `Service` hoặc `Controller`, bạn có convert về `Mono<Page<User>>` nếu cần thiết.
```java
import org.springframework.data.domain.Page;
import org.springframework.data.domain.PageImpl;
import org.springframework.data.domain.Pageable;
import reactor.core.publisher.Flux;
import reactor.core.publisher.Mono;
public Mono<Page<User>> getUsers(Pageable pageable) {
    return userRepository.findAllBy(pageable)
            .collectList() // Thu thập tất cả người dùng vào một danh sách (Mono<List<User>>)
            .zipWith(userRepository.count()) // Kết hợp với Mono<Long> đếm tổng số người dùng
            .map(tuple -> new PageImpl<>(tuple.getT1(), pageable, tuple.getT2())); // Tạo Page<User> từ danh sách người dùng
}
```

## 4. Sử dụng `StepVerifier` để kiểm thử R2DBC
Khi làm việc với R2DBC và các luồng dữ liệu phản ứng, việc kiểm thử các luồng này là rất quan trọng để đảm bảo rằng chúng hoạt động đúng như mong đợi. `StepVerifier` là một công cụ mạnh mẽ trong thư viện Reactor Test, giúp bạn kiểm thử các luồng dữ liệu phản ứng một cách dễ dàng và hiệu quả.
Dưới đây là một ví dụ về cách sử dụng `StepVerifier` để kiểm thử một phương thức trong repository sử dụng R2DBC:
```java
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;  
import org.springframework.boot.test.autoconfigure.data.r2dbc.DataR2dbcTest;
import reactor.core.publisher.Flux;
import reactor.test.StepVerifier;

@DataR2dbcTest
public class UserRepositoryTest {

    @Autowired
    private UserRepository userRepository;

    @Test
    public void testFindByLastName() {
        Flux<User> users = userRepository.findByLastName("Doe");

        StepVerifier.create(users)
                .expectNextMatches(user -> user.getLastName().equals("Doe"))
                .verifyComplete();
    }
}
```
Trong ví dụ trên, chúng ta đã tạo một lớp kiểm thử `UserRepositoryTest` sử dụng annotation `@DataR2dbcTest` để cấu hình môi trường kiểm thử cho R2DBC. Chúng ta đã kiểm thử phương thức `findByLastName` trong `UserRepository` bằng cách sử dụng `StepVerifier`. Chúng ta tạo một `Flux<User>` từ phương thức và sử dụng `StepVerifier` để xác nhận rằng luồng dữ liệu trả về đúng như mong đợi, với ít nhất một người dùng có họ là "Doe" và kết thúc luồng một cách hoàn chỉnh.

Ngoài ra `SepVerifier` còn cung cấp nhiều phương thức khác để kiểm thử các luồng dữ liệu phản ứng, như:
- `create()`: Tạo một `StepVerifier` từ một `Publisher`.
- `expectNext()`: Kiểm tra các phần tử tiếp theo trong luồng.
- `expectNextMatches()`: Kiểm tra phần tử tiếp theo dựa trên một điều kiện.
- `expectNextCount()`: Kiểm tra số lượng phần tử tiếp theo.
- `thenConsumeWhile()`: Tiêu thụ các phần tử trong luồng cho đến khi điều kiện không còn đúng.
- `assertNext()`: Kiểm tra phần tử tiếp theo với một hàm kiểm tra tùy chỉnh.
- `expectComplete()`: Kiểm tra rằng luồng đã hoàn thành.
- `expectError()`: Kiểm tra rằng luồng đã kết thúc với một lỗi cụ thể.
- `verify()`: Kích hoạt quá trình kiểm thử và xác nhận các kỳ vọng đã được thiết lập.

```java
var flux = Flux.just(1, 2, 3, 4, 5); // Tạo một Flux với các số từ 1 đến 5 
StepVerifier.create(flux) // Tạo StepVerifier từ Flux
    .expectNext(1) // Kiểm tra phần tử tiếp theo là 1
    .expectNextCount(4) // Kiểm tra có thêm 4 phần tử tiếp theo (2, 3, 4, 5)
    .expectComplete() // Kiểm tra rằng luồng đã hoàn thành
    .verify(); // Kích hoạt quá trình kiểm thử
```

> Khi sử dụng `Flux` hoặc `Mono` trong Spring, thường có hàm `doOnNext()` để thực hiện một hành động phụ khi một phần tử được phát ra. Chúng ta có thể tận dụng nó để có thể xử lý dữ liệu được phát ra ngay mà không cần phải chờ đến khi hoàn thành toàn bộ luồng dữ liệu. Ví dụ:
```java
// Spring MVC
User user = userRepository.findById(id);
user.setName("New Name");
userRepository.save(user);

// Spring WebFlux
userRepository.findById(id)
    .doOnNext(user -> {
        user.setName("New Name");
        userRepository.save(user).subscribe(); // Lưu thay đổi ngay lập tức, subscribe để kích hoạt luồng dữ liệu
    })
    .subscribe();
```

> sử dụng `flatMap()` để thực hiện các thao tác bất đồng bộ trên từng phần tử trong luồng dữ liệu thay cho `map()`, vì `map()` chỉ biến đổi dữ liệu mà không hỗ trợ các thao tác bất đồng bộ.
> Sử dụng `concatMap()` khi bạn muốn duy trì thứ tự của các phần tử trong luồng dữ liệu, trong khi `flatMap()` có thể không đảm bảo thứ tự.
```java
userRepository.findByName("Dan")
    .doOnNext(user -> {
        user.setName("New Name");
    })
    .flatMap(user -> userRepository.save(user)) // Sử dụng flatMap để lưu thay đổi bất đồng bộ
    .subscribe();
```

> Có thể sử dụng `Spring Data JPA` trong các ứng dụng `Spring WebFlux`, tuy nhiên cần lưu ý rằng `Spring Data JPA` hoạt động theo mô hình lập trình đồng bộ (blocking), khi sử dụng trong môi trường phản ứng (reactive) như `Spring WebFlux`, cần phải đảm bảo rằng các thao tác truy cập cơ sở dữ liệu không chặn luồng chính của ứng dụng. Điều này có thể được thực hiện bằng cách sử dụng các kỹ thuật như `Schedulers` để chuyển đổi các thao tác đồng bộ sang các luồng riêng biệt, tránh làm tắc nghẽn luồng chính.
```java
import reactor.core.scheduler.Schedulers;

Mono.fromSupplier(() -> userJpaRepository.findById(id))
    .subscribeOn(Schedulers.boundedElastic()) // Chuyển đổi thao tác đồng bộ sang luồng riêng biệt (rất quan trọng)
    .map(user -> {
        user.setName("New Name");
        return userJpaRepository.save(user);
    })
    .doOnNext(savedUser -> {
        // Xử lý sau khi lưu thành công
    });
```

# CRUD trong Web Flux sử dụng R2DBC
## 1. Giới thiệu
Trong phần này, chúng ta sẽ xây dựng một ứng dụng CRUD (Create, Read, Update, Delete) đơn giản sử dụng Spring WebFlux và R2DBC để tương tác với cơ sở dữ liệu phản ứng. Chúng ta sẽ tạo một API RESTful để quản lý các thực thể "User".

## 2. Cấu hình dự án
Trước tiên, hãy tạo một dự án Spring Boot mới với các phụ thuộc sau trong `build.gradle` hoặc `pom.xml`:
- Spring WebFlux
- Spring Data R2DBC
- R2DBC Driver cho cơ sở dữ liệu bạn đang sử dụng (ví dụ: H2, PostgreSQL, MySQL, v.v.)
- Lombok (tùy chọn, để giảm boilerplate code)
## 3. Cấu hình kết nối R2DBC
Trong `application.properties` hoặc `application.yml`, cấu hình kết nối R2DBC đến cơ sở dữ liệu của bạn. Ví dụ, với H2:
```properties   
spring.r2dbc.url=r2dbc:h2:mem:///testdb;DB_CLOSE_DELAY=-1;DB_CLOSE_ON_EXIT=FALSE
spring.r2dbc.username=sa
spring.r2dbc.password=
spring.sql.init.platform=h2
spring.sql.init.mode=always
```
## 4. Tạo thực thể Customer
Tạo một lớp thực thể `Customer` để đại diện cho bảng khách hàng trong cơ sở dữ liệu:
```java
import org.springframework.data.annotation.Id;
import org.springframework.data.relational.core.mapping.Table;
import lombok.Data;
import lombok.NoArgsConstructor;
import lombok.AllArgsConstructor;
import lombok.Builder;
@Data
@NoArgsConstructor
@AllArgsConstructor
@Builder
@Table("customers") // Trong r2dbc, sử dụng @Table để chỉ định tên bảng
public class Customer { 
    @Id
    private Long id;
    private String name;
    private String email;
}
```

## 5. Tạo Repository
Tạo một interface `CustomerRepository` mở rộng từ `ReactiveCrudRepository` để cung cấp các phương thức CRUD:
```java
import org.springframework.data.repository.reactive.ReactiveCrudRepository;
import reactor.core.publisher.Mono;
public interface CustomerRepository extends ReactiveCrudRepository<Customer, Long> {
    Mono<Customer> findByName(String name);
}
```
## 6. Tạo Service
Tạo một lớp dịch vụ `CustomerService` để xử lý logic nghiệp vụ:
```java
package com.didan.reactive.learn.crud.service;

import com.didan.reactive.learn.crud.dto.CustomerDto;
import com.didan.reactive.learn.crud.mapper.EntityDtoMapper;
import com.didan.reactive.learn.crud.repository.CustomerRepository;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;
import reactor.core.publisher.Flux;
import reactor.core.publisher.Mono;

@Service
@RequiredArgsConstructor
public class CustomerService {

  private final CustomerRepository customerRepository;

  public Flux<CustomerDto> getAllCustomers() {
    return this.customerRepository.findAll() // Lấy tất cả khách hàng từ repository
        .map(EntityDtoMapper::toDto); // Chuyển đổi từng Customer entity thành CustomerDto
  }

  public Mono<CustomerDto> getCustomerById(Integer id) {
    return this.customerRepository.findById(id) // Tìm khách hàng theo ID
        .map(EntityDtoMapper::toDto); // Chuyển đổi Customer entity thành CustomerDto
  }

  public Mono<CustomerDto> saveCustomer(Mono<CustomerDto> customerDtoMono) { // Truyền vào Mono<CustomerDto>
    return customerDtoMono.map(EntityDtoMapper::toEntity) // Chuyển đổi CustomerDto thành Customer entity
        .flatMap(this.customerRepository::save) // Sau khi lưu có kiểu Mono<Customer> nên phải dùng flatMap để tránh lồng Mono
        .map(EntityDtoMapper::toDto);
  }

  public Mono<CustomerDto> updateCustomer(Integer id, Mono<CustomerDto> customerDtoMono) {
    return this.customerRepository.findById(id) // Tìm khách hàng theo ID
        .flatMap(entity -> customerDtoMono) // Lấy dữ liệu mới từ client (Mono<CustomerDto>) dùng flatMap để tránh lồng Mono (biến đổi Mono sang Entity)
        .map(EntityDtoMapper::toEntity) // Chuyển đổi CustomerDto thành Customer entity
        .doOnNext(c -> c.setId(id)) // Đảm bảo ID không bị thay đổi
        .flatMap(customerRepository::save) // Lưu khách hàng đã được cập nhật (Mono<Customer>) dùng flatMap để tránh lồng Mono, vì save trả về Mono<Customer> biến đổi sang DTO
        .map(EntityDtoMapper::toDto); // Chuyển đổi Customer entity thành CustomerDto
  }

  public Mono<Void> deleteCustomer(Integer id) {
    return this.customerRepository.deleteById(id); // Xoá khách hàng theo ID
  }
}
```
> Lưu ý: Sử dụng `flatMap()` để thực hiện các thao tác bất đồng bộ trên từng phần tử trong luồng dữ liệu thay cho `map()`, vì `map()` chỉ biến đổi dữ liệu mà không hỗ trợ các thao tác bất đồng bộ. Ngoài ra, khi thực hiện các thao tác với r2dbc, các phương thức như `save()`, `findById()`, và `deleteById()` đều trả về các kiểu `Mono` hoặc `Flux`, do đó việc sử dụng `flatMap()` hoặc `concatMap()` là cần thiết để xử lý các luồng dữ liệu phản ứng này convert về đúng kiểu.

## 7. Tạo Controller
Tạo một lớp controller `CustomerController` để xử lý các yêu cầu HTTP:
```java
package com.didan.reactive.learn.crud.controller;

import com.didan.reactive.learn.crud.dto.CustomerDto;
import com.didan.reactive.learn.crud.service.CustomerService;
import lombok.RequiredArgsConstructor;
import org.springframework.web.bind.annotation.DeleteMapping;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.PutMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;
import reactor.core.publisher.Flux;
import reactor.core.publisher.Mono;

@RestController
@RequestMapping("customers")
@RequiredArgsConstructor
public class CustomerController {

  private final CustomerService customerService;

  @GetMapping
  public Flux<CustomerDto> allCustomers() {
    return customerService.getAllCustomers();
  }

  @GetMapping("{id}")
  public Mono<CustomerDto> getCustomerById(@PathVariable Integer id) {
    return customerService.getCustomerById(id);
  }

  @PostMapping
  public Mono<CustomerDto> createCustomer(@RequestBody Mono<CustomerDto> customerDto) {
    return customerService.saveCustomer(customerDto);
  }

  @PutMapping("{id}")
  public Mono<CustomerDto> updateCustomer(@PathVariable Integer id,
      @RequestBody Mono<CustomerDto> customerDto) {
    return customerService.updateCustomer(id, customerDto);
  }

  @DeleteMapping("{id}")
  public Mono<Void> deleteCustomer(@PathVariable Integer id) {
    return customerService.deleteCustomer(id);
  }

}
```
> Sử dụng `@RequestBody Mono<T>` khác với `@RequestBody T` ở chỗ `Mono<T>` cho phép xử lý bất đồng bộ và có thể chứa giá trị null, trong khi `T` yêu cầu giá trị không null và đồng bộ. Điều này rất quan trọng trong các ứng dụng phản ứng như Spring WebFlux, nơi mà việc xử lý dữ liệu bất đồng bộ là cần thiết để tận dụng tối đa hiệu suất và khả năng mở rộng của ứng dụng.

## 8. Sử dụng ResponseEntity để trả về phản hồi HTTP
Trong `WebFlux`, nên lưu ý rằng, với `Flux` sẽ trả về một luồng dữ liệu có thể chứa nhiều phần tử, do đó không thể sử dụng `ResponseEntity` để bao bọc `Flux`. Thay vào đó, bạn có thể trả về `Flux` trực tiếp từ controller. Ví dụ:
```java
@GetMapping
public Flux<CustomerDto> allCustomers() {
  return customerService.getAllCustomers();
}
```
Tuy nhiên, với `Mono`, bạn có thể sử dụng `ResponseEntity` để bao bọc phản hồi HTTP. Ví dụ:
```java
@GetMapping("{id}")
public Mono<ResponseEntity<CustomerDto>> getCustomerById(@PathVariable Integer id) {
  return customerService.getCustomerById(id) // Tìm khách hàng theo ID
      .map(ResponseEntity::ok) // Nếu tìm thấy, trả về ResponseEntity với mã 200 OK
      .defaultIfEmpty(ResponseEntity.notFound().build()); // Nếu không tìm thấy, trả về mã 404 Not Found
}
```

## 9. Testing với WebTestClient
Bạn có thể sử dụng `WebTestClient` để kiểm thử các endpoint của bạn trong môi trường WebFlux. Dưới đây là một ví dụ về cách viết các bài kiểm thử cho `CustomerController`:
```java
package com.didan.reactive.learn.crud;

import com.didan.reactive.learn.crud.dto.CustomerDto;
import java.util.Objects;
import lombok.extern.slf4j.Slf4j;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.web.reactive.AutoConfigureWebTestClient;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.http.MediaType;
import org.springframework.test.web.reactive.server.WebTestClient;

@AutoConfigureWebTestClient
@Slf4j
public class CustomerServiceTest {

  @Autowired
  private WebTestClient client; // Khách hàng WebTestClient để thực hiện các yêu cầu HTTP trong bài kiểm tra

  @Test

        .uri("/customers") // Đặt URI cho yêu cầu

        .expectHeader().contentType(MediaType.APPLICATION_JSON) // Kiểm tra header Content-Type là application/json
        .expectBodyList(CustomerDto.class) // Kỳ vọng phản hồi là một danh sách các đối tượng CustomerDto
        .value(list -> log.info("Customers: {}", list)) // Ghi log danh sách khách hàng nhận được
        .hasSize(10) // Kiểm tra kích thước của danh sách là 10
        .consumeWith(response -> log.info("Response: {}", response.getResponseBody())); // Ghi log phản hồi nhận được
  }

  @Test
  public void paginatedCustomers() {
    this.client.get()
        .uri("/customers/paginated?page=3&size=2") // Gọi API với tham số phân trang page=3 và size=2

        .consumeWith(r -> log.info("{}", new String(Objects.requireNonNull(r.getResponseBody())))) // Ghi log phản hồi nhận được
        .jsonPath("$.length()").isEqualTo(2) // Kiểm tra độ dài mảng phản hồi là 2 vơi `$` đại diện cho json root

  }

  @Test
  public void customerById() {
    this.client.get()
        .uri("/customers/1") // Gọi API để lấy khách hàng có ID là 1
        .exchange() // Thực hiện yêu cầu
        .expectStatus().is2xxSuccessful() // Kiểm tra mã trạng thái HTTP trả về là 2xx

        .consumeWith(r -> log.info("{}", new String(Objects.requireNonNull(r.getResponseBody())))) // Ghi log phản hồi nhận được

  }

  @Test
  public void createAndDeleteCustomer() {
    // create
    var dto = new CustomerDto(null, "marshal", "marshal@gmail.com"); // Tạo đối tượng CustomerDto mới để gửi trong yêu cầu tạo khách hàng

        .expectBody() // Kỳ vọng phản hồi

        .uri("/customers/11") // Đặt URI cho yêu cầu để xoá khách hàng có ID là 11
        .exchange() // Thực hiện yêu cầu

  @Test

        .bodyValue(dto) // Đặt thân yêu cầu với đối tượng CustomerDto
        .exchange() // Thực hiện yêu cầu
        .expectStatus().is2xxSuccessful() // Kiểm tra mã trạng thái HTTP trả về là 2xx
        .expectBody() // Kỳ vọng phản hồi

  @Test
  public void customerNotFound() {
    // get
    this.client.get()
        .uri("/customers/11")
        .exchange()
        .expectStatus().is4xxClientError()
        .expectBody().isEmpty();

    // delete
    this.client.delete()
        .uri("/customers/11")
        .exchange()
        .expectStatus().is4xxClientError()
        .expectBody().isEmpty();

    // put
    var dto = new CustomerDto(null, "noel", "noel@gmail.com");
    this.client.put()
        .uri("/customers/11")
        .bodyValue(dto)
        .exchange()

        .expectBody().isEmpty();
  }

}
```
> Trong `WebClient` test, sử dụng `jsonPath` để kiểm tra các giá trị cụ thể trong phản hồi JSON. Dấu `$` đại diện cho gốc của tài liệu JSON, và bạn có thể sử dụng các biểu thức `jsonPath` để truy cập và kiểm tra các trường cụ thể trong đối tượng JSON trả về.
> Với các method có yêu cầu requet body như POST và PUT, có thể sử dụng 2 phương thức:
> - `bodyValue(Object body)`: Phương thức này được sử dụng khi bạn có một đối tượng cụ thể mà bạn muốn gửi trong thân yêu cầu. Đối tượng này sẽ được tự động chuyển đổi thành định dạng JSON (hoặc định dạng khác tùy thuộc vào cấu hình của bạn) trước khi gửi đi.
> - `body(Mono<? extends T> body, Class<T> elementClass)`: Phương thức này được sử dụng khi bạn có một `Mono` (hoặc `Flux`) chứa đối tượng mà bạn muốn gửi trong thân yêu cầu. Điều này hữu ích trong các tình huống phản ứng, nơi dữ liệu có thể không có sẵn ngay lập tức và bạn muốn gửi nó khi nó trở nên có sẵn.
