# Thread trong Java
## 1. Giới thiệu về Thread trong Java
Thread (luồng) trong Java là một đơn vị thực thi nhỏ nhất của một chương trình. Mỗi chương trình Java có thể chứa nhiều thread, và mỗi thread có thể thực hiện các tác vụ riêng biệt đồng thời với các thread khác. Điều này giúp tận dụng tối đa tài nguyên hệ thống và cải thiện hiệu suất của ứng dụng.

### 1.1. Tại sao sử dụng Thread?
- **Đa nhiệm (Multitasking)**: Cho phép thực hiện nhiều tác vụ cùng một lúc.
- **Cải thiện hiệu suất**: Tận dụng tốt hơn tài nguyên CPU và giảm thời gian chờ.
- **Giao diện người dùng mượt mà**: Giúp giao diện người dùng không bị đóng băng khi thực hiện các tác vụ nặng.
- **Xử lý song song**: Thực hiện các tác vụ độc lập cùng lúc.
### 1.2. Các trạng thái của Thread
Một thread trong Java có thể ở trong một trong các trạng thái sau:
- **New**: Thread mới được tạo nhưng chưa bắt đầu.
- **Runnable**: Thread đang sẵn sàng để chạy.
- **Blocked**: Thread bị chặn và không thể tiếp tục thực thi.
- **Waiting**: Thread đang chờ một sự kiện hoặc tín hiệu.
- **Timed Waiting**: Thread đang chờ trong một khoảng thời gian xác định.
- **Terminated**: Thread đã hoàn thành công việc và kết thúc.
## 2. Tạo và quản lý Thread trong Java
### 2.1. Cách tạo Thread
#### 2.1.1 Sử dụng lớp Thread và giao diện Runnable
Có hai cách chính để tạo một thread trong Java:
- **Kế thừa lớp Thread**: Tạo một lớp con của lớp Thread và ghi đè phương thức run().
```java
class MyThread extends Thread {
    public void run() {
        System.out.println("Thread is running");
    }
}
public class Main {
    public static void main(String[] args) {
        MyThread thread = new MyThread();
        thread.start(); // Bắt đầu thread
    }
}
```
- **Cài đặt giao diện Runnable**: Tạo một lớp triển khai giao diện Runnable và định nghĩa phương thức run().
```java
class MyRunnable implements Runnable {
    public void run() {
        System.out.println("Thread is running");
    }
}
public class Main {
    public static void main(String[] args) {
        Thread thread = new Thread(new MyRunnable());
        thread.start(); // Bắt đầu thread
    }
}
```
#### 2.1.2 Sử dụng Lambda Expression (Java 8 trở lên)
```java
public class Task {

    private static final Logger log = LoggerFactory.getLogger(Task.class);

    public static void ioIntensive(int i){

        try {
            log.info("starting I/O task {}. Thread Info: {}", i, Thread.currentThread());
            Thread.sleep(Duration.ofSeconds(10));
            log.info("ending I/O task {}. Thread Info: {}", i, Thread.currentThread());
        } catch (InterruptedException e) {
            throw new RuntimeException(e);
        }

    }

}
```
> Sử dụng Lambda Expression để tạo thread một cách ngắn gọn.
```java
private static final int MAX_PLATFORM = 10_000;
public static void main(String[] args) {

    for (int i = 0; i < MAX_PLATFORM; i++) {
        final int taskId = i;
        Thread thread = new Thread(() -> Task.ioIntensive(taskId));
        thread.start();
    }

}
```
> Sử dụng Thread.Builder (Java 19 trở lên) để tạo thread với các tùy chọn cấu hình.
```java
public static void main(String[] args) {
    var builder = Thread.ofPlatform().name("task-", 1); // Tạo builder với tên tiền tố "task-" và số thứ tự bắt đầu từ 1
    for (int i = 0; i < MAX_PLATFORM; i++) {
        final int taskId = i;
        Thread thread = builder.unstarted(() -> Task.ioIntensive(taskId)); // Tạo thread chưa khởi động với công việc I/O
        thread.start(); // Bắt đầu thread
    }

}
```

### 2.2. Quản lý Thread
Java cung cấp nhiều phương thức để quản lý thread, bao gồm:
- **start()**: Bắt đầu thực thi thread.
- **sleep(long millis)**: Tạm dừng thread trong một khoảng thời gian xác định.
- **join()**: Chờ một thread hoàn thành trước khi tiếp tục.
- **interrupt()**: Gửi tín hiệu ngắt đến một thread.
## 3. Đồng bộ hóa Thread trong Java
Khi nhiều thread truy cập cùng một tài nguyên chung, có thể xảy ra tình trạng tranh chấp dữ liệu. Để tránh điều này, Java cung cấp cơ chế đồng bộ hóa (synchronization).
### 3.1. Từ khóa synchronized
Từ khóa synchronized được sử dụng để đảm bảo rằng chỉ một thread có thể truy cập vào một phương thức hoặc khối mã tại một thời điểm.
```java
class Counter {
    private int count = 0;

    public synchronized void increment() {
        count++;
    }

    public int getCount() {
        return count;
    }
}
```
### 3.2. Khối synchronized
Bạn cũng có thể sử dụng khối synchronized để đồng bộ hóa một phần cụ thể của mã.
```java
public void increment() {
    synchronized(this) {
        count++;
    }
}
```
### 3.3. Sử dụng Lock
Java cung cấp lớp Lock trong gói java.util.concurrent.locks để cung cấp cơ chế đồng bộ hóa linh hoạt hơn.
```java
import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReentrantLock;
class Counter {
    private int count = 0;
    private final Lock lock = new ReentrantLock();

    public void increment() {
        lock.lock();
        try {
            count++;
        } finally {
            lock.unlock();
        }
    }

    public int getCount() {
        return count;
    }
}
```
## 4. CoundownLatch và CyclicBarrier
Java cung cấp các công cụ trong gói java.util.concurrent để quản lý sự đồng bộ giữa các thread, bao gồm CountDownLatch và CyclicBarrier.
### 4.1. CountDownLatch
CountDownLatch cho phép một hoặc nhiều thread chờ cho đến khi một số lượng thread khác hoàn thành công việc của chúng.
```java
import java.util.concurrent.CountDownLatch;
class Main {
    public static void main(String[] args) throws InterruptedException {
        CountDownLatch latch = new CountDownLatch(3); // Chờ 3 thread hoàn thành

        Runnable task = () -> {
            System.out.println("Task started");
            try { 
                Thread.sleep(1000); // Simulate work
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
            System.out.println("Task completed");
            latch.countDown(); // Giảm số đếm của latch khi hoàn thành 1 task
        };

        new Thread(task).start();
        new Thread(task).start();
        new Thread(task).start();

        latch.await(); // Đợi cho đến khi tất cả các thread hoàn thành
        System.out.println("All tasks completed");
    }
}
```

### 4.2. CyclicBarrier
CyclicBarrier cho phép một nhóm thread chờ nhau tại một điểm cụ thể trước khi tiếp tục thực thi.
```java
import java.util.concurrent.BrokenBarrierException;
import java.util.concurrent.CyclicBarrier;
class Main {
    public static void main(String[] args) {
        CyclicBarrier barrier = new CyclicBarrier(3, () -> {
            System.out.println("All parties have arrived at the barrier, let's proceed!");
        });

        Runnable task = () -> {
            System.out.println("Task started"); 
            try { 
                Thread.sleep(1000); // Simulate work
                System.out.println("Task waiting at barrier");
                barrier.await(); // Chờ tại barrier
            } catch (InterruptedException | BrokenBarrierException e) {
                e.printStackTrace();
            }
            System.out.println("Task completed");
        };

        new Thread(task).start();
        new Thread(task).start();
        new Thread(task).start();
    }
}
```

# Daemon Thread trong Java
Daemon Thread là một loại thread đặc biệt trong Java, được thiết kế để chạy nền và hỗ trợ các thread khác trong quá trình thực thi của ứng dụng. Khi tất cả các thread không phải daemon (user thread) kết thúc, JVM sẽ tự động kết thúc tất cả các daemon thread và dừng chương trình.

## 1. Đặc điểm của Daemon Thread
- **Chạy nền**: Daemon thread thường được sử dụng để thực hiện các tác vụ nền như thu gom rác (Garbage Collection), giám sát hệ thống, hoặc các dịch vụ hỗ trợ khác.
- **Không ngăn JVM kết thúc**: Khi tất cả các user thread kết thúc, JVM sẽ tự động kết thúc tất cả các daemon thread.
- **Không thể sử dụng để thực hiện các tác vụ quan trọng**: Vì daemon thread có thể bị kết thúc bất cứ lúc nào khi không còn user thread, nên không nên sử dụng chúng để thực hiện các tác vụ quan trọng.
## 2. Tạo Daemon Thread
Kết hợp với `CountDownLatch` để hiển thị cách tạo và sử dụng daemon thread trong Java.
```java
public static void main(String[] args) throws InterruptedException {
    CountDownLatch latch = new CountDownLatch(MAX_PLATFORM); // Tạo CountDownLatch với số đếm ban đầu

    var builder = Thread.ofPlatform().daemon().name("daemon-task-", 1); // Tạo builder cho daemon thread với tên tiền tố "daemon-task-"
    for (int i = 0; i < MAX_PLATFORM; i++) {
        final int taskId = i;
        Thread thread = builder.unstarted(() -> {
            Task.ioIntensive(taskId); // Thực hiện công việc I/O
            latch.countDown(); // Giảm số đếm của latch khi hoàn thành task
        });
        thread.start(); // Bắt đầu daemon thread
    }
    latch.await(); // Đợi cho đến khi tất cả các daemon thread hoàn thành
}
```
Trong ví dụ trên, chúng ta tạo một số lượng lớn daemon thread để thực hiện các tác vụ I/O. Sử dụng `CountDownLatch` để đảm bảo rằng chương trình chính sẽ chờ cho đến khi tất cả các daemon thread hoàn thành công việc của chúng trước khi kết thúc.

# Virtual Thread trong Java
Virtual Thread là một tính năng mới được giới thiệu trong Java 19 như một phần của Project Loom. Virtual Thread cung cấp một cách tiếp cận nhẹ hơn và hiệu quả hơn để xử lý đa luồng so với các thread truyền thống (platform thread). Chúng được thiết kế để hỗ trợ hàng triệu luồng đồng thời mà không gây áp lực lớn lên hệ thống.
## 1. Đặc điểm của Virtual Thread
- **Nhẹ hơn**: Virtual Thread sử dụng ít tài nguyên hệ thống hơn so với platform thread, cho phép tạo và quản lý hàng triệu luồng đồng thời.
- **Quản lý bởi JVM**: Virtual Thread được quản lý bởi JVM thay vì hệ điều hành, giúp giảm thiểu overhead liên quan đến việc chuyển đổi ngữ cảnh (context switching).
- **Tương thích với API hiện có**: Virtual Thread có thể sử dụng cùng các API đồng bộ hóa và các thư viện hiện có mà không cần thay đổi mã nguồn.

## 2. So sánh Virtual Thread và Deamon Thread
| Đặc điểm               | Virtual Thread                          | Daemon Thread                           |
|-----------------------|----------------------------------------|----------------------------------------|
| Mục đích sử dụng      | Xử lý đa luồng nhẹ và hiệu quả         | Chạy nền để hỗ trợ các thread khác     |
| Quản lý                | Bởi JVM                                | Bởi hệ điều hành                       |
| Tài nguyên sử dụng    | Ít tài nguyên hơn, hỗ trợ hàng triệu luồng | Sử dụng tài nguyên hệ thống như platform thread |
| Kết thúc               | Kết thúc khi tất cả các user thread kết thúc | Kết thúc khi tất cả các user thread kết thúc |

> Giả sử, Máy ảo có xCPU (Xử lý tối đa x luồng đồng thời), `xCPU = Runtime.getRuntime().availableProcessors();`
> - Nếu thực hiện `N` tác vụ, mỗi tác vụ có thời gian chờ I/O là `1s`, nếu `N <= xCPU` thì Platform Thread xử lý trong `1s`. `N >> xCPU`, Platform Thread sẽ mất `ceil(N/xCPU)` do mỗi 1 task phải chờ I/O (thực hiện được 1 khoảng thời gian sẽ phải nhường CPU cho task khác, tổng thời gian chờ sẽ là `ceil(N/xCPU) * 1s`).
> - Với Virtual Thread, do nhẹ hơn rất nhiều, có thể tạo `N` Virtual Thread để xử lý `N` tác vụ đồng thời, tổng thời gian sẽ là `1s`, bất kể `N` lớn đến đâu. Bởi vì Virtual Thread không bị giới hạn bởi số lượng CPU, chúng có thể chờ I/O mà không chiếm dụng tài nguyên CPU, mặc định JVM có thể tạo hàng triệu Virtual Thread, nhưng CPU sẽ vẫn chỉ hiểu đang thực hiện 1 task tại 1 thời điểm, trong khi 1 task đó đang có nhiều Virtual Thread.
## 3. Tạo và sử dụng Virtual Thread
Dưới đây là ví dụ về cách tạo và sử dụng Virtual Thread trong Java:
```java
public static void main(String[] args) throws InterruptedException {
    CountDownLatch latch = new CountDownLatch(MAX_VIRTUAL); // Tạo CountDownLatch với số đếm ban đầu

    var builder = Thread.ofVirtual().name("virtual-task-", 1); // Tạo builder cho virtual thread với tên tiền tố "virtual-task-"
    for (int i = 0; i < MAX_VIRTUAL; i++) {
        final int taskId = i;
        Thread thread = builder.unstarted(() -> {
            Task.ioIntensive(taskId); // Thực hiện công việc I/O
            latch.countDown(); // Giảm số đếm của latch khi hoàn thành task
        });
        thread.start(); // Bắt đầu virtual thread
    }
    latch.await(); // Đợi cho đến khi tất cả các virtual thread hoàn thành
}
```
Trong ví dụ trên, chúng ta tạo một số lượng lớn virtual thread để thực hiện các tác vụ I/O. Sử dụng `CountDownLatch` để đảm bảo rằng chương trình chính sẽ chờ cho đến khi tất cả các virtual thread hoàn thành công việc của chúng trước khi kết thúc.

## 4. Khi nào nên sử dụng Virtual Thread
Virtual Thread rất phù hợp cho các ứng dụng cần xử lý nhiều kết nối đồng thời, chẳng hạn như các ứng dụng web, dịch vụ mạng, hoặc các hệ thống xử lý sự kiện. Chúng giúp giảm thiểu overhead và cải thiện hiệu suất mà không cần phải thay đổi nhiều mã nguồn hiện có.

## 5. Vấn đề Pinning Threads
Khi sử dụng Virtual Thread, có thể gặp phải vấn đề "pinning threads" khi một Virtual Thread bị khóa vào một Platform Thread trong thời gian dài, điều này có thể làm giảm hiệu suất của hệ thống. Để tránh vấn đề này, nên sử dụng các API không chặn (non-blocking) và các thư viện hỗ trợ Virtual Thread.
Có thể lấy ví dụ về việc sử dụng từ khóa `synchronized` trong Virtual Thread:
```java
class Counter {
    private int count = 0;

    public synchronized void increment() {
        count++;
    }

    public int getCount() {
        return count;
    }
}

public static void main(String[] args) throws InterruptedException {
    CountDownLatch latch = new CountDownLatch(MAX_VIRTUAL); // Tạo CountDownLatch với số đếm ban đầu

    var builder = Thread.ofVirtual().name("virtual-task-", 1); // Tạo builder cho virtual thread với tên tiền tố "virtual-task-"
    Counter counter = new Counter(); // Tạo một đối tượng Counter để chia sẻ giữa các virtual thread
    for (int i = 0; i < MAX_VIRTUAL; i++) {
        final int taskId = i;
        Thread thread = builder.unstarted(() -> {
            counter.increment(); // Tăng biến đếm trong Counter
            latch.countDown(); // Giảm số đếm của latch khi hoàn thành task
        });
        thread.start(); // Bắt đầu virtual thread
    }
    latch.await(); // Đợi cho đến khi tất cả các virtual thread hoàn thành
    System.out.println("Final count: " + counter.getCount()); // In ra giá trị cuối cùng của biến đếm
}
```
Trong ví dụ trên, nếu một Virtual Thread gọi phương thức `increment()` và bị chặn bởi một Virtual Thread khác đang giữ khóa, thì Virtual Thread đầu tiên sẽ bị "pinned" vào một Platform Thread trong thời gian chờ. Điều này có thể làm giảm hiệu suất của hệ thống nếu có nhiều Virtual Thread bị chặn như vậy.

### 5.1. Giải pháp tránh Pinning Threads
- Sử dụng `Java 25` trở lên, nơi đã cải tiến cơ chế đồng bộ hóa để giảm thiểu vấn đề pinning threads.
- Sử dụng `ReentrantLock` thay vì từ khóa `synchronized` để có kiểm soát tốt hơn về việc quản lý khóa.
```java
import java.util.concurrent.locks.Lock;
import java.util.concurrent.locks.ReentrantLock;
class Counter {
    private int count = 0;
    private final Lock lock = new ReentrantLock(); // Sử dụng ReentrantLock để quản lý đồng bộ hóa 

    public void increment() {
        lock.lock(); // Khóa trước khi tăng biến đếm
        try {
            count++; // Tăng biến đếm
        } finally {
            lock.unlock(); // Mở khóa sau khi hoàn thành
        }
    }

    public int getCount() {
        return count;
    }
}

public static void main(String[] args) throws InterruptedException {
    CountDownLatch latch = new CountDownLatch(MAX_VIRTUAL); // Tạo CountDownLatch với số đếm ban đầu

    var builder = Thread.ofVirtual().name("virtual-task-", 1); // Tạo builder cho virtual thread với tên tiền tố "virtual-task-"
    Counter counter = new Counter(); // Tạo một đối tượng Counter để chia sẻ giữa các virtual thread
    for (int i = 0; i < MAX_VIRTUAL; i++) {
        final int taskId = i;
        Thread thread = builder.unstarted(() -> {
            counter.increment(); // Tăng biến đếm trong Counter
            latch.countDown(); // Giảm số đếm của latch khi hoàn thành task
        });
        thread.start(); // Bắt đầu virtual thread
    }
    latch.await(); // Đợi cho đến khi tất cả các virtual thread hoàn thành
    System.out.println("Final count: " + counter.getCount()); // In ra giá trị cuối cùng của biến đếm
}
```
Trong ví dụ trên, việc sử dụng `ReentrantLock` giúp giảm thiểu nguy cơ pinning threads so với việc sử dụng từ khóa `synchronized`, đặc biệt khi chạy trên Virtual Thread.
## 5.1. ThreadFactory cho Virtual Thread
Khi sử dụng Virtual Thread trong các ứng dụng phức tạp, việc quản lý việc tạo và cấu hình các Virtual Thread có thể trở nên khó khăn. Để giải quyết vấn đề này, Java cung cấp một cách tiếp cận thông qua việc sử dụng `ThreadFactory`.

`ThreadFactory` là một giao diện trong Java cho phép bạn tùy chỉnh cách các thread được tạo ra. Bằng cách sử dụng `ThreadFactory`, bạn có thể kiểm soát các thuộc tính của Virtual Thread như tên, mức độ ưu tiên, và các đặc tính khác một cách dễ dàng hơn. Ngoài ra, việc sử dụng `ThreadFactory` giúp mã nguồn trở nên sạch sẽ và dễ bảo trì hơn, đặc biệt khi bạn cần tạo nhiều Virtual Thread với các cấu hình khác nhau trong cùng một ứng dụng.

Dưới đây là ví dụ về cách sử dụng `ThreadFactory` để tạo Virtual Thread trong Java:
```java
import java.util.concurrent.CountDownLatch;
import java.util.concurrent.ThreadFactory;
public class VirtualThreadFactoryExample {
    private static final int MAX_VIRTUAL = 1000; // Số lượng Virtual Thread cần tạo

    public static void main(String[] args) throws InterruptedException {
        CountDownLatch latch = new CountDownLatch(MAX_VIRTUAL); // Tạo CountDownLatch với số đếm ban đầu

        // Tạo ThreadFactory cho Virtual Thread
        ThreadFactory virtualThreadFactory = Thread.ofVirtual().name("virtual-task-", 1).factory();

        for (int i = 0; i < MAX_VIRTUAL; i++) {
            final int taskId = i;
            // Sử dụng ThreadFactory để tạo Virtual Thread
            Thread thread = virtualThreadFactory.newThread(() -> {
                Task.ioIntensive(taskId); // Thực hiện công việc I/O
                latch.countDown(); // Giảm số đếm của latch khi hoàn thành task
            }); // Khởi tạo Virtual Thread không khởi động
            thread.start(); // Bắt đầu virtual thread
        }
        latch.await(); // Đợi cho đến khi tất cả các virtual thread hoàn thành
    }
}
```

# ExecutorService
ExecutorService là một phần của gói java.util.concurrent trong Java, cung cấp một cách tiếp cận cao cấp để quản lý và thực thi các tác vụ đa luồng. Thay vì tạo và quản lý các thread một cách thủ công, ExecutorService cho phép bạn tập trung vào việc định nghĩa các tác vụ và để nó lo liệu việc quản lý thread pool, lập lịch và thực thi các tác vụ đó.
## 1. Tại sao sử dụng ExecutorService?
- **Quản lý thread pool**: Giúp tái sử dụng các thread và giảm overhead khi tạo mới thread.
- **Lập lịch tác vụ**: Cung cấp các cơ chế để lập lịch và quản lý các tác vụ.
- **Đơn giản hóa mã nguồn**: Giúp mã nguồn trở nên sạch sẽ và dễ bảo trì hơn.
- **Hỗ trợ các mô hình đồng bộ hóa**: Cung cấp các công cụ để xử lý các tác vụ đồng bộ hóa và giao tiếp giữa các thread.
## 2. Các loại ExecutorService
Java cung cấp nhiều loại ExecutorService khác nhau để phục vụ các nhu cầu khác nhau:
- **FixedThreadPool**: Tạo một pool với số lượng thread cố định.\
- **SingleThreadExecutor**: Tạo một pool với một thread duy nhất.
- **CachedThreadPool**: Tạo một pool với số lượng thread linh hoạt, có thể tăng hoặc giảm dựa trên nhu cầu, có thể tái sử dụng các thread đã tạo trước đó trong một khoảng thời gian nhất định. Nếu trong khoảng thời gian đó không có thread nào được sử dụng, các thread không hoạt động sẽ bị loại bỏ khỏi pool.
- **ScheduledThreadPool**: Tạo một pool để lập lịch các tác vụ thực thi định kỳ hoặc sau một khoảng thời gian nhất định.
- **ThreadPerTaskExecutor**: Tạo một thread mới cho mỗi tác vụ được gửi đến executor (từ Java 21 trở lên).
- **VirtualThreadPerTaskExecutor**: Tạo một Virtual Thread mới cho mỗi tác vụ được gửi đến executor (từ Java 21 trở lên).

Khai báo và sử dụng ExecutorService:
> Sử dụng các phương thức tĩnh trong lớp `Executors` để tạo các loại ExecutorService khác nhau, ví dụ:
```java
ExecutorService executor = Executors.newFixedThreadPool(10); // Tạo pool với 10 thread
ExecutorService executor = Executors.newSingleThreadExecutor(); // Tạo pool với 1 thread
ExecutorService executor = Executors.newCachedThreadPool(); // Tạo pool với số lượng thread linh hoạt
ExecutorService executor = Executors.newScheduledThreadPool(5); // Tạo ScheduledThreadPool với 5 thread
ExecutorService executor = Executors.newVirtualThreadPerTaskExecutor(); // Tạo ThreadPerTaskExecutor với Virtual Thread (Java 21 trở lên)
```
> Sử dụng `ThreadFactory` để tùy chỉnh cách tạo các thread trong ExecutorService, ví dụ:
```java
ThreadFactory threadFactory = Thread.ofVirtual().name("virtual-task-", 1).factory();
ExecutorService executor = Executors.newThreadPerTaskExecutor(threadFactory); // Tạo ThreadPerTaskExecutor với Virtual Thread tùy chỉnh (Java 21 trở lên)
```

> Sử dụng các phương thức `submit()` hoặc `execute()` để gửi các tác vụ đến ExecutorService, `submit()` trả về một đối tượng `Future<?>` đại diện cho kết quả của tác vụ, trong khi `execute()` không trả về gì.
> - Với đối tượng `Future<?>`, bạn có thể sử dụng phương thức `get()` để chờ và lấy kết quả của tác vụ khi nó hoàn thành. Ngoài ra còn có các phương thức khác như `get(long timeout, TimeUnit unit)` để chờ với thời gian giới hạn, `isDone()` để kiểm tra xem tác vụ đã hoàn thành hay chưa, và `cancel(boolean mayInterruptIfRunning)` để hủy tác vụ nếu cần thiết.

> Sử dụng `shutdown()` để đóng ExecutorService sau khi hoàn thành các tác vụ, lúc này nó sẽ không chấp nhận thêm tác vụ mới nhưng sẽ hoàn thành các tác vụ đã gửi trước đó.

> Sử dụng `shutdownNow()` để cố gắng dừng tất cả các tác vụ đang chạy và trả về danh sách các tác vụ chưa được thực thi.

> Lưu ý:
> - ExecutorService không tự động quản lý vòng đời của các thread, bạn cần đảm bảo gọi `shutdown()` hoặc `shutdownNow()` khi không còn cần thiết.
> - Có thể sử dụng `awaitTermination()` để chờ cho đến khi tất cả các tác vụ hoàn thành sau khi gọi `shutdown()`.
> - Dùng khối `try` để giúp `executor` tự động đóng khi hoàn thành công việc.

```java
public static void main(String[] args) {
    try (ExecutorService executor = Executors.newSingleThreadExecutor()) { // Tạo pool với 1 thread
        for (int i = 0; i < 10; i++) {
            final int taskId = i;
            executor.submit(() -> {
                System.out.println("Task " + taskId + " is running in " + Thread.currentThread().getName());
            });
        }
    } // ExecutorService sẽ tự động đóng ở đây
}
```
> - Tuy nhiên, trong `Spring Boot`, không nên sử dụng `try-with-resources` để tạo `ExecutorService` vì nó sẽ tự động đóng khi thoát khỏi khối `try`, điều này không phù hợp với vòng đời của ứng dụng Spring Boot. Thay vào đó, nên khai báo `ExecutorService` như một bean trong cấu hình Spring để quản lý vòng đời của nó một cách hiệu quả hơn.
> - Khi sử dụng `Virtual Thread` thì nó sẽ tự động quản lý vòng đời của các thread ảo, do đó không cần phải gọi `shutdown()` hoặc `shutdownNow()`.

```java
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
public class FixedThreadPoolExample {
    public static void main(String[] args) {

        execute(Executors.newSingleThreadExecutor(), 3); // Sử dụng SingleThreadExecutor với 3 tác vụ
        // SingleThreadExecutor đảm bảo rằng các tác vụ được thực thi tuần tự, một tác vụ sẽ hoàn thành trước khi tác vụ tiếp theo bắt đầu.

        execute(Executors.newFixedThreadPool(5), 20); // Sử dụng FixedThreadPool với 5 thread và 20 tác vụ
        // FixedThreadPool với 5 thread sẽ cho phép tối đa 5 tác vụ chạy đồng thời. Nếu có nhiều hơn 5 tác vụ, các tác vụ dư thừa sẽ được xếp hàng chờ cho đến khi một thread trở nên sẵn sàng. 
        // newFixedThreadPool(1) tương đương với SingleThreadExecutor().

        execute(Executors.newCachedThreadPool(), 200); // Sử dụng CachedThreadPool với 200 tác vụ
        // CachedThreadPool sẽ tạo mới các thread khi cần thiết và tái sử dụng các thread đã tạo trước đó nếu chúng đang rảnh.

        execute(Executors.newVirtualThreadPerTaskExecutor(), 10_000); // Sử dụng ThreadPerTaskExecutor với 10000 song song tác vụ (Java 21 trở lên) (điều mà các loại ExecutorService khác không làm được do các executorService khác bị giới hạn bởi số lượng platform thread)

        scheduler(); // Sử dụng ScheduledThreadPool để lập lịch tác vụ định kỳ
        // ScheduledThreadPool cho phép lập lịch các tác vụ để thực thi sau một khoảng thời gian nhất định hoặc định kỳ.
    
    }

    private static void scheduler() {
        try (var executorService = Executors.newSingleThreadScheduledExecutor()) { // Tạo ScheduledThreadPool với 1 thread
            executorService.scheduleAtFixedRate(() -> 
            {
                System.out.println("Scheduled task is running in " + Thread.currentThread().getName()); // Thực thi tác vụ đã lập lịch
            }, 
            0, // Thời gian trễ ban đầu trước khi thực thi tác vụ lần đầu tiên
            5, java.util.concurrent.TimeUnit.SECONDS); // Lập lịch thực thi tá vụ mỗi 5 giây 

            Thread.sleep(5000); // Chạy tác vụ đã lập lịch trong 20 giây
        } // ExecutorService sẽ tự động đóng ở đây, không cần gọi shutdown() vì sử dụng try-with-resources
    }

    private static void excute(ExecutorService executor, int numberOfTasks) {
        try (executor) {
            for (int i = 0; i < numberOfTasks; i++) {
                final int taskId = i;
                executor.submit(() -> {
                    ioIntensive(taskId);
                });
                log.info("Submitted task {}", taskId);
            }
        } // ExecutorService sẽ tự động đóng ở đây không cần gọi shutdown() vì sử dụng try-with-resources
    }

    private static void ioIntensive(int i){
        try {
            System.out.println("starting I/O task " + i + ". Thread Info: " + Thread.currentThread());
            Thread.sleep(10000);
            System.out.println("ending I/O task " + i + ". Thread Info: " + Thread.currentThread());
        } catch (InterruptedException e) {
            throw new RuntimeException(e);
        }
    }
}
```

## 3. Phân biệt Concurency (Đồng thời) và Parallelism (Song song)
- **Concurrency (Đồng thời)**: Là khả năng của hệ thống để xử lý nhiều tác vụ trong cùng một khoảng thời gian. Trong mô hình đồng thời, các tác vụ có thể không thực sự chạy cùng lúc, nhưng hệ thống quản lý chúng sao cho chúng tiến triển một cách hiệu quả. 
> Ví dụ:
> - Một ứng dụng web có thể xử lý nhiều yêu cầu từ người dùng cùng lúc bằng cách sử dụng các thread để quản lý từng yêu cầu.
> - Một người làm việc có thể làm việc trên nhiều dự án cùng một lúc bằng cách chuyển đổi giữa các nhiệm vụ khác nhau, nhưng chỉ làm việc trên một nhiệm vụ tại một thời điểm.

- **Parallelism (Song song)**: Là khả năng của hệ thống để thực hiện nhiều tác vụ cùng một lúc bằng cách sử dụng nhiều đơn vị xử lý (CPU cores). Trong mô hình song song, các tác vụ thực sự chạy đồng thời trên các lõi CPU khác nhau.
> Ví dụ: 
> - Một ứng dụng xử lý hình ảnh có thể chia nhỏ một bức ảnh lớn thành nhiều phần và xử lý từng phần trên các lõi CPU khác nhau cùng một lúc.
> - Một đội ngũ làm việc có thể chia nhỏ một dự án lớn thành các phần nhỏ và giao cho các thành viên khác nhau trong đội để làm việc cùng một lúc.

## 4. Aggregator Service với ExecutorService
Aggregator Service là một mô hình thiết kế trong đó một dịch vụ trung gian thu thập dữ liệu từ nhiều nguồn khác nhau và tổng hợp chúng lại để cung cấp một cái nhìn toàn diện hơn. Trong Java, bạn có thể sử dụng ExecutorService để thực hiện các tác vụ đồng thời nhằm thu thập dữ liệu từ các nguồn khác nhau một cách hiệu quả.
Dưới đây là ví dụ về cách sử dụng ExecutorService để xây dựng một Aggregator Service đơn giản:
```java
import java.util.ArrayList;
import java.util.List;
import java.util.concurrent.Callable;
import java.util.concurrent.ExecutionException;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.Future;
public class AggregatorService {
    public static void main(String[] args) {
        ExecutorService executor = Executors.newSingleThreadExecutor(); // Hoặc sử dụng newFixedThreadPool, newCachedThreadPool, v.v.
        List<Callable<String>> tasks = new ArrayList<>();

        // Thêm các tác vụ thu thập dữ liệu từ các nguồn khác nhau
        tasks.add(() -> fetchDataFromSource("Source 1"));
        tasks.add(() -> fetchDataFromSource("Source 2"));
        tasks.add(() -> fetchDataFromSource("Source 3"));
        tasks.add(() -> fetchDataFromSource("Source 4"));
        tasks.add(() -> fetchDataFromSource("Source 5"));

        try {
            // Gửi tất cả các tác vụ và nhận về danh sách các Future
            List<Future<String>> results = executor.invokeAll(tasks);

            // Hoặc
            // List<Future<String>> results = IntStream.range(0, tasks.size())
            //         .mapToObj(i -> executor.submit(tasks.get(i)))
            //         .collect(Collectors.toList());

            // Thu thập kết quả từ các Future
            for (Future<String> result : results) {
                try {
                    String data = result.get(); // Lấy kết quả từ Future
                    System.out.println("Aggregated Data: " + data);
                } catch (ExecutionException e) {
                    System.err.println("Error fetching data: " + e.getMessage());
                }
            }
        } catch (InterruptedException e) {
            System.err.println("Task interrupted: " + e.getMessage());
        } finally {
            executor.shutdown(); // Đóng ExecutorService
        }
    }

    // Mô phỏng việc thu thập dữ liệu từ một nguồn
    private static String fetchDataFromSource(String sourceName) throws InterruptedException {
        switch (sourceName) {
            case "Source 1" -> Thread.sleep(2000); // Giả lập thời gian chờ 2 giây
            case "Source 2" -> Thread.sleep(3000); // Giả lập thời gian chờ 3 giây
            case "Source 3" -> Thread.sleep(1000); // Giả lập thời gian chờ 1 giây
            case "Source 4" -> Thread.sleep(4000); // Giả lập thời gian chờ 4 giây
            case "Source 5" -> Thread.sleep(2500); // Giả lập thời gian chờ 2.5 giây
        }
        return "Data from " + sourceName;
    }
}
```
Trong ví dụ trên, chúng ta tạo một Aggregator Service sử dụng ExecutorService với Virtual Thread để thu thập dữ liệu từ năm nguồn khác nhau. Mỗi nguồn được mô phỏng bằng một tác vụ Callable, và chúng ta sử dụng phương thức invokeAll() để gửi tất cả các tác vụ đồng thời. Sau đó, chúng ta thu thập kết quả từ các Future và in ra dữ liệu đã tổng hợp. Cuối cùng, chúng ta đóng ExecutorService để giải phóng tài nguyên.

> Ngoài ra, chúng ta có thể tạo các `Executor` lồng nhau, thread ảo chính thực hiện nhiều thread ảo con, để xử lý các tác vụ phức tạp hơn, sử dụng lợi ích của `Virtual Thread` để tối ưu hiệu suất. Không nên sử dụng `ThreadPerTaskExecutor` bên trong `Virtual Thread`, vì mỗi `Virtual Thread` đã rất nhẹ, việc tạo thêm `ThreadPerTaskExecutor` sẽ không mang lại lợi ích gì và có thể gây lãng phí tài nguyên.

> Khi sử dụng lồng nhau các `Executor`, cần chú ý đến việc quản lý vòng đời của chúng, đảm bảo rằng tất cả các `Executor` đều được đóng đúng cách để tránh rò rỉ tài nguyên. Đảm bảo các `executor` con thực hiện trong cùng 1 thread con phải đợi nhau cùng lúc kết thúc tránh tình trạng `Thread Leak`. Sử dụng `Future` để chờ kết quả từ các tác vụ con trước khi kết thúc `executor` cha.

```java
public ProductDto getProductDto(int id) throws Exception {
        var product = executorService.submit(() -> Client.getProduct(id));
        var rating = executorService.submit(() -> Client.getRating(id));
        return new ProductDto(id, product.get(), rating.get()); // Dùng Future.get() để chờ kết quả từ các tác vụ con, không để executor nào chưa kết thúc trước khi các tác vụ con hoàn thành
}
```
Trong ví dụ trên, chúng ta sử dụng một `ExecutorService` để gửi hai tác vụ đồng thời: một để lấy thông tin sản phẩm và một để lấy đánh giá sản phẩm. Cả hai tác vụ này được thực hiện trong cùng một `Virtual Thread`, tận dụng lợi ích của `Virtual Thread` để tối ưu hiệu suất. Chúng ta sử dụng phương thức `submit()` để gửi các tác vụ và nhận về các đối tượng `Future`, sau đó sử dụng phương thức `get()` để chờ và lấy kết quả khi các tác vụ hoàn thành. Cuối cùng, chúng ta tạo một đối tượng `ProductDto` từ kết quả thu thập được.

## 5. ThreadPoolTaskExecutor trong Spring Boot
Trong Spring Boot, `ThreadPoolTaskExecutor` là một lớp triển khai của `TaskExecutor` sử dụng một thread pool để quản lý và thực thi các tác vụ đa luồng. Nó cung cấp một cách dễ dàng để cấu hình và sử dụng thread pool trong ứng dụng Spring Boot của bạn.
### 5.1. So sánh ThreadPoolTaskExecutor và ExecutorService
| Đặc điểm                     | ThreadPoolTaskExecutor                  | ExecutorService                       |
|-----------------------------|----------------------------------------|--------------------------------------|
| Tích hợp với Spring         | Có, dễ dàng tích hợp với Spring Boot    | Không, cần cấu hình thủ công          |
| Cấu hình                    | Cung cấp nhiều tùy chọn cấu hình       | Cần cấu hình thủ công               |
| Quản lý vòng đời            | Được quản lý bởi Spring                 | Cần quản lý thủ công                  |
| Hỗ trợ các tính năng Spring | Có, hỗ trợ các tính năng như @Async     | Không, không tích hợp với Spring      |
### 5.2. Cấu hình ThreadPoolTaskExecutor trong Spring Boot
Bạn có thể cấu hình `ThreadPoolTaskExecutor` trong lớp cấu hình Spring Boot của bạn như sau:
```java
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.scheduling.concurrent.ThreadPoolTaskExecutor;
import java.util.concurrent.Executor;
@Configuration
public class AsyncConfig {
    @Bean(name = "taskExecutor")
    public Executor taskExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        int cores = Runtime.getRuntime().availableProcessors();
        executor.setCorePoolSize(cores); // Số lượng thread tối thiểu trong pool
        executor.setMaxPoolSize(cores * 2); // Số lượng thread tối đa trong pool
        executor.setQueueCapacity(1000); // Sức chứa của hàng đợi tác vụ
        executor.setThreadNamePrefix("Async-"); // Tiền tố tên thread
        executor.initialize(); // Khởi tạo executor
        return executor;
    }
}
```
### 5.3. Sử dụng ThreadPoolTaskExecutor với @Async
Bạn có thể sử dụng `ThreadPoolTaskExecutor` để thực thi các phương thức bất đồng bộ trong Spring Boot bằng cách sử dụng chú thích `@Async`. Dưới đây là ví dụ về cách sử dụng:
```java
import org.springframework.scheduling.annotation.Async;
import org.springframework.stereotype.Service;
@Service
public class AsyncService {
    @Async("taskExecutor") // Sử dụng executor đã cấu hình
    public void performAsyncTask(int taskId) {
        System.out.println("Performing async task " + taskId + " in thread " + Thread.currentThread().getName());
        try {
            Thread.sleep(2000); // Giả lập công việc mất thời gian
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
        System.out.println("Completed async task " + taskId);
    }
}
```

### 5.4. Kích hoạt hỗ trợ bất đồng bộ
Để sử dụng chú thích `@Async`, bạn cần kích hoạt hỗ trợ bất đồng bộ trong ứng dụng Spring Boot của mình bằng cách thêm chú thích `@EnableAsync` vào lớp cấu hình chính hoặc một lớp cấu hình riêng biệt:
```java
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.scheduling.annotation.EnableAsync;
@SpringBootApplication
@EnableAsync
public class AsyncApplication {
    public static void main(String[] args) {
        SpringApplication.run(AsyncApplication.class, args);
    }
}
```

### 5.5. Gọi phương thức bất đồng bộ
Bạn có thể gọi phương thức bất đồng bộ từ bất kỳ nơi nào trong ứng dụng Spring Boot của bạn. Dưới đây là ví dụ về cách gọi phương thức `performAsyncTask` từ một controller:
```java
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;
@RestController
public class AsyncController {

        }

    }
}
```

### 5.6. Sử dụng ThreadPoolTaskExecutor với CompletableFuture
Bạn cũng có thể sử dụng `ThreadPoolTaskExecutor` cùng với `CompletableFuture` để thực hiện các tác vụ bất đồng bộ trong Spring Boot. Dưới đây là ví dụ về cách sử dụng:
```java
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.scheduling.annotation.Async;
import org.springframework.stereotype.Service;
import java.util.concurrent.CompletableFuture;
@Service
public class AsyncCompletableFutureService {
    @Autowired
    private Executor taskExecutor;

    @Async("taskExecutor") // Sử dụng executor đã cấu hình
    public CompletableFuture<String> performAsyncTask(int taskId) {
        return CompletableFuture.runAsync(() -> {
            System.out.println("Performing async task " + taskId + " in thread " + Thread.currentThread().getName());
            try {
                Thread.sleep(2000); // Giả lập công việc mất thời gian
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
            System.out.println("Completed async task " + taskId);
            return "Result of task " + taskId;
        }, taskExecutor);
    }
}
```
Trong ví dụ trên, chúng ta sử dụng `CompletableFuture.supplyAsync()` để thực hiện tác vụ bất đồng bộ trong một thread từ `ThreadPoolTaskExecutor`. Phương thức `performAsyncTask` trả về một `CompletableFuture<String>`, cho phép bạn xử lý kết quả của tác vụ khi nó hoàn thành.

## 6. Semaphore trong Java
Semaphore là một công cụ đồng bộ hóa trong Java được sử dụng để kiểm soát truy cập vào một tài nguyên chung bởi nhiều thread. Nó duy trì một bộ đếm nội bộ để theo dõi số lượng thread có thể truy cập tài nguyên cùng một lúc. Khi một thread muốn truy cập tài nguyên, nó phải "acquire" (lấy) một phép cho phép từ semaphore. Nếu không còn phép nào, thread sẽ bị chặn cho đến khi một phép được "release" (giải phóng) bởi một thread khác.
### 6.1. Tạo và sử dụng Semaphore
Dưới đây là ví dụ về cách tạo và sử dụng Semaphore trong Java:
```java
import java.util.concurrent.Semaphore;
public class SemaphoreExample {
    private static final int MAX_CONCURRENT_THREADS = 3; // Số lượng thread tối đa có thể truy cập tài nguyên cùng một lúc
    private static final Semaphore semaphore = new Semaphore(MAX_CONCURRENT_THREADS); // Tạo semaphore với số phép tối đa

    public static void main(String[] args) {
        for (int i = 0; i < 10; i++) {
            final int threadId = i;
            new Thread(() -> {
                try {
                    System.out.println("Thread " + threadId + " is trying to acquire a permit.");
                    semaphore.acquire(); // Lấy một phép từ semaphore 
                    System.out.println("Thread " + threadId + " has acquired a permit.");
                    // Thực hiện công việc với tài nguyên chung
                    Thread.sleep(2000); // Giả lập công việc mất thời gian
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                } finally {
                    System.out.println("Thread " + threadId + " is releasing a permit.");
                    semaphore.release();
                }
            }).start();
        }
    }
}
```

## 7. CompletableFuture trong Java
`CompletableFuture` là một lớp trong Java cung cấp một cách tiếp cận mạnh mẽ để xử lý các tác vụ bất đồng bộ và kết hợp các tác vụ này một cách linh hoạt. Nó cho phép bạn tạo các chuỗi các tác vụ, xử lý kết quả của chúng khi hoàn thành, và quản lý lỗi một cách dễ dàng. Nó cũng được implement từ `Future` có thêm các tính năng như:
- Có thêm nhiều phương thức để xâu chuỗi các tác vụ bất đồng bộ như `thenApply()`, `thenAccept()`, `thenCompose()`, v.v, các phương thức xử lý lỗi như `exceptionally()`, `handle()`, v.v., các phương thức kết hợp nhiều `CompletableFuture` như `allOf()`, `anyOf()`, v.v.
- Cho phép chúng ta có thể kế thừa và mở rộng các phương thức của `CompletableFuture` để tạo ra các lớp con tùy chỉnh, từ đó có thể thêm các tính năng hoặc hành vi mới phù hợp với nhu cầu cụ thể của ứng dụng.
- Chấp nhận một `Executor` tùy chỉnh để thực thi các tác vụ bất đồng bộ, giúp kiểm soát tốt hơn về cách các tác vụ được thực thi và quản lý tài nguyên.

### 7.1. So sánh sử dụng CompletableFuture và không sử dụng CompletableFuture
> Sử dụng `CompletaleFuture`:
```java
getUsernameFromRemoteService()
    .thenApply(name -> "HELLO " + name.toUpperCase()) // Xử lý kết quả khi hoàn thành 
    .exceptionally(ex -> "Hey User..!") // Xử lý lỗi nếu có
    .orTimeout(1, TimeUnit.SECONDS) // Giới hạn thời gian chờ
    .exceptionally(ex -> "Oops.. the service is slow"); // Xử lý lỗi khi vượt quá thời gian chờ
    .thenApply(s -> s + " - " + LocalDateTime.now()); // Thêm thời gian hiện tại vào kết quả
```

> Không sử dụng `CompletaleFuture`:
```java
String result;
try {
    String name = getUsernameFromRemoteService().get(1, TimeUnit.SECONDS); // Lấy kết quả với thời gian chờ
    result = "HELLO " + name.toUpperCase(); // Xử lý kết quả
} catch (InterruptedException | ExecutionException e) {
    result = "Hey User..!"; // Xử lý lỗi
} catch (TimeoutException e) {
    result = "Oops.. the service is slow"; // Xử lý lỗi khi vượt quá thời gian chờ
}
result = result + " - " + LocalDateTime.now(); // Thêm thời gian hiện tại vào kết quả
```
> Trong ví dụ trên, sử dụng `CompletableFuture` giúp mã nguồn trở nên sạch sẽ và dễ đọc hơn, đồng thời cung cấp các phương thức tiện lợi để xử lý kết quả và lỗi một cách linh hoạt. Trong khi đó, không sử dụng `CompletableFuture` dẫn đến mã nguồn phức tạp hơn với nhiều khối `try-catch` và xử lý lỗi thủ công.

### 7.2. Cách hoạt động của CompletableFuture
`CompletableFuture` hoạt động dựa trên mô hình lập trình bất đồng bộ, cho phép bạn định nghĩa các tác vụ mà không cần chờ chúng hoàn thành ngay lập tức. Khi một tác vụ được gửi đến `CompletableFuture`, nó sẽ được thực thi trong một thread riêng biệt (có thể là một thread từ pool hoặc một thread ảo nếu sử dụng Virtual Thread). Khi tác vụ hoàn thành, kết quả sẽ được truyền đến các phương thức tiếp theo trong chuỗi xử lý.
Dưới đây là ví dụ về cách sử dụng `CompletableFuture` để thực hiện một tác vụ bất đồng bộ:
```java
import java.util.concurrent.CompletableFuture;
public class CompletableFutureExample {
    public static void main(String[] args) {
        log.info("main starts");
        var cf = fastTask(); // Gọi phương thức trả về CompletableFuture
        log.info("value={}", cf.join()); // Chờ và lấy kết quả từ CompletableFuture
        // Thứ tự logging:
        // main starts
        // method starts
        // method ends
        // value=hi
        // main ends

        var cf2 = slowTask(); // Gọi phương thức trả về CompletableFuture
        cf2.thenAccept(value -> log.info("value={}", value)); // Xử lý kết quả khi hoàn thành
        // Thứ tự logging:
        // main starts
        // method starts
        // method ends
        // main ends
        // value=hi (Do thực hiện bởi virtual thread, nên có thể xuất hiện sau main ends)

        log.info("main ends");
        Thread.sleep(2000); // Đợi để đảm bảo tác vụ chậm hoàn thành trước khi kết thúc chương trình
    }

    private static CompletableFuture<String> fastTask() {
        log.info("method starts");
        var cf = new CompletableFuture<String>(); // Tạo một CompletableFuture mới
        cf.complete("hi"); // Hoàn thành CompletableFuture với giá trị "hi"
        log.info("method ends");
        return cf; // Trả về CompletableFuture
    }

    private static CompletableFuture<String> slowTask() {
        log.info("method starts");
        var cf = new CompletableFuture<String>(); // Tạo một CompletableFuture mới
        Thread.ofVirtual().start(() -> {
            Thread.sleep(1); // Giả lập công việc mất thời gian
            cf.complete("hi"); // Hoàn thành CompletableFuture với giá trị "hi"
        });
        log.info("method ends");
        return cf; // Trả về CompletableFuture
    }
} 
```

#### 7.2.1. runAsync trong CompletableFuture
Phương thức `runAsync` trong `CompletableFuture` được sử dụng để thực thi một tác vụ bất đồng bộ mà không trả về giá trị. Nó nhận vào một đối tượng `Runnable` đại diện cho tác vụ cần thực thi và có thể nhận thêm một `Executor` tùy chỉnh để kiểm soát cách thức thực thi tác vụ.
Dưới đây là ví dụ về cách sử dụng `runAsync` trong `CompletableFuture`:
```java
import java.util.concurrent.CompletableFuture;
public class CompletableFutureRunAsyncExample {
    public static void main(String[] args) {
        log.info("main starts");
        runAsync()
            .thenRun(() -> log.info("it is done")); // Xử lý khi tác vụ hoàn thành
            .exceptionally(ex -> {
                log.error("error occurred: {}", ex.getMessage());
                return null;
            }); // Xử lý lỗi nếu có
        log.info("main ends");
    }

    private static CompletableFuture<Void> runAsync() {
        log.info("method starts");
        var cf = CompletableFuture.runAsync(() -> {
            try {
                Thread.sleep(1000); // Giả lập công việc mất thời gian
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }, 
        Executors.newVirtualThreadPerTaskExecutor() // Sử dụng Virtual Thread để thực thi tác vụ
        ); 
        log.info("method ends");
        return cf; // Trả về CompletableFuture
    }
}
```
#### 7.2.2. supplyAsync trong CompletableFuture
Phương thức `supplyAsync` trong `CompletableFuture` được sử dụng để thực thi một tác vụ bất đồng bộ và trả về một giá trị. Nó nhận vào một đối tượng `Supplier<T>` đại diện cho tác vụ cần thực thi và có thể nhận thêm một `Executor` tùy chỉnh để kiểm soát cách thức thực thi tác vụ.
Dưới đây là ví dụ về cách sử dụng `supplyAsync` trong `CompletableFuture`:
```java
import java.util.concurrent.CompletableFuture;
public class CompletableFutureSupplyAsyncExample {
    public static void main(String[] args) {
        log.info("main starts");
        supplyAsync()
            .thenAccept(value -> log.info("value={}", value)) // Xử lý kết quả khi hoàn thành
            .exceptionally(ex -> {
                log.error("error occurred: {}", ex.getMessage());
                return null;
            }); // Xử lý lỗi nếu có
        log.info("main ends");
    }

    private static CompletableFuture<String> supplyAsync() {
        log.info("method starts");
        var cf = CompletableFuture.supplyAsync(() -> {
            try {
                Thread.sleep(1000); // Giả lập công việc mất thời gian
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
            return "hi"; // Trả về giá trị khi hoàn thành
        },
        Executors.newVirtualThreadPerTaskExecutor() // Sử dụng Virtual Thread để thực thi tác vụ
        );
        log.info("method ends");
        return cf; // Trả về CompletableFuture
    }
}
```

### 7.3. Sử dụng CompletableFuture để xử lý lỗi khi dùng Aggregator Service
Dưới đây là ví dụ về cách sử dụng `CompletableFuture` để xây dựng một Aggregator Service với xử lý lỗi:
```java
import java.util.ArrayList;
import java.util.List;
import java.util.concurrent.CompletableFuture;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
public class AggregatorServiceWithErrorHandling {
    public static void main(String[] args) {
        ExecutorService executor = Executors.newVirtualThreadPerTaskExecutor(); // Sử dụng Virtual Thread Executor
        List<CompletableFuture<String>> futures = new ArrayList<>();

        // Thêm các tác vụ thu thập dữ liệu từ các nguồn khác nhau với xử lý lỗi
        futures.add(fetchDataFromSource("Source 1", executor));
        futures.add(fetchDataFromSource("Source 2", executor));
        futures.add(fetchDataFromSource("Source 3", executor));
        futures.add(fetchDataFromSource("Source 4", executor));
        futures.add(fetchDataFromSource("Source 5", executor));

        // Kết hợp tất cả các CompletableFuture và thu thập kết quả
        CompletableFuture.allOf(futures.toArray(new CompletableFuture[0]))
            .thenAccept(v -> {
                for (CompletableFuture<String> future : futures) {
                    try {
                        String data = future.get(); // Lấy kết quả từ CompletableFuture
                        System.out.println("Aggregated Data: " + data);
                    } catch (Exception e) {
                        System.err.println("Error fetching data: " + e.getMessage());
                    }
                }
            })
            .exceptionally(ex -> {
                System.err.println("Error in aggregation: " + ex.getMessage());
                return null;
            })
            .orTimeout(1, java.util.concurrent.TimeUnit.SECONDS) // Giới hạn thời gian chờ 1 giây
            .exceptionally(ex -> {
                System.err.println("Aggregation timed out: " + ex.getMessage());
                return null;
            }) // Xử lý lỗi khi vượt quá thời gian chờ
            .join(); // Chờ cho đến khi tất cả các tác vụ hoàn thành

        executor.shutdown(); // Đóng ExecutorService
    }

    // Mô phỏng việc thu thập dữ liệu từ một nguồn với xử lý lỗi
    private static CompletableFuture<String> fetchDataFromSource(String sourceName, ExecutorService executor) {
        return CompletableFuture.supplyAsync(() -> {
            switch (sourceName) {
                case "Source 1" -> Thread.sleep(2000); // Giả lập thời gian chờ 2 giây
                case "Source 2" -> Thread.sleep(3000); // Giả lập thời gian chờ 3 giây
                case "Source 3" -> Thread.sleep(1000); // Giả lập thời gian chờ 1 giây
                case "Source 4" -> Thread.sleep(4000); // Giả lập thời gian chờ 4 giây
                case "Source 5" -> Thread.sleep(2500); // Giả lập thời gian chờ 2.5 giây
            }
            if (Math.random() < 0.2) { // Giả lập lỗi ngẫu nhiên
                throw new RuntimeException("Failed to fetch data from " + sourceName);
            }
            return "Data from " + sourceName;
        }, executor);
    }
}
```
Trong ví dụ trên, chúng ta sử dụng `CompletableFuture` để thu thập dữ liệu từ năm nguồn khác nhau với xử lý lỗi. Mỗi nguồn được mô phỏng bằng một tác vụ `supplyAsync`, và chúng ta sử dụng `CompletableFuture.allOf()` để kết hợp tất cả các tác vụ. Khi tất cả các tác vụ hoàn thành, chúng ta thu thập kết quả từ từng `CompletableFuture` và xử lý lỗi nếu có. Cuối cùng, chúng ta đóng `ExecutorService` để giải phóng tài nguyên.

> Bên cạnh `allOf()`, chúng ta cũng có thể sử dụng `anyOf()` để chờ cho đến khi bất kỳ một trong các `CompletableFuture` hoàn thành, điều này hữu ích khi bạn chỉ cần kết quả từ một trong số các tác vụ mà không cần chờ tất cả chúng hoàn thành.

> `thenCombine()` được sử dụng để kết hợp kết quả của hai `CompletableFuture` khi cả hai đều hoàn thành. Phương thức này nhận vào hai `CompletableFuture` và một hàm kết hợp để xử lý kết quả của chúng. Dưới đây là ví dụ về cách sử dụng `thenCombine()`:
```java
import java.util.concurrent.CompletableFuture;
public class CompletableFutureThenCombineExample {
    public static void main(String[] args) {
        CompletableFuture<Integer> future1 = CompletableFuture.supplyAsync(() -> {
            // Giả lập công việc mất thời gian
            try {
                Thread.sleep(1000);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
            return 10;
        });

        CompletableFuture<Integer> future2 = CompletableFuture.supplyAsync(() -> {
            // Giả lập công việc mất thời gian
            try {
                Thread.sleep(1500);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
            return 20;
        });

        CompletableFuture<Integer> combinedFuture = future1.thenCombine(future2, (result1, result2) -> {
            // Kết hợp kết quả của hai CompletableFuture
            return result1 + result2;
        });

        combinedFuture.thenAccept(result -> {
            System.out.println("Combined Result: " + result); // In kết quả kết hợp
        }).join(); // Chờ cho đến khi kết quả được in ra
    }
}
```

> Lưu ý: Nếu không truyền tham số `executor` vào các phương thức như `supplyAsync()` hoặc `runAsync()`, `CompletableFuture` sẽ sử dụng `ForkJoinPool.commonPool()` để thực thi các tác vụ bất đồng bộ. Điều này có thể không tối ưu trong một số trường hợp, đặc biệt là khi bạn muốn kiểm soát cách thức thực thi các tác vụ hoặc khi bạn muốn sử dụng một loại thread cụ thể như `Virtual Thread`. Do đó, việc truyền một `Executor` tùy chỉnh giúp bạn kiểm soát tốt hơn về cách các tác vụ được thực thi và quản lý tài nguyên.
