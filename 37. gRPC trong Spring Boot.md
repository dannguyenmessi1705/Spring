# gRPC trong Spring Boot
## 1. Giới thiệu
gRPC (gRPC Remote Procedure Call) là một framework RPC mã nguồn mở được phát triển bởi Google. gRPC sử dụng HTTP/2 làm giao thức truyền tải và Protobuf (Protocol Buffers) làm định dạng dữ liệu. gRPC hỗ trợ nhiều ngôn ngữ lập trình khác nhau và cho phép các dịch vụ giao tiếp với nhau một cách hiệu quả và nhanh chóng.

gRPC được sử dụng rộng rãi trong các ứng dụng microservices, nơi mà các dịch vụ cần giao tiếp với nhau qua mạng. gRPC cung cấp nhiều tính năng mạnh mẽ như xác thực, mã hóa, truyền tải dữ liệu nhị phân và hỗ trợ streaming (truyền tải dữ liệu liên tục).

## 2. So sánh gRPC với REST
|| Tiêu chí | gRPC | REST |
|---|---|---|---|
| 1 | Giao thức | HTTP/2 | HTTP/1.1 |
| 2 | Định dạng dữ liệu | Protobuf | JSON |
| 3 | Tốc độ | Nhanh hơn | Chậm hơn |
| 4 | Streaming | Hỗ trợ | Không hỗ trợ |

Ưu điểm của gRPC:
- Tốc độ nhanh hơn so với REST nhờ sử dụng HTTP/2 và Protobuf.
- Hỗ trợ streaming (truyền tải dữ liệu liên tục) giúp tiết kiệm băng thông và tăng hiệu suất.
- Hỗ trợ nhiều ngôn ngữ lập trình khác nhau.
- Hỗ trợ xác thực và mã hóa dữ liệu.

Nhược điểm của gRPC:
- Cần cài đặt thêm thư viện gRPC trên client và server.
- Không hỗ trợ trình duyệt web (cần sử dụng gRPC-Web để hỗ trợ trình duyệt).
- Cần có kiến thức về Protobuf để định nghĩa các dịch vụ và thông điệp.

Kết hợp giữa gRPC và REST:
- Có thể sử dụng gRPC cho các dịch vụ backend hoặc microservices giao tiếp với nhau, trong khi sử dụng REST cho các dịch vụ frontend hoặc client giao tiếp với server.

VD: User gọi API REST để lấy thông tin tài khoản, sau đó gọi API gRPC để lấy thông tin chi tiết về tài khoản đó ở dưới backend.

## 3. Protocol Buffers (Protobuf)
Protocol Buffers (Protobuf) là một ngôn ngữ định nghĩa giao thức (Interface Definition Language - IDL) và một thư viện để tuần tự hóa dữ liệu (data serialization). Protobuf được phát triển bởi Google và được sử dụng rộng rãi trong các hệ thống phân tán và microservices.

Protobuf cho phép bạn định nghĩa các cấu trúc dữ liệu (messages) và dịch vụ (services) trong một file `.proto`. Sau đó, bạn có thể sử dụng trình biên dịch Protobuf để tạo mã nguồn cho nhiều ngôn ngữ lập trình khác nhau từ file `.proto` này.

### 3.1. So sánh Protobuf với JSON
|| Tiêu chí | Protobuf | JSON |
|---|---|---|---|
| 1 | Kích thước dữ liệu | Nhỏ hơn | Lớn hơn |
| 2 | Tốc độ tuần tự hóa | Nhanh hơn | Chậm hơn |
| 3 | Định dạng | Nhị phân | Văn bản |
| 4 | Khả năng mở rộng | Dễ dàng mở rộng | Khó mở rộng |

### 3.2. Cú pháp cơ bản của Protobuf
- Định nghĩa message:
```proto
syntax = "proto3"; // Khai báo sử dụng phiên bản proto3

option java_package = "com.example"; // Chỉ định package cho mã Java được sinh ra sau khi biên dịch .proto

// option go_package = "example"; // Chỉ định package cho mã Go được sinh ra sau khi biên dịch .proto
// option csharp_namespace = "Example"; // Chỉ định namespace cho mã C# được sinh ra sau khi biên dịch .proto

package example; // Đặt tên package cho file proto (Tránh trường hợp xung đột tên khi có nhiều file cùng tên .proto, cùng tên message, ...) Nên để file proto trong các thư mục con khác nhau tương ứng với tên package

java_multiple_files = true; // Tạo nhiều file Java từ một file proto (mỗi message và service sẽ được tạo thành một file Java riêng biệt)

// message định nghĩa một cấu trúc dữ liệu
// Định nghĩa theo cú pháp
/*
message <TênMessage> {
  <KiểuDữLiệu> <TênTrường> = <SốThứTự>;
  ...
}
*/
message Book {
  int32 book_id = 1; // ID của sách (số thứ tự 1)
  string title = 2;  // Tiêu đề sách (số thứ tự 2)
  float price = 3;   // Giá sách (số thứ tự 3)
  int32 pages = 4;   // Số trang (số thứ tự 4)
  int32 author_id = 5; // ID tác giả (số thứ tự 5)
}

enum Type {
  UNKNOWN = 0;
  FICTION = 1;
  SCIENCE = 2;
  BIOGRAPHY = 3;
}

message Author {
  int32 author_id = 1;  // ID tác giả
  string first_name = 2; // Tên tác giả
  string last_name = 3;  // Họ tác giả
  string gender = 4;     // Giới tính
  repeated Book books = 5;     // Danh sách sách sách của tác giả
  map<string, string> contacts = 6; // Thông tin liên lạc (key: loại liên lạc, value: thông tin)
  Type author_type = 7;  // Loại tác giả
  reserved 8, 9; // Đánh dấu số thứ tự 8, 9 đã bị loại bỏ, tránh tái sử dụng trong tương lai
  reserved "middle_name", "age"; // Đánh dấu tên trường middle_name, age đã bị loại bỏ, tránh tái sử dụng trong tương lai
}

// oneof: Chỉ một trong các trường được set
message Phone {
  int32 number = 1;
  int32 code = 2;
}

message Email {
  string address = 1;
  string password = 2;
}

messgage ContactInfo {
  oneof contact_method { // Trường này có thể có kiểu dữ liệu là Phone hoặc Email, nếu không set thì mặc định là UNKNOWN_CONTACT_METHOD
    Phone phone = 1;
    Email email = 2;
  }
}

```

Sau đó, để compile file `.proto` thành mã nguồn Java, bạn cần sử dụng plugin `protobuf-maven-plugin` trong Maven hoặc `protobuf-gradle-plugin` trong Gradle. Sau khi thêm plugin và cấu hình, bạn có thể chạy lệnh build để tự động sinh mã nguồn từ file `.proto`: `mvn clean compile` hoặc `./gradlew build`.

> Lưu ý số thứ tự các trường:
> - Mỗi trường trong một message phải có số thứ tự duy nhất (số nguyên dương).
> - 1-15: Dành cho các trường thường sử dụng (sử dụng 1 byte khi serialize).
> - 16-2047: Dành cho các trường ít sử dụng hơn (sử dụng 2 byte khi serialize).
> - Số thứ tự 1 là nhỏ nhất, không được sử dụng số thứ tự 0 (vì nó dành cho mục đích nội bộ của Protobuf), số thứ tự lớn nhất là 2^29 - 1 (536,870,911).
> - Số thứ tự không được thay đổi sau khi đã sử dụng, nếu muốn loại bỏ một trường, hãy sử dụng từ khóa `reserved` để đánh dấu số thứ tự hoặc tên trường đã bị loại bỏ, tránh tái sử dụng trong tương lai. (19000 - 19999 được dành riêng cho các mục đích nội bộ của Protobuf).
> - Không được thay đooir số thứ tự của các trường khi nó đã được sử dụng, vì sẽ gây ra lỗi khi deserialize dữ liệu đã được serialize trước đó.
> - Không được thay đổi kiểu dữ liệu của các trường đã được sử dụng, vì sẽ gây ra lỗi khi deserialize dữ liệu đã được serialize trước đó.
> - Hãy sử dụng `reserved` để đánh dấu các trường muốn xóa (loại bỏ) thay vì xóa trực tiếp và gán lại số thứ tự trường khác để tránh tái sử dụng số thứ tự hoặc tên trường đó trong tương lai. Ví dụ:
```proto
// Kiểu Employee ban đầu:

message Employee {
	string first_name = 1;
	int32 age = 2;
	int32 salary = 3;
}

// Sau đó có yêu cầu xóa salary, ta sẽ sử dụng reserved như sau:
message Employee {
  string first_name = 1;
  int32 age = 2;
  reserved 3; // Đánh dấu số thứ tự 3 đã bị loại bỏ
  reserved "salary"; // Đánh dấu tên trường salary đã bị loại bỏ
}

service EmployeeService { // Định nghĩa service EmployeeService

  rpc getEmployee(Employee) returns (Employee); // Phương thức getEmployee nhận vào một Employee và trả về một Employee (client gửi request, server trả về response)

  rpc listEmployees(google.protobuf.Empty) returns (stream Employee); // Phương thức listEmployees không nhận tham số và trả về một luồng (stream) các Employee (server streaming)

  rpc uploadEmployees(stream Employee) returns (google.protobuf.Empty); // Phương thức uploadEmployees nhận vào một luồng (stream) các Employee và trả về một Empty (client streaming)

  rpc chatEmployees(stream Employee) returns (stream Employee); // Phương thức chatEmployees nhận vào và trả về một luồng (stream) các Employee (bidirectional streaming)


}
```

### 3.3. Tính chẩt của file JAVA được sinh ra từ Protobuf
- Các class Java được sinh ra từ Protobuf thường là các class immutable (không thể thay đổi sau khi tạo Chỉ có thể tạo mới hoặc sử dụng Builder để tạo đối tượng mới từ đối tượng cũ, có getter nhưng không có setter).
- Sử dụng Builder pattern để tạo và cấu hình các đối tượng message, muốn sửa đổi giá trị của một trường, bạn cần tạo một đối tượng mới thông qua `toBuilder()` của đối tượng hiện tại.
```java
Book book = Book.newBuilder()
    .setBookId(1)
    .setTitle("Example Book")
    .build();
Book updatedBook = book.toBuilder()
    .setTitle("Updated Title")
    .build();

Book removedFieldBook = book.toBuilder()
    .clearTitle() // Xóa trường title, chứ không được set null
    .build();

Phone phone = Phone.newBuilder()
    .setNumber(123456789)
    .setCode(1)
    .build();

Email email = Email.newBuilder()
    .setAddress("example@example.com")
    .setPassword("password")
    .build();
ContactInfo contactByPhone = ContactInfo.newBuilder()
    .setPhone(phone) // Chỉ set phone
    .build();
ContactInfo contactByEmail = ContactInfo.newBuilder()
    .setEmail(email) // Chỉ set email
    .build();
```

- Objects được tạo ra không thể set null cho các trường, nếu không set giá trị cho một trường, nó sẽ có giá trị mặc định (0 cho số, rỗng cho chuỗi, false cho boolean). 
- Sử dụng các phương thức `has<FieldName>()` để kiểm tra xem một trường có được set hay không (chỉ áp dụng cho các trường message và enum).

| Protobuf Type | Java Type | Default Value | Mô tả |

| double | double | 0.0 | Số thực 64-bit |

| uint32 | int | 0 | Số nguyên không dấu 32-bit |
| int64 | long | 0L | Số nguyên 64-bit |
| sint64 | long | 0L | Số nguyên 64-bit (sử dụng mã hóa zigzag) |
| uint64 | long | 0L | Số nguyên không dấu 64-bit |
| bool | boolean | false | Giá trị boolean |
| string | String | "" | Chuỗi UTF-8 |

| reserved + <field numbers/names> | N/A | N/A | Dùng để đánh dấu các số thứ tự hoặc tên trường đã bị loại bỏ, tránh tái sử dụng trong tương lai |

### 3.5. Serialization và Deserialization
- Protobuf sử dụng định dạng nhị phân để tuần tự hóa (serialization) và giải tuần tự hóa (deserialization) dữ liệu, giúp tiết kiệm băng thông và tăng tốc độ truyền tải so với định dạng văn bản như JSON hoặc XML.
- Sử dụng `writeTo(OutputStream output)` để tuần tự hóa một message thành luồng byte, và `parseFrom(InputStream input)` để giải tuần tự hóa từ luồng byte thành một message.

```java
// Giả sử compile file .proto để tạo class Book
Book book = Book.newBuilder()
    .setBookId(1)
    .setTitle("Example Book")
    .setPrice(19.99f)
    .setPages(300)
    .setAuthorId(10)
    .build();
// Serialization
try (var stream = Files.newOutputStream(Path.of("book.bin"))) {
    book.writeTo(stream);
} catch (IOException e) {
    e.printStackTrace();
}
// Deserialization
try (var stream = Files.newInputStream(Path.of("book.bin"))) {
    Book deserializedBook = Book.parseFrom(stream);
    System.out.println("Deserialized Book: " + deserializedBook);
} catch (IOException e) {
    e.printStackTrace();
}

System.out.println("Compare books: " + book.equals(deserializedBook)); // true
```
### 3.6. Import trong Protobuf
- Protobuf hỗ trợ import các file `.proto` khác để tái sử dụng định nghĩa message và service. Trong file `.proto`, bạn có thể sử dụng cú pháp sau để import một file khác:

```proto
import "other.proto"; // Import file other.proto nếu cùng package
import "proto/common/book.proto"; // Import file book.proto nếu khác package (file book.proto nằm trong thư mục proto/common/ đã được định nghĩa package là proto.common)

// Sử dụng message hoặc service từ file đã import
message Library {
  repeated proto.common.Book books = 1; // Sử dụng cú pháp <package>.<MessageName>
}
```
- Ngoài ra, Google cũng cung cấp một số file `.proto` chuẩn trong thư viện `google/protobuf` sau khi compile, bạn có thể import chúng như sau:

```proto
import "google/protobuf/timestamp.proto"; // Import message Timestamp
import "google/protobuf/any.proto"; // Import message Any
import "google/protobuf/wrappers.proto"; // Import các message wrapper như Int32Value, StringValue, ...
import "google/protobuf/empty.proto"; // Import message Empty
```

### 3.7. Proto CI/CD
- Trong quy trình CI/CD, bạn có thể tự động biên dịch các file `.proto` thành mã nguồn Java (hoặc ngôn ngữ khác) mỗi khi có thay đổi trong file `.proto`. Điều này đảm bảo rằng mã nguồn luôn được cập nhật với định nghĩa mới nhất.
- Trong thư mục `protoc-plugins` (sau khi compile), bạn có thể lưu trữ các file `.proto` và sử dụng file `protoc-{version}-{os}.exe` để biên dịch các file `.proto` thành mã nguồn Java trong quá trình build của CI/CD. Cú pháp sử dụng như sau:

```bash
./protoc-<version>-<os>.exe --java_out=./output/path --proto_path=./proto/path ./proto/path/schema.proto
```
Trong đó:
- `--java_out`: Chỉ định thư mục đầu ra để lưu trữ mã nguồn Java được sinh ra. (python_out, cpp_out, go_out, csharp_out, ruby_out, ... tùy theo ngôn ngữ bạn muốn sinh mã nguồn)
- `--proto_path`: Chỉ định thư mục chứa các file `.proto`.
- `./proto/path/schema.proto`: Đường dẫn đến file `.proto` cần biên dịch.

## 4. Mô hình giao tiếp gRPC
gRPC hỗ trợ bốn mô hình giao tiếp chính giữa client và server:
1. **Unary RPC**: Client gửi một request và nhận về một response từ server. Đây là mô hình đơn giản nhất và phổ biến nhất.
   - Ví dụ: Client gửi yêu cầu lấy thông tin người dùng, server trả về thông tin người dùng.
2. **Server Streaming RPC**: Client gửi một request và nhận về một luồng (stream) các response từ server. Server có thể gửi nhiều response cho một request.
    - Ví dụ: Client gửi yêu cầu lấy thông tin giao hàng, server trả về nhiều bản ghi giao hàng theo thời gian thực.
3. **Client Streaming RPC**: Client gửi một luồng (stream) các request đến server và nhận về một response từ server. Client có thể gửi nhiều request trước khi nhận response.
    - Ví dụ: Client gửi nhiều bản ghi cảm biến đến server, server trả về tổng hợp dữ liệu sau khi nhận tất cả các bản ghi.
4. **Bidirectional Streaming RPC**: Client và server cùng gửi và nhận các luồng (stream) các message. Cả hai bên có thể gửi và nhận message độc lập với nhau.
   - Ví dụ: Chat ứng dụng, client và server có thể gửi và nhận tin nhắn liên tục.

## 4.1. Stream Observer trong gRPC
gRPC sử dụng `StreamObserver` để xử lý các luồng (stream) trong các mô hình giao tiếp streaming (Server Streaming, Client Streaming, Bidirectional Streaming).

`StreamObserver<T>` là một interface trong gRPC đại diện cho một luồng các message kiểu T. Nó có ba phương thức chính:
- 1. `onNext(T value)`: Phương thức này được gọi để gửi một message mới trong luồng. Trong server streaming, server sẽ gọi phương thức này để gửi từng response cho client. Trong client streaming, client sẽ gọi phương thức này để gửi từng request đến server.
- 2. `onError(Throwable t)`: Phương thức này được gọi khi có lỗi xảy ra trong luồng. Nó sẽ kết thúc luồng và thông báo lỗi cho bên nhận.
- 3. `onCompleted()`: Phương thức này được gọi để kết thúc luồng một cách bình thường. Nó thông báo rằng không còn message nào sẽ được gửi nữa.

Thông thường `method` của các service trong file `.proto` sẽ có kiểu trả về là `void` (nhìn có vẻ lạ vì không trả về gì cả) nhưng thực chất nó trả về một `StreamObserver<T>` để xử lý các luồng message (`StreanObserver` lại là tham số của phương thức `method` trong abstract class được sinh ra từ file `.proto`). Đây là mô hình kiểu mới, giúp gRPC có thể hỗ trợ tốt các mô hình giao tiếp streaming.

> Request và Response truyền thồng
```java
public T getSomething(Input) {
  ...
  return t;
}
```
> Request và Response với gRPC sử dụng StreamObserver
```java
public void getSomething(Input request, StreamObserver<T> responseObserver) {
  ...
  responseObserver.onNext(t); // Gửi response
  responseObserver.onCompleted(); // Kết thúc luồng
}
```

## 4.2. Cấu hình gRPC Server
Để cấu hình gRPC server trong Spring Boot, có 2 cách phổ biến:
### 4.2.1. Sử dụng thư viện `net.devh:grpc-server-spring-boot-starter` để tích hợp gRPC vào Spring Boot một cách dễ dàng. 
B1: Thêm dependency vào file `pom.xml` của module server:

### 4.2.2. Tự cấu hình gRPC server bằng cách tạo một bean `Server` trong Spring Boot.
```java
import io.grpc.BindableService;
import io.grpc.Server;
import io.grpc.ServerBuilder;
import io.grpc.health.v1.HealthCheckResponse.ServingStatus;
import io.grpc.protobuf.services.HealthStatusManager;
import java.io.IOException;
import java.util.List;
import java.util.concurrent.Executor;
import java.util.concurrent.TimeUnit;
import javax.annotation.PreDestroy;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Qualifier;
import org.springframework.boot.context.properties.EnableConfigurationProperties;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Slf4j
@Configuration
@RequiredArgsConstructor
@EnableConfigurationProperties(GrpcProperties.class)
public class GrpcServerConfiguration {

  private Server server; // Đây là instance của gRPC Server
  private Server healthServer; // Đây là instance của gRPC Health Server
  private final ServerTracingInterceptor serverTracingInterceptor; // Đây là interceptor để theo dõi và ghi log các request gRPC, nếu có
  private final GrpcProperties grpcProperties; // Cấu hình gRPC từ file application.yml
  private final HealthStatusManager healthStatusManager = new HealthStatusManager(); // Quản lý trạng thái sức khỏe của gRPC server

  @Bean
  public HealthStatusManager healthStatusManager() {
    return healthStatusManager; // Trả về instance của HealthStatusManager
  }

  @Bean
  public Server grpcServer(
    GrpcProperties grpcProperties, // Inject cấu hình gRPC
    List<BindableService> grpcServices,  // Inject tất cả các dịch vụ gRPC đã được định nghĩa (các class kế thừa BindableService, là các service được sinh ra từ file .proto)
    @Qualifier("ioExecutor") Executor executor // Inject Executor để xử lý các request gRPC bằng thread pool
  ) {
    try {
        server = createServer(grpcProperties, grpcServices, executor);
        var service - server.getServices()
        .stream() // Lấy tất cả các dịch vụ đã đăng ký trên gRPC server
        .mao(ServerServiceDefinition::getServiceDescriptor) // Lấy ServiceDescriptor từ mỗi dịch vụ
        .map(ServiceDescriptor::getName) // Lấy tên dịch vụ từ ServiceDescriptor
        .toList();  // Chuyển đổi sang danh sách
      }
      server.start();
    catch (IOException e) {
      log.error("Failed to start gRPC server", e);
    }
    log.info("gRPC server started successfully on port {}, services: {}", grpcProperties.getConfig().getPort(), service);
    healthStatusManager.setStatus("", ServingStatus.SERVING); // Đặt trạng thái sức khỏe của gRPC server là SERVING (đang hoạt động)
    Runtime.getRuntime().addShutdownHook(new Thread(this::shutDownServer)); // Thêm hook để tắt gRPC server khi JVM shutdown
    return server; // Trả về instance của gRPC Server
  }

  @PreDestroy // Đánh dấu phương thức này sẽ được gọi khi bean bị hủy (khi ứng dụng Spring Boot tắt)
  public void stopServer() {
    shutDownServer(); // Gọi phương thức để tắt gRPC server
  }

  private void shutDownServer() { // Phương thức để tắt gRPC server
    healthStatusManager.setStatus("", ServingStatus.NOT_SERVING); // Đặt trạng thái sức khỏe của gRPC server là NOT_SERVING (không hoạt động)
    if (server != null && !server.isShutdown()) { // Kiểm tra nếu server không null và chưa bị tắt
      log.info("Shutting down gRPC server since JVM is shutting down"); // Ghi log thông báo tắt gRPC server do JVM đang tắt
      try {
        server.shutdown(); // Yêu cầu gRPC server tắt một cách nhẹ nhàng
        if (!server.awaitTermination(grpcProperties.getConfig().getAwaitTermination(), TimeUnit.MILLISECONDS)) { // Chờ server tắt trong khoảng thời gian cấu hình, nếu không thì ép tắt
          log.warn("gRPC server did not shut down in the allocated time. Forcing shutdown.");
          server.shutdownNow(); // Ép tắt gRPC server ngay lập tức
        }
        log.info("gRPC server shut down successfully"); // Ghi log thông báo gRPC server đã tắt thành công
      } catch (InterruptedException e) {
        log.error("gRPC server shut down interrupted", e);
        Thread.currentThread().interrupt(); // Khôi phục trạng thái interrupt của thread
      }
    }
  }

  private Server createServer(GrpcProperties grpcProperties, List<BindableService> grpcServices, Executor executor) {
    ServerBuilder<?> serverBuilder = ServerBuilder // Tạo builder để cấu hình gRPC server
        .forPort(grpcProperties.getConfig().getPort()) // Cấu hình port cho gRPC server
        .addService(healthStatusManager.getHealthService()) // Thêm dịch vụ health check vào gRPC server
        .keepAliveTime(grpcProperties.getConfig().getKeepAliveTime(), TimeUnit.MILLISECONDS) // Cấu hình thời gian keep-alive
        .keepAliveTimeout(grpcProperties.getConfig().getKeepAliveTimeout(), TimeUnit.MILLISECONDS) // Cấu hình timeout cho keep-alive
        .permitKeepAliveWithoutCalls(grpcProperties.getConfig().isKeepAliveWithoutCalls()) // Cấu hình cho phép keep-alive khi không có cuộc gọi
        .permitKeepAliveTime(grpcProperties.getConfig().getPermitKeepAliveTime(), TimeUnit.MILLISECONDS) // Cấu hình thời gian cho phép keep-alive
        .handshakeTimeout(grpcProperties.getConfig().getHandshakeTimeout(), TimeUnit.MILLISECONDS) // Cấu hình timeout cho handshake
        .maxInboundMessageSize(grpcProperties.getConfig().getMaxInboundMessageSize()) // Cấu hình kích thước tối đa của message nhận vào
        .maxInboundMetadataSize(grpcProperties.getConfig().getMaxInboundMetadataSize()) // Cấu hình kích thước tối đa của metadata nhận vào
        .executor(executor) // Cấu hình executor để xử lý các request
        .intercept(serverTracingInterceptor); // Thêm interceptor để theo dõi tracing cho server

    grpcServices.forEach(serverBuilder::addService); // Thêm tất cả các dịch vụ gRPC vào server
    return serverBuilder.build(); // Xây dựng và trả về instance của gRPC Server
  }
}
```

```java
import io.grpc.CallOptions;
import io.grpc.Channel;
import io.grpc.ClientCall;

import java.util.concurrent.TimeUnit;

import org.springframework.beans.factory.annotation.Qualifier;
import org.springframework.boot.context.properties.EnableConfigurationProperties;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Slf4j
@Configuration
@EnableConfigurationProperties(GrpcProperties.class)
public class GrpcChannelConfiguration {

    public static final String ACCOUNTING_SERVICE = "accounting-service";
    private static final String GZIP_COMPRESSION = "gzip";
    private final TracingInterceptor tracingInterceptor; // Interceptor để theo dõi và ghi log các request gRPC
    private final Executor ioExecutor;

    public GrpcChannelConfiguration(
        TracingInterceptor tracingInterceptor, // Inject interceptor để theo dõi tracing
        @Qualifier("ioExecutor") Executor ioExecutor // Inject Executor để xử lý các request gRPC bằng thread pool
    ) { 
        this.tracingInterceptor = tracingInterceptor; 
        this.ioExecutor = ioExecutor;
    }

    /**
     * Tạo bean stub cho dịch vụ AccountingService (unary service, blocking stub)
     * return: AccountingServiceGrpc.AccountingServiceBlockingStub - Stub để gọi các phương thức của dịch vụ AccountingService
     */
    @Bean 
    public AccountingServiceGrpc.AccountingServiceBlockingStub accountingServiceBlockingStub(GrpcProperties grpcProperties) {
        Channel channel = createChannel(grpcProperties.getServers().get(ACCOUNTING_SERVICE), grpcProperties.getConfig());
        return AccountingServiceGrpc.newBlockingStub(channel); // Tạo và trả về stub blocking (synchronous) cho dịch vụ AccountingService
    }

    private Channel createChannel(GrpcServerProperties properties) {
        log.info("Creating Sidecar gRPC channel for {}:{}", properties.getHost(), properties.getPort());

        return ManagedChannelBuilder.forAddress(properties.getHost(), properties.getPort()) // Tạo kênh kết nối đến server gRPC với địa chỉ và cổng được cấu hình
            .usePlaintext() // Sử dụng kết nối không mã hóa (plaintext, không sử dụng SSL/TLS tùy thuộc vào yêu cầu bảo mật)
            .executor(ioExecutor) // Sử dụng executor để xử lý các request gRPC
            .intercept(tracingInterceptor) // Thêm interceptor để theo dõi tracing cho client
            .intercept(gzipInterceptor()) // Thêm interceptor để nén dữ liệu bằng gzip
            .enableFullStreamDecompression() // Kích hoạt giải nén đầy đủ cho các luồng dữ liệu
            .keepAliveTime(properties.getKeepAliveTime(), TimeUnit.MILLISECONDS) // Cấu hình thời gian keep-alive
            .keepAliveWithoutCalls(properties.isKeepAliveWithoutCalls()) // Cấu hình cho phép keep-alive khi không có cuộc gọi
            .keepAliveTimeout(properties.getKeepAliveTimeout(), TimeUnit.MILLISECONDS) // Cấu hình thời gian chờ keep-alive
            .disableRetry() // Vô hiệu hóa tính năng retry của gRPC
            .build();
    }
    
    /**
     * Interceptor để nén dữ liệu bằng gzip
     */
    private ClientInterceptor gzipInterceptor() { 
        return new ClientInterceptor() {
            @Override
            public <Q, P> ClientCall<Q, P> interceptCall(MethodDescriptor<Q, P> methodDescriptor,
                CallOptions callOptions, Channel channel) {
                return channel.newCall(methodDescriptor, callOptions.withCompression(GZIP_COMPRESSION)); // Sử dụng nén gzip cho cuộc gọi gRPC
            }
        };
    }
}
```

## 5. Cài đặt gRPC trong Spring Boot
### 5.1. Cài đặt gRPC
Chúng ta sẽ dùng Maven chia thành 3 module:
- `grpc-server`: Module chứa server gRPC.
- `grpc-client`: Module chứa client gRPC.
- `proto`: Module chứa các file proto định nghĩa dịch vụ gRPC.

```
│   ├── pom.xml
```

## 5.2. Định nghĩa gRPC Service với Protobuf

### 5.2.1. Tạo file schema.proto

File `.proto` là file định nghĩa giao thức gRPC bằng ngôn ngữ Protocol Buffers. Dưới đây là các bước để tạo một file `.proto` trong dự án Spring Boot:

1. Đầu tiên, tạo thư mục `proto/src/main/proto` trong dự án của bạn.
2. Tạo file `schema.proto` trong thư mục đó với nội dung như sau:

```proto
syntax = "proto3"; // Khai báo sử dụng phiên bản proto3

package com.didan; // Đặt tên package cho file proto

option java_multiple_files = true; // Tạo nhiều file Java từ một file proto

// Định nghĩa message Book
message Book {
  int32 book_id = 1; // ID của sách (số thứ tự 1)
  string title = 2;  // Tiêu đề sách (số thứ tự 2)
  float price = 3;   // Giá sách (số thứ tự 3)
  int32 pages = 4;   // Số trang (số thứ tự 4)
  int32 author_id = 5; // ID tác giả (số thứ tự 5)
}

// Định nghĩa message Author
message Author {
  int32 author_id = 1;  // ID tác giả
  string first_name = 2; // Tên tác giả
  string last_name = 3;  // Họ tác giả
  string gender = 4;     // Giới tính
  int32 book_id = 5;     // ID sách
}

// Định nghĩa service BookAuthorService
service BookAuthorService {
  // Phương thức unary (1 request, 1 response)
  rpc getAuthor(Author) returns(Author) {}
}
```

### 5.2.2. Chi tiết cú pháp file .proto

#### Cú pháp cơ bản

- `syntax = "proto3"`: Khai báo sử dụng phiên bản Protocol Buffers 3.
- `package com.didan`: Định nghĩa namespace để tránh xung đột tên.
- `option java_multiple_files = true`: Tạo file Java riêng cho mỗi message và service.

#### Message

Message là cấu trúc dữ liệu chính trong Protocol Buffers. Mỗi trường trong message được định nghĩa với cú pháp:

```proto
<kiểu_dữ_liệu> <tên_trường> = <số_thứ_tự>;
```

- **Kiểu dữ liệu**: int32, int64, float, double, bool, string, bytes, enum, message khác,...
- **Tên trường**: Tên của trường (nên sử dụng snake_case).
- **Số thứ tự**: Số nguyên dương duy nhất cho mỗi trường trong message, dùng để định danh trường trong quá trình serialize/deserialize.

#### Service

Service định nghĩa các phương thức RPC mà client có thể gọi:

```proto
service <TênService> {
  rpc <TênPhươngThức>(<KiểuRequest>) returns (<KiểuResponse>) {}
}
```

#### Các kiểu RPC

1. **Unary RPC**: Client gửi một request, server trả về một response.
   ```proto
   rpc getAuthor(Author) returns(Author) {}
   ```

2. **Server Streaming RPC**: Client gửi một request, server trả về nhiều response.
   ```proto
   rpc listAuthors(Author) returns(stream Author) {}
   ```

3. **Client Streaming RPC**: Client gửi nhiều request, server trả về một response.
   ```proto
   rpc createAuthors(stream Author) returns(Author) {}
   ```

4. **Bidirectional Streaming RPC**: Client và server đều gửi nhiều message.
   ```proto
   rpc chatWithAuthor(stream Author) returns(stream Author) {}
   ```

### 5.2.4. Biên dịch file .proto

Sau khi đã cấu hình Maven plugin, bạn có thể biên dịch file `.proto` bằng câu lệnh:

```bash
mvn clean compile
```

Khi chạy lệnh này, Maven sẽ sử dụng protoc compiler để biên dịch file `.proto` thành các class Java tương ứng.

### 5.2.5. Các file Java được tạo ra sau khi biên dịch

Khi biên dịch file `.proto` có nội dung như trên, các file Java sau sẽ được tạo ra trong thư mục `target/generated-sources/protobuf`:

1. **Message classes**:
   - `Book.java`: Class cho message Book.
   - `BookOrBuilder.java`: Interface cho Book builder.
   - `Author.java`: Class cho message Author.
   - `AuthorOrBuilder.java`: Interface cho Author builder.

2. **Service classes**:
   - `BookAuthorServiceGrpc.java`: Class chứa code để gọi service, bao gồm:
     - `BookAuthorServiceImplBase`: Abstract class để implement service trên server.
     - `BookAuthorServiceBlockingStub`: Stub để gọi service một cách đồng bộ.
     - `BookAuthorServiceFutureStub`: Stub để gọi service với Future.
     - `BookAuthorServiceStub`: Stub để gọi service một cách bất đồng bộ.

### 5.2.6. Best practices khi viết file .proto

1. **Số thứ tự trường**:
   - Sử dụng số từ 1-15 cho các trường thường xuyên được sử dụng (chỉ tốn 1 byte).
   - Số từ 16-2047 tốn 2 bytes.
   - Không sử dụng lại số thứ tự, ngay cả khi trường đã bị xóa.

2. **Tên trường**:
   - Sử dụng snake_case cho tên trường trong file .proto.
   - Protobuf compiler sẽ tự động chuyển thành camelCase trong code Java.

3. **Phiên bản**:
   - Thêm phiên bản vào tên package để hỗ trợ tương thích ngược.
   - Ví dụ: `package com.didan.v1;`

4. **Reserved Fields**:
   - Khi xóa một trường, đánh dấu số của nó là reserved để tránh tái sử dụng.
   ```proto
   message Book {
     reserved 4, 15, 16 to 20;
     reserved "removed_field";
   }
   ```

5. **Default Values**:
   - Khi một trường không được set, nó sẽ có giá trị mặc định (0, chuỗi rỗng, false).
   - Không thể phân biệt giữa giá trị mặc định và giá trị được set.

### 5.2.7. Ví dụ mở rộng

Ví dụ về việc sử dụng các tính năng nâng cao của Protocol Buffers:

```proto
syntax = "proto3";

package com.didan.v1;

option java_multiple_files = true;
option java_package = "com.didan.model";
option java_outer_classname = "BookProtos";

import "google/protobuf/timestamp.proto";

// Định nghĩa enum cho thể loại sách
enum BookCategory {
  UNKNOWN = 0;
  FICTION = 1;
  SCIENCE = 2;
  BIOGRAPHY = 3;
  TECHNOLOGY = 4;
}

message Book {
  int32 book_id = 1;
  string title = 2;
  float price = 3;
  int32 pages = 4;
  int32 author_id = 5;
  BookCategory category = 6;
  google.protobuf.Timestamp published_date = 7;
  
  // Nested message - Thông tin nhà xuất bản
  message Publisher {
    string name = 1;
    string address = 2;
  }
  
  Publisher publisher = 8;
  
  // Repeated field - Danh sách từ khóa
  repeated string keywords = 9;
}

// Request/Response messages
message GetBookRequest {
  int32 book_id = 1;
}

message GetBookResponse {
  Book book = 1;
  string message = 2;
  int32 status_code = 3;
}

// Service với nhiều phương thức
service BookService {
  // Unary
  rpc GetBook(GetBookRequest) returns(GetBookResponse) {}
  
  // Server streaming
  rpc ListBooks(GetBookRequest) returns(stream Book) {}
  
  // Client streaming
  rpc CreateBooks(stream Book) returns(GetBookResponse) {}
  
  // Bidirectional streaming
  rpc ProcessBooks(stream Book) returns(stream GetBookResponse) {}
}
```

### 6.4. Triển khai gRPC Service

Để triển khai một gRPC service, bạn cần tạo một class kế thừa từ abstract class được tự động tạo ra từ file `.proto`. Trong trường hợp này, chúng ta sẽ triển khai `BookAuthorServiceGrpc.BookAuthorServiceImplBase`. Đây là class cơ sở để bạn override các phương thức RPC đã định nghĩa trong file `.proto`.

Các phương thức RPC mặc định sẽ có kiểu trả về `void` và nhận vào các tham số như request object và một `StreamObserver` để gửi response. Tuy là `void`, nhưng bạn sẽ sử dụng `StreamObserver` để gửi dữ liệu trả về cho client theo dạng `stream`.

```java
package com.didan.server.service;

import com.didan.Author;
import com.didan.BookAuthorServiceGrpc;
import io.grpc.stub.StreamObserver;
import net.devh.boot.grpc.server.service.GrpcService;

@GrpcService
public class BookAuthorServerService extends BookAuthorServiceGrpc.BookAuthorServiceImplBase {

    @Override // Override phương thức getAuthor từ file .proto 
    public void getAuthor(Author request, StreamObserver<Author> responseObserver) {
        // Xử lý yêu cầu và tạo phản hồi
        System.out.println("Server received request for author ID: " + request.getAuthorId());
        
        // Tạo đối tượng Author để trả về
        Author response = Author.newBuilder()
                .setAuthorId(request.getAuthorId())
                .setFirstName("Nguyễn")
                .setLastName("Văn A")
                .setGender("Nam")
                .setBookId(123)
                .build();
        
        // Gửi response về client
        responseObserver.onNext(response);
        
        // Hoàn thành xử lý
        responseObserver.onCompleted();
    }
}
```

Annotation `@GrpcService` đánh dấu class này là một gRPC service và tự động đăng ký nó với gRPC server.

### 4.5. Tạo server streaming service

```java
@GrpcService
public class BookAuthorServerService extends BookAuthorServiceGrpc.BookAuthorServiceImplBase {

    // Phương thức unary đã triển khai ở trên
    // ...
    
    @Override
    public void listAuthors(Author request, StreamObserver<Author> responseObserver) {
        System.out.println("Server received request to list authors with book ID: " + request.getBookId());
        
        // Giả lập việc gửi nhiều author về client
        for (int i = 1; i <= 5; i++) {
            Author author = Author.newBuilder()
                .setAuthorId(100 + i)
                .setFirstName("Tác giả")
                .setLastName("Số " + i)
                .setGender(i % 2 == 0 ? "Nam" : "Nữ")
                .setBookId(request.getBookId())
                .build();
            
            // Gửi từng author về client
            responseObserver.onNext(author);
            
            // Giả lập delay để thấy rõ streaming
            try {
                Thread.sleep(1000);
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }
        
        // Hoàn thành stream
        responseObserver.onCompleted();
    }
}
```

Lưu ý: Phương thức `listAuthors` phải được định nghĩa trong file `.proto` trước khi triển khai:

```proto
service BookAuthorService {
  // unary
  rpc getAuthor(Author) returns(Author) {}
  
  // server streaming

}
```

### 4.6. Tạo client streaming service

```java
@GrpcService
public class BookAuthorServerService extends BookAuthorServiceGrpc.BookAuthorServiceImplBase {

    // Các phương thức đã triển khai ở trên
    // ...
    
    @Override
    public StreamObserver<Author> createAuthors(StreamObserver<Author> responseObserver) {
        return new StreamObserver<Author>() {
            private int count = 0;
            private Author lastAuthor = null;
            
            @Override
            public void onNext(Author author) {
                // Xử lý mỗi author được gửi từ client
                count++;
                System.out.println("Received author #" + count + ": " + author.getFirstName() + " " + author.getLastName());
                lastAuthor = author;
            }
            
            @Override
            public void onError(Throwable t) {
                // Xử lý lỗi
                System.err.println("Error in createAuthors: " + t.getMessage());
            }
            
            @Override
            public void onCompleted() {
                // Khi client hoàn thành việc gửi dữ liệu
                System.out.println("Client completed sending data. Total authors received: " + count);
                
                // Gửi response về client
                Author response;
                if (lastAuthor != null) {
                    response = Author.newBuilder(lastAuthor)
                            .setFirstName("Processed " + count + " authors")
                            .build();
                } else {
                    response = Author.newBuilder()
                            .setAuthorId(-1)
                            .setFirstName("No authors received")
                            .build();
                }
                
                responseObserver.onNext(response);
                responseObserver.onCompleted();
            }
        };
    }
}
```

Lưu ý: Phương thức `createAuthors` phải được định nghĩa trong file `.proto`:

```proto
service BookAuthorService {
  // ... other methods
  
  // client streaming
  rpc createAuthors(stream Author) returns(Author) {}
}
```

```java
        };
```

#### 4.8.4. Cập nhật Service để sử dụng Repository

```java
package com.didan.server.service;

import com.didan.Author;
import com.didan.BookAuthorServiceGrpc;
import com.didan.server.entity.AuthorEntity;
import com.didan.server.repository.AuthorRepository;
import io.grpc.Status;
import io.grpc.stub.StreamObserver;
import net.devh.boot.grpc.server.service.GrpcService;
import org.springframework.beans.factory.annotation.Autowired;

import java.util.Optional;

@GrpcService
public class BookAuthorServerService extends BookAuthorServiceGrpc.BookAuthorServiceImplBase {

    private final AuthorRepository authorRepository;
    
    @Autowired
    public BookAuthorServerService(AuthorRepository authorRepository) {
        this.authorRepository = authorRepository;
    }

    @Override
    public void getAuthor(Author request, StreamObserver<Author> responseObserver) {
        try {
            if (request.getAuthorId() <= 0) {
                // Xử lý lỗi nếu ID không hợp lệ
                responseObserver.onError(
                    Status.INVALID_ARGUMENT
                        .withDescription("Author ID must be positive")
                        .asRuntimeException()
                );
                return;
            }
            
            // Tìm author từ database
            Optional<AuthorEntity> optionalAuthor = authorRepository.findById(request.getAuthorId());
            
            if (optionalAuthor.isPresent()) {
                AuthorEntity entity = optionalAuthor.get();
                
                // Chuyển đổi từ entity sang protobuf message
                Author response = Author.newBuilder()
                        .setAuthorId(entity.getId())
                        .setFirstName(entity.getFirstName())
                        .setLastName(entity.getLastName())
                        .setGender(entity.getGender())
                        .setBookId(entity.getBookId())
                        .build();
                
                // Gửi response về client
                responseObserver.onNext(response);
                responseObserver.onCompleted();
            } else {
                // Xử lý khi không tìm thấy author
                responseObserver.onError(
                    Status.NOT_FOUND
                        .withDescription("Author not found with ID: " + request.getAuthorId())
                        .asRuntimeException()
                );
            }
        } catch (Exception e) {
            // Xử lý ngoại lệ
            responseObserver.onError(
                Status.INTERNAL
                    .withDescription("Internal server error: " + e.getMessage())
                    .asRuntimeException()
            );
        }
    }
}
```

```java
package com.didan.server.interceptor;

import io.grpc.*;
import net.devh.boot.grpc.server.interceptor.GrpcGlobalServerInterceptor;
import org.springframework.stereotype.Component;

@Component
@GrpcGlobalServerInterceptor
public class AuthInterceptor implements ServerInterceptor {

    private static final Metadata.Key<String> AUTH_TOKEN_KEY =
            Metadata.Key.of("Authorization", Metadata.ASCII_STRING_MARSHALLER);

    @Override
    public <ReqT, RespT> ServerCall.Listener<ReqT> interceptCall(
            ServerCall<ReqT, RespT> call,
            Metadata headers,
            ServerCallHandler<ReqT, RespT> next) {
        
        String token = headers.get(AUTH_TOKEN_KEY);
        
        if (token == null || !isValidToken(token)) {
            call.close(Status.UNAUTHENTICATED
                    .withDescription("Invalid or missing token"),
                    new Metadata());
                    
            return new ServerCall.Listener<>() {};
        }
        
        return next.startCall(call, headers);
    }
    
    private boolean isValidToken(String token) {
        // Logic kiểm tra token
        // Trong thực tế, bạn có thể sử dụng JWT hoặc OAuth2
        return token.startsWith("Bearer ") && token.length() > 10;
    }
}
```

```java
                    }
                }, headers)) {

                logger.info("Received message: {}", message);
                super.onMessage(message);
            }
            
            @Override
            public void onHalfClose() {
                logger.info("Client finished sending messages for method: {}", methodName);
                super.onHalfClose();
            }
            
            @Override
            public void onComplete() {
                logger.info("Call completed for method: {}", methodName);

            }
```

```java
    public <ReqT, RespT> ClientCall<ReqT, RespT> interceptCall(
            MethodDescriptor<ReqT, RespT> method,
            CallOptions callOptions,
            Channel next) {
        
        return new ForwardingClientCall.SimpleForwardingClientCall<>(
                next.newCall(method, callOptions)) {
            
            @Override
            public void start(Listener<RespT> responseListener, Metadata headers) {
                // Thêm token vào metadata
                headers.put(AUTH_TOKEN_KEY, "Bearer " + jwtToken);
                super.start(responseListener, headers);
            }
        };
    }
}
```

## 6. So sánh các phương thức gRPC

| Kiểu RPC | Mô tả | Use cases |
|----------|-------|-----------|
| Unary | Client gửi một request và nhận về một response | Hầu hết các API thông thường, như get/update/delete |
| Server Streaming | Client gửi một request và nhận về nhiều response | Lấy dữ liệu lớn, real-time updates, streaming data |
| Client Streaming | Client gửi nhiều request và nhận về một response | Tải lên dữ liệu lớn, real-time data collection |
| Bidirectional Streaming | Client và server gửi và nhận nhiều message | Chat applications, real-time collaboration, monitoring |

### 6.1. Ví dụ Unary RPC

**Schema.proto**:
```proto
rpc GetAuthor(AuthorRequest) returns (Author) {}
```

**Server implementation**:
```java
@Override
public void getAuthor(AuthorRequest request, StreamObserver<Author> responseObserver) {
    Author author = // ... logic to get author
    responseObserver.onNext(author);
    responseObserver.onCompleted();
}
```

**Client implementation**:
```java
AuthorRequest request = AuthorRequest.newBuilder().setAuthorId(123).build();
Author response = stub.getAuthor(request);
```

**Schema.proto**:
```proto
rpc ListAuthors(BookRequest) returns (stream Author) {}
```

**Server implementation**:
```java

    // Gửi nhiều authors
    for (Author author : getAuthorsForBook(request.getBookId())) {
```

**Schema.proto**:
```proto

```

**Server implementation**:

```java
        @Override
        public void onNext(Author author) {

            // Xử lý lỗi
        }

        public void onCompleted() {

            CreateAuthorsResponse response = CreateAuthorsResponse.newBuilder()
                    .setCount(authors.size())
                    .build();
                    
            responseObserver.onNext(response);
            responseObserver.onCompleted();
        }
    };
}
```

**Client implementation**:

### 6.4. Ví dụ Bidirectional Streaming RPC

**Schema.proto**:
```proto
rpc ProcessAuthors(stream Author) returns (stream AuthorProcessingResult) {}
```

**Server implementation**:
```java
@Override
public StreamObserver<Author> processAuthors(StreamObserver<AuthorProcessingResult> responseObserver) {
    return new StreamObserver<Author>() {
        @Override
        public void onNext(Author author) {
            // Xử lý mỗi author và trả về kết quả ngay lập tức
            AuthorProcessingResult result = processAuthor(author);
            responseObserver.onNext(result);
        }
        
        @Override
        public void onError(Throwable t) {
            // Xử lý lỗi
        }
        
        @Override
        public void onCompleted() {
            // Khi client hoàn thành việc gửi dữ liệu
            responseObserver.onCompleted();
        }
    };
}
```

**Client implementation**:
```java
StreamObserver<AuthorProcessingResult> responseObserver = new StreamObserver<AuthorProcessingResult>() {
    @Override
    public void onNext(AuthorProcessingResult result) {
        System.out.println("Received result for author: " + result.getAuthorId());
    }
    
    @Override
    public void onError(Throwable t) {
        System.err.println("Error: " + t.getMessage());
    }
    
    @Override
    public void onCompleted() {
        System.out.println("Server completed sending results");
    }
};

StreamObserver<Author> requestObserver = asyncStub.processAuthors(responseObserver);

// Gửi nhiều authors và nhận kết quả cho mỗi author

    requestObserver.onNext(author);
    Thread.sleep(500); // Đợi một chút để xem kết quả
}

requestObserver.onCompleted();
```

## 7. Best Practices và Optimization

### 7.1. Hiệu suất

1. **Reuse gRPC channels**: Channel tạo ra nhiều kết nối TCP persistent, nên tái sử dụng chúng.
   ```java
   // Đúng - tạo một channel và sử dụng lại
   ManagedChannel channel = ManagedChannelBuilder.forAddress(host, port).build();
   Stub stub1 = ServiceGrpc.newStub(channel);
   Stub stub2 = ServiceGrpc.newStub(channel);
   ```

2. **Batching requests**: Gom nhóm các request nhỏ thành một request lớn.
   ```java
   // Thay vì gọi N lần với 1 item
   for (Item item : items) {
       saveItem(item);
   }
   
   // Gọi 1 lần với N items
   saveItems(items);
   ```

3. **Sử dụng streaming thay vì unary** cho dữ liệu lớn.

4. **Compression**: Bật compression để giảm kích thước dữ liệu.
   ```java
   ManagedChannel channel = ManagedChannelBuilder.forAddress(host, port)
           .enableFullStreamDecompression()
           .build();
   ```

### 7.2. Reliability

1. **Timeout**: Luôn đặt timeout cho mọi RPC call.
   ```java
   stub.withDeadlineAfter(5, TimeUnit.SECONDS).myMethod(request);
   ```

2. **Retry**: Cấu hình retry cho các lỗi tạm thời.

3. **Circuit Breaking**: Ngăn chặn gọi đến các service không khả dụng.
   ```java
   // Sử dụng thư viện resilience4j
   CircuitBreaker circuitBreaker = CircuitBreaker.ofDefaults("backendService");
   Supplier<Response> decoratedSupplier = CircuitBreaker
           .decorateSupplier(circuitBreaker, () -> stub.myMethod(request));
   ```

### 7.3. Security

1. **TLS/SSL**: Luôn bật TLS/SSL trong môi trường production.

2. **Authentication**: Sử dụng interceptor để thêm token vào mọi request.

3. **Authorization**: Kiểm tra quyền truy cập ở server.

### 7.4. Monitoring

1. **Logging**: Log tất cả các gRPC calls và errors.

2. **Metrics**: Thu thập metrics như số lượng calls, latency, error rates.

3. **Tracing**: Sử dụng distributed tracing để theo dõi request qua nhiều services.
   ```java
   // Sử dụng OpenTelemetry
   Tracer tracer = openTelemetry.getTracer("my-service");
   Span span = tracer.spanBuilder("grpc-call").startSpan();
   try (Scope scope = span.makeCurrent()) {
       // Gọi gRPC
       stub.myMethod(request);
   } finally {
       span.end();
   }
   ```

### 7.5. Versioning

1. **Package versioning**: Thêm phiên bản vào tên package.
   ```proto
   package com.didan.v1;
   ```

2. **Field evolution**: Thêm trường mới với reserved field numbers.

3. **Backward compatibility**: Luôn bảo đảm backward compatibility khi thay đổi API.

> XdsBootstrapConfig.java
```java
package com.didan.testperformance.first.config.grpc;

import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Configuration;
import org.springframework.core.io.Resource;

import javax.annotation.PostConstruct;
import java.io.IOException;
import java.nio.charset.StandardCharsets;

@Slf4j
@Configuration
public class XdsBootstrapConfig {

    @Value("${grpc.xds.bootstrap-config-path}")
    private Resource bootstrapConfigResource;

    @PostConstruct
    public void initializeXdsBootstrap() {
        try {
            String bootstrapConfig = bootstrapConfigResource.getContentAsString(StandardCharsets.UTF_8);
            log.info("Setting xDS bootstrap configuration");

            // Set the system property that gRPC uses to find the bootstrap config
            System.setProperty("io.grpc.xds.bootstrapConfig", bootstrapConfig);

            log.info("xDS bootstrap configuration set successfully");
        } catch (IOException e) {
            log.error("Failed to load xDS bootstrap configuration", e);
            throw new RuntimeException("Failed to initialize xDS bootstrap configuration", e);
        }
    }
}
```
- Vai trò: Đọc file bootstrap config và thiết lập cấu hình xDS cho gRPC client
- Cách hoạt động: Đọc file từ đường dẫn cấu hình và đặt vào system property

> XdsConfiguration.java
```java
package com.didan.testperformance.first.config.grpc;

import io.grpc.LoadBalancerRegistry;
import io.grpc.NameResolverRegistry;
import io.grpc.xds.WeightedRoundRobinLoadBalancerProvider;
import io.grpc.xds.XdsNameResolverProvider;
import jakarta.annotation.PostConstruct;
import org.springframework.context.annotation.Configuration;

@Configuration
public class XdsConfiguration {

  @PostConstruct
  public void registerXdsResolver() {
    NameResolverRegistry.getDefaultRegistry().register(new XdsNameResolverProvider());
    LoadBalancerRegistry.getDefaultRegistry().register(new WeightedRoundRobinLoadBalancerProvider());
  }
}
```
- Vai trò: Đăng ký xDS name resolver và load balancer vào gRPC client
- Mục đích: Cho phép gRPC client sử dụng xDS để resolve tên service và load balance
- XdsNameResolverProvider: Giúp gRPC client hiểu cách resolve tên service qua xDS
- WeightedRoundRobinLoadBalancerProvider: Cung cấp thuật toán load balancing theo trọng số
- Đăng ký: Được thực hiện trong phương thức annotated với @PostConstruct để đảm bảo nó được gọi sau khi bean được khởi tạo

### 10.2. ProxylessChannelGrpc sẽ sử dụng xDS target để nói cho gRPC biết rằng nó cần tìm service thông qua xDS discovery, không phải kết nối trực tiếp.
> ProxylessChannelGrpc.java
```java
package com.didan.testperformance.first.config.grpc;

import com.didan.testperformance.first.entity.RequestServiceGrpc;
import io.grpc.CallOptions;
import io.grpc.Channel;
import io.grpc.ClientCall;
import io.grpc.ClientInterceptor;
import io.grpc.ManagedChannelBuilder;
import io.grpc.MethodDescriptor;
import java.util.concurrent.Executor;
import java.util.concurrent.TimeUnit;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Qualifier;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Slf4j
@Configuration
@RequiredArgsConstructor
public class ProxylessChannelGrpc {

  @Value("${grpc.xds.service-name}")
  private String xdsServiceName;
  @Value("${grpc.xds.load-balancing-policy}")
  private String loadBalancingPolicy;

  public static final String SECOND_SERVICE = "seconds-service";
  public static final String GZIP_COMPRESSION = "gzip";
  public static final String XDS_SCHEME = "xds:///";
  private final GrpcInterceptor grpcInterceptor;
  @Qualifier("ioExecutor")
  private final Executor executor;

  @Bean
  public RequestServiceGrpc.RequestServiceBlockingStub proxylessSecondServiceBlockingStub() {
    Channel channel = createChannel();
    return RequestServiceGrpc.newBlockingStub(channel);
  }

  private Channel createChannel() {
    String target = buildXdsTarget();
    log.info("Creating xDS proxyless channel to second gRPC server with target: {}", target);
    return ManagedChannelBuilder.forTarget(target)  // Sử dụng forTarget() cho xDS, không phải forAddress()
        .executor(executor)
        .intercept(grpcInterceptor)
        .intercept(gzipInterceptor())
        .defaultLoadBalancingPolicy(loadBalancingPolicy)
        .keepAliveTime(30L, TimeUnit.SECONDS)
        .keepAliveWithoutCalls(true)
        .keepAliveTimeout(10L, TimeUnit.SECONDS)
        .disableRetry()
        .usePlaintext()
        .build();
  }

  private String buildXdsTarget() {
    // Đây là tên service trong Kubernetes, không phải địa chỉ IP/port cụ thể
    // xDS sẽ resolve tên này thành các endpoint thực tế
    return String.format("%s%s", XDS_SCHEME, xdsServiceName);
  }

  private ClientInterceptor gzipInterceptor() {
    return new ClientInterceptor() {
      @Override
      public <Q, P> ClientCall<Q, P> interceptCall(MethodDescriptor<Q, P> methodDescriptor,
          CallOptions callOptions, Channel channel) {
        return channel.newCall(methodDescriptor, callOptions.withCompression(GZIP_COMPRESSION));
      }
    };
  }
}
```
- Vai trò: Định nghĩa target service mà client muốn kết nối đến
- Không phải địa chỉ IP/port: Đây là tên logic của service
- xDS sẽ resolve: Tên này thành các endpoint thực tế

> application.yml
```yaml
grpc:
  xds:
    service-name: localhost # Tên service trong Kubernetes mà gRPC client muốn kết nối đến
    load-balancing-policy: round_robin # Chính sách load balancing
    bootstrap-config-path: classpath:grpc-bootstrap.json # Đường dẫn đến file bootstrap config
```

## 11. Kết luận

gRPC là một công nghệ hiện đại và mạnh mẽ cho phép triển khai các API hiệu suất cao trong môi trường phân tán. Với sự hỗ trợ mạnh mẽ từ Spring Boot, việc tích hợp gRPC vào các ứng dụng Java trở nên dễ dàng và hiệu quả.

Ưu điểm của việc sử dụng gRPC trong Spring Boot:
- Hiệu suất cao với HTTP/2 và Protocol Buffers
- Định nghĩa API rõ ràng với contract-first approach
- Hỗ trợ streaming hai chiều
- Tích hợp dễ dàng với Spring Boot ecosystem

Một số thách thức:
- Đường cong học tập dốc hơn so với REST
- Khả năng interoperability với web browsers hạn chế
- Tooling chưa phổ biến như REST

Tuy nhiên, với những ưu điểm vượt trội, gRPC là một lựa chọn tuyệt vời cho giao tiếp giữa các services trong các hệ thống microservices hiện đại.
